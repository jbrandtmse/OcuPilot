## 2. What the classic System Management Portal looks and behaves like today

**Shell (D3c, shell digest "Portal shell inventory")**
- Home page is "one 2,823-line Zen home page". "Three regions: left **selector** (product categories), centre **finder** (`hs:SMPFinderPane`, columns or list view) or **search results** or **splash**, right **message panel**." Title "Welcome, <user>".
- Category selector order: Home; HealthShare/Health (if installed); Analytics; Interoperability; System Operation; System Explorer; System Administration. Disabled items are "greyed, tooltip 'You do not have privilege to view this page.'" Analytics/Interop "switch to a namespace picker when the current namespace does not support them".
- Finder: "Columns view: item name, description, **Go** button (`navigate(link)`), **Add to favorites**." "List view: **Go** link on selected row. Double-click navigates." An "Assign" resource mode for `%Admin_Secure` holders opens a "700×600 popup".
- Menu is "built from server-side nested arrays (name, title, link, disabled flag, icon, description, resource, custom resource, tags)"; `%CheckResources` gates every item by URL prefix or class RESOURCE, "disables any node whose children are all disabled". Custom resources "keyed by normalized page URL, so a portal with different routes must map its routes back to those keys or lose existing assignments."
- **Header strip**: "server, namespace with switch link, user with change-password link, escalation role with escalate and remove links, licensed-to, instance, and a Live, Test, Failover or Development badge; small menu Home, About, Help, Contact, Logout; a fixed 16-link 'Menu' drop-down filtered by access; breadcrumb locator with an optional namespace select; per-page ribbon commands."
- **Breadcrumbs**: "Each page contributes `$LB(caption, link)`; parent chain is declared statically via `PARENTPAGE`. When `SHOWNAMESPACE=1` the locator also renders a **namespace `<select>`**."
- **Ribbon**: "Commands are `$LB(id, caption, help, onclick)`; view icons (`View:` label) switch finder/list modes; optional sort options and search box." Digest note: "The Angular shell needs a per-page command bar equivalent."
- **Form template**: "Default ribbon **Save** / **Cancel**; `validateRequired`, `showMsg/resetMsg`, `IsEditForm` (title 'Edit: <PID>')".
- **Auto-refresh list template**: "Refresh on/off, refresh rate, 'Last update:' stamp, column sort persisted server-side; nav bar with **Filter**, **Page size**, **Max rows**." "Used by most list pages." Home panel "refreshing every 10 seconds only when auto-refresh is enabled".
- **Namespace switching**: "opens a dialog, then rewrites the target URL into the namespace's own CSP application"; popup `%ZEN.Dialog.namespaceSelect` "(500×500)"; "If no web app exists an alert says the namespace cannot be used in this context."
- **Search**: "covers menu metadata only (name, title, tags), never classes, globals, users or data, with a 220-millisecond typeahead"; ≥3 chars; "disabled rows are unlinked with a no-privilege tooltip".
- **Home content**: favorites and recent (per-user server-side), "a 'Did you know' tip", documentation/support links, right-hand **System Information** panel (uptime, mirror status, four alerts: database space, journal space, lock table, write daemon; System Monitor liveness; per-namespace production status) — "hidden at widths below 1,100 pixels". "No license, ECP or application-error widgets live on Home; they are on the System Dashboard."
- **About**: 14 fields + "17-language session-language selector". **Help**: "opens DocBook by a per-page help address" in a new window. **Contact**: WRC form. **Logout**: "Confirms if `pageModified`"; a Zen auto-logout timer exists ("client-side auto-logout timer" not read — Open questions).
- State persistence is cookie-only ("Per-browser only; nothing server-side") for selector/view mode.
- Server-method errors "trigger a connectivity probe and a status message unless popups are limited."

**Zen vs legacy CSP vs Angular (D3a, D3b, D3d)**
- "Zen is deprecated" (D2). System Operation: "Nearly half the section is still pre-Zen `%CSP.Util.AutoPage` CSP: all Backup pages, all Journal pages, the System Dashboard, Shadow Servers, the New Task wizard, the Application Error Log, Messages Log, System Usage and Diagnostic Reports".
- "Detail pages are hybrids: Database, Process and Task details host a legacy HTML dashboard pane of value meters built in code, so a rewrite reproduces meter semantics rather than a Zen model."
- "several legacy pages render empty on GET and are probably POST-driven"; Task Details "Edit" "rendered empty for every `$ID1` tried" (sysop digest).
- New Task is a "legacy frameset" ("uses HTML frames") with "about 60 fields"; footer "`< Back`, `Finish`, `Cancel`, help".
- System Dashboard: "Real-time meters in 7 groups ... 'Details for selected item' panel"; "click a meter for details".
- Application Error Log: "3-level drill-down" (namespaces → dates → errors). Messages Log: "Full `messages.log` text with search-and-highlight", "**Search**, **Clear Highlight**, Goto Top/Bottom", "90 KB render". System Monitor Log: file view "with search/highlight and show-all".
- Edition/feature gating "is runtime, not compile-time" (mirror, sharding, Windows-only, VMS).
- Long-running work: "JOBs a worker, and reports progress in `^IRIS.Temp.MgtPortalTask` read by the Background Tasks page" (Compact, Defragment, Integrity Check, mirror actions); everything else synchronous. Audit copy/export/purge "run as background task".
- Editors are large multi-tab Zen pages: web-application editor "1423" lines, "largest page in section"; user editor with "roles/SQL tabs"; SSL editor with **Test**; LDAP with a test page; OAuth editors with **Rotate Keys**, **Discover and Save**, **Update JWKS**. Audit viewer is a multi-field search form (time range, source/type/name, users, PIDs, namespaces, JSON search, max rows) with a detail dialog.
- Interoperability: "Eleven Zen pages embed iframes, none of them Angular"; "View > Messages is hard-coded to the Zen viewer, and the Angular message viewer is reachable only from that page's 'Open in the new UI' button".
- Directory allow-list restricts server file paths in browse dialogs (export/import).

**Pain points and complaints the research cites (verbatim where available)**
- "Community demand for cosmetic/accessibility portal improvements exists (dark mode requests and workarounds, banner colour changer) between Aug 2025 and Aug 2026." (contest-field digest; workarounds: "Dark Reader; banner colour changer").
- "Zen, the framework under the classic portal, is deprecated"; community question: "With Intersystems indicating ZEN pages are being deprecated, I'm looking to find out how to add custom configuration pages for the management portal using the new method similar to the new Rules editor."
- "InterSystems' own Angular-era interface has modernized interoperability surfaces only, none of the administration areas the contest names" (D2).
- Vendor's own new UI notes "Improved UI performance for larger productions, such as those with more than 2,000 hosts" and "collapsible production items" (contest-field digest), implying scale pain in the classic UI.
- Search "Searches menu metadata only — not classes, globals, users or data."
- Message panel "Shown only when window width > 1100 px."
- Angular editors reached "only by full-page navigation"; "cross-app links open sibling editors in new tabs"; "the logo link navigates the frame to the classic portal home" (D5).
- Console-assistant complaint the research treats as the design driver (D8, [43]): "unreliable and irrelevant information that required too many steps to access"; "many hallucinations, it often ignores instructions"; praise for "page context, follow-up memory and precise investigations".

## 5. Authentication UX

**Mechanism as established** (spike §6; research D4, insight 1): a browser-level cookie `CSPBrowserId` ("`path=/`, `httpOnly`, `SameSite=Strict`, no `Expires`") is set by a classic portal login or any JWT login. An empty-body `POST <jwt-app>/login` with that cookie mints an access/refresh pair "only if the JWT application carries the same `GroupById`". "only `Authorization: Bearer <access>` authorizes a data call ... cookies alone never do". Access token **60 s**, refresh **900 s** (`exp − iat`). "Any JWT-enabled application accepts any valid, unrevoked token from this instance regardless of group or `app` claim." `/api/atelier` and `/api/mgmnt` "accept only Basic or their own CSP session".

**What the shell does** (spike §7, Rec 3): "**Startup:** `POST /api/admin/login` with an empty body and `credentials: "include"`. 200 → the user is logged in (portal-first case, or a returning tab); store the pair. 401 → show OcuPilot's login form and `POST /api/admin/login` with `{"user","password"}` (OcuPilot-first case)." Token in "`sessionStorage` (per tab, as the vendor does), never `localStorage`". "**Refresh:** schedule `POST /api/admin/refresh` at `exp − iat − 10 s`; on any 401, refresh once and retry; if the refresh fails, return to the login form." "**Logout:** `POST /api/admin/logout` with the Bearer **and** `credentials: "include"`, then clear `sessionStorage`. This ends the browser-level login too, so the classic portal and the embedded editors are logged out as well." Vendor bundles "refresh and retry once" on 401 and use `revoke` on their `timeout()` path.

**Visible states and transitions a sign-in screen and session handling must cover** (enumerated from the spike observations; 14):
1. **Cold start / silent probe in flight** — the empty-body login is pending; nothing rendered yet is authoritative.
2. **Silently signed in** (portal-first user, or a returning/new tab in the same browser) — 200, no prompt ("users arriving from the classic portal are never prompted", SH-01).
3. **Sign-in form shown** (OcuPilot-first, 401 on the silent probe; also "Empty-body login with no cookies → 401").
4. **Form rejected** — "Wrong password → 401" (spike row 11).
5. **Signed in, token fresh** — Bearer on every JWT-enabled API; one token serves `/api/admin`, `/api/interop-editors`, `/api/security-config`, `/api/ocupilot`.
6. **Access token expired (60 s)** — "the 60-second Bearer, expired → 401 / 401" (row 36); scheduled refresh at `exp − iat − 10 s`, or refresh-once-and-retry on 401 (row 37: refreshed Bearer → 200).
7. **Refresh token expired/revoked (900 s idle or `revoke`)** — refresh 401 → "return to the login form" (spike §7). Whether to retry the silent cookie login before showing the form is not stated (§9 gap).
8. **Signed out by OcuPilot** — logout with Bearer + cookie; sessionStorage cleared; classic portal and embedded editors also signed out (row 23).
9. **Signed out elsewhere** — classic `?IRISLogout=end` in a sibling tab: silent re-login 401 and the frame's stored Bearer 401 (row 42); the shell learns this only on its next call/refresh.
10. **Bearer-only logout elsewhere** — "that app's `sid` is revoked but the cookie still mints (200)" (row 22): OcuPilot's session may die while the browser-level login survives.
11. **Embedded editor iframe** — loads at `/ui/interop/<editor>/index.html?...`, mints its own pair silently "with no user interaction", renders toolbar; in normal mode shows its own banner ("RULE EDITOR account_circle _SYSTEM"), logo link to classic portal, About/Logout menu; `VSCODE=1` hides the banner but "The password crosses into the frame and onto the wire" if the `auth` message is used (optional). Untested alternative: host seeds the frame's sessionStorage token keys.
12. **Atelier-backed feature** — "the token is not accepted, and a cookie-only call from the page triggers the browser's native Basic-auth prompt" and the fetch is "**pending forever**" (row 35). "Never call it without an explicit `Authorization: Basic` header, or route Atelier-backed features through `/api/ocupilot`." Consequence: any SQL/class/routine screen needs credentials the JWT does not supply (D6c: "the harvested services must send an explicit Basic header or go through OcuPilot's own REST").
13. **Privilege-denied** — `/api/admin/info` returns a `privileges` map and "403s if non[e]" (api-coverage digest, truncated); menu/route gating "from the caller's %Admin_* privilege map" (SH-02); classic no-privilege tooltips (SH-06).
14. **Local development** — "`CSPBrowserId` is `SameSite=Strict`; an `ng serve` on another port will not carry it. Local development must proxy through the IRIS origin."

**Two designs** (spike §8): Design A silent-first with Group by ID ("recommended for the contest"; "a user arriving from the classic portal is never asked to log in"); Design B JWT-only ("The shell always shows its own login"; "one extra login when the user comes from the classic portal"). Both: "one login, one token for every API the contest needs, embedded editors with no password hand-off, and a logout that ends everything." Residual risk: docs say of Group by ID "Do not use. This field is for migrated legacy applications only" while the vendor's portal, editors and admin API rely on it.

**Handoff vs digest**: the handoff's H1(a) premise (cookies alone authorize a data call) **failed** (401); its assumption that the *serving page's* Group by ID matters was **overturned** (H1-control identical); research.md carries the corrected model ([22] "CORRECTED").

## 6. Hidden `/api/admin` surface

- `%Api.Admin` with dispatch v1 and v2, "84 Hidden classes"; "hidden, undocumented", "unsupported and unversioned in the documentation, so it is a dependency risk". `AccessCheck` performs no check; per-endpoint `%Admin_*` resources; `GET /api/admin/info` returns `apiVersion 2`, username, `serverVersion`, product, namespace list and a `privileges` map. Location headers rewritten to `/iris/api/admin/` ("suggests InterSystems is building its own new portal front end on this API").
- **Backs five of six areas** (D4 table): web apps + web sessions (plus `/api/mgmnt` discovery/OpenAPI; gap: "`/api/mgmnt/v2` refuses to return the spec for InteropEditors and lists only spec-based services"); users/roles/resources/services/SQL privileges ("none found" gap); SSL/X.509/OAuth/wallet/encryption/LDAP ("no wallet page exists" in the classic portal; "X.509 backing class not identified"); tasks incl. run/suspend/resume/history/upcoming/task manager ("none found"); processes (terminate/suspend/resume/broadcast), system usage, shared memory, dashboards, database dirs/volumes, devices + `/api/monitor/metrics` ("freeze and thaw absent").
- **Does not back**: messages.log and application error log ("no backing class found; a file-reading endpoint is needed"), production-wide event log, memory/startup/SQL/NLS settings, backup/restore, mirror config/status, globals, journal purge, freeze/thaw, interop credentials/default settings/managed alerts/purge, SQL plans/stats. Five sub-areas "UrlMap-only until exercised" (web applications, external language servers, DocDB, SQL privileges, web-authentication settings).
- **UI consequences**: Area 6 needs "the two custom-endpoint viewers for messages.log and the application error log" (LG-03/04); alerts log "since last scrape only" (`/api/monitor/alerts`); Atelier jobs endpoint "returned an empty list, whereas `/api/admin/v2/processes` returned the full table". Unfinished large editors "link ... to the classic portal page"; P4 "Analytics full applications as rebuilds (link instead)". Startup guard: "pin to `/v2`, check `apiVersion` from `GET /api/admin/info` at startup" (SH-11).
