# Reconcile: VS Code shell reference → EXPERIENCE.md

**Input.** A VS Code screenshot the owner shared mid-session as "the VS Code example" for the shell. Not a file; the facilitator's record is the memlog event beginning "user shared a VS Code screenshot". What it showed: activity bar left (icon stack, account + gear pinned bottom, badge counts on icons); command center top-center with back/forward arrows; editor area with keyboard-shortcut hints when empty ("Open Chat ⌃⌘I", "Show All Commands ⇧⌘P", "Go to File ⌘P"); right-docked panel with a tabbed header row ("Claude Code", "Antigravity"), a history/clock icon, an add icon, full-screen and close controls; a usage banner above the input; input footer with mode chips and a stop button; status bar bottom (branch, errors/warnings, language mode, notifications bell).

**Compared against.** `EXPERIENCE.md` (Foundation shell table, Information Architecture, Component Patterns, Interaction Primitives, State Patterns › Panel, Inspiration & Anti-patterns) and the memlog decisions on the navigation model, slide-out, command box, panel width, narrow viewport, header/status split, rail badges, keyboard model and Home. PRD FR-10, FR-12, FR-19, FR-72, FR-73 and §12 were read where the spine defers to them.

**Verdict in one line.** The spine adopts the reference's *geometry* completely and its *chrome contents* selectively; the panel header and input footer are where the most VS Code affordances were left on the floor without a recorded decision.

## Recommendations for the facilitator

Five "not discussed" items worth one question each. Defaults are suggestions for the user to accept or replace, not decisions.

- **Stop a running turn.** *Ask:* should Send become Stop while a turn is Busy? *Default:* yes — Send turns into Stop during Busy; Stop cancels at the next tool boundary, the transcript gets a card "Stopped by you at <step>" (same shape as the error card), that turn's live proposals are canceled, and the lock banner still answers a second Enter. Additive to FR-12; no PRD change needed.
- **New conversation from the panel.** *Ask:* is "new tab = new conversation" enough for the demo, or does the panel header get a New conversation action? *Default:* add a "New conversation" button-text to the panel header; it starts a fresh conversation in the same tab, the previous one stays stored per user (FR-72), and FR-12's new-tab rule still holds.
- **Chord discoverability.** *Ask:* where do Ctrl/Cmd+K, +I and +B appear in the product? *Default:* append the chord to the command-box placeholder ("Search screens and commands · Ctrl+K"), extend the panel caption to "Enter to send · Ctrl+I to focus", and put "Ctrl+B" in the rail-items' tooltips; no separate shortcut hints screen.
- **Account and settings home.** *Ask:* confirm the status-bar user segment as the account menu (the spine's `[ASSUMPTION]` for Sign-out), and name it as the polish-week home for the theme toggle and Change password. *Default:* confirm; the menu reads Sign out now and grows to Sign out · Change password · Theme in polish week, keeping the header at logo · command-box · namespace switch.
- **Earlier conversations from the panel.** *Ask:* does a user need to reopen a previous conversation from the panel in Release 1? *Default:* no — Release 1 keeps the per-tab transcript with reload; the P1 Transcripts screen (own transcripts only) is the history view; revisit only if the demo needs it.

Not worth a question now: the **notifications bell** (toasts plus the persistent row highlight and the audit ledger cover it; revisit only if the accessibility lens challenges the 10 s auto-dismiss) and a **definition picker / panel tabs** (matters only once step 7 ships a second enabled provider). Both are recorded in the Dropped table so the gap is visible if scope moves.
