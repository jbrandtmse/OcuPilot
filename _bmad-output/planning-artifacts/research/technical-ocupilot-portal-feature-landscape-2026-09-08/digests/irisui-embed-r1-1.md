## Embedding mechanics

### 1. The Zen portal does not iframe the Angular apps — it navigates to them

Every launch site in `irislib/EnsPortal` replaces the top-level document: `zenPage.gotoPage(zenLink(zenPage.interopBaseURL + '&' + ...))` (`Productions.cls:93`, `226`), `window.location.href = href` (`DTLEditor.cls:3918`, `BPLEditor.cls:1348`, `HL7/SchemaMain.cls:1467`), `zenPage.gotoPage(zenLink(zenPage.ruleEditorBaseURL + '&rule=' + …))` (`Rules.cls:153`), `zenPage.gotoPage(zenLink(messageLink))` (`MessageViewer.cls:194`). The 30 `iframe` hits in EnsPortal are Zen's own content panes (`contentFrame`, `chartFrame`, `svgFrameMask`, `dummyFrame`), none of them points at `/ui/interop`. So there is no "iframe URL pattern" to copy from InterSystems' own portal; what exists is a **URL contract** for top-level navigation.

URL construction: `EnsPortal.Util.PageLinks.GetURL` (`irisui/_analysis/EnsPortal.Util.PageLinks.cls`) returns `<page>?$NAMESPACE=<url-encoded $NAMESPACE>`; the new-UI pages are `$$$InteropWebAppRoot_"<app>/index.html"`. The Zen pages then append the document parameter. Origin prefix is taken from the current page: `window.location.href.split('/csp/')[0]` (`DTLEditor.cls:3909`, `BPLEditor.cls:1339`, `HL7/SchemaMain.cls:1462`). `EnsPortal.Application.Link()` (`Application.cls:258–270`) short-circuits any link containing `/ui/interop/` to `%CSP.Portal.Application.Link` so it is never rewritten to a custom management URL.

### 2. Serving constraints that pin the URL

- Interop apps: `<base href="index.html">` (`ui/interop/rule-editor/index.html`), hash routes (`#/smp` seen live in the snapshot). Live: `/ui/interop/rule-editor/` → 404, `/ui/interop/rule-editor/smp` → 404, `/ui/interop/rule-editor/index.html?$NAMESPACE=HSCUSTOM&rule=Demo.Rule` → 200. Static files are served **without authentication** (200 with no credentials) and with no `Set-Cookie`, no `X-Frame-Options`, no `Content-Security-Policy` (`curl -I http://localhost:52774/ui/interop/rule-editor/index.html`, headers: `Date, Server: Apache, CONTENT-LENGTH, CONTENT-DISPOSITION: inline; filename=index.html, EXPIRES (+1h), LAST-MODIFIED: Fri, 26 Jun 2026 15:40:51 UTC, Content-Type`).
- **The bundle derives its API root from its own URL and requires `/ui/interop` in it**: `const c=new RegExp(/(.*?)(?=\/ui\/interop)/);this.server=window.location.href.match(c)[st_ZERO],this.baseAPIPath=\`${this.server}/api/interop-editors/v7/\`` (production branch, `rule-editor/main-*.js`). Re-hosting the bundle under another path would make `match()` return null and throw. Same expression appears for the JWT `apiUrl`. Consequence: embed by URL in place; do not copy.
- HealthShare apps: `<base href="{$webAppPath}">` rewritten live to `<base href="/ui/security-config/">` (`curl http://localhost:52774/ui/security-config/`); GET `/ui/security-config/` and `/csp/fhir-management/` return 200 with no auth and no framing/cookie headers; HEAD returns 405 (`ALLOW: GET,OPTIONS,POST`). Path-location routing per README lines 141–149.

### 3. Session / auth hand-off

- `%Api.InteropEditors`: `Parameter HandleCorsRequest = 1; Parameter UseSession As Integer = 0;` and all routes forward to `v1…v7.disp` (`/api/atelier/v1/%25SYS/doc/%25Api.InteropEditors.cls` lines 20–35). `dispParent.AccessCheck` authorises if the caller has any of rule read/write, dtl read, production read, bpl read, lookupTable read (`%Api.InteropEditors.Utils.GetPrivileges()`), and `OnPreDispatch`/`%AdjustNamespace` switches `$namespace` to the 2nd URL segment (never into `%SYS`) — live `dispParent` lines 13–47, 51–63, 66–94.
- Unauthenticated REST → `401` + `WWW-AUTHENTICATE: Bearer` (`GET /api/interop-editors/v7/HSCUSTOM/mgmt-url` without credentials). HTTP Basic also works (`-u _SYSTEM:SYS` → 200, body `{"url":"/csp/hscustom/"}`).
- **JWT login is the app's mechanism.** `POST /api/interop-editors/login` with `{"user":"_SYSTEM","password":"SYS"}` → 200 `{access_token (ES256, exp = iat+60 s, claims iss/sub/sid/app="/api/interop-editors/"), refresh_token (exp = iat+900 s), sub, iat, exp}` plus `Set-Cookie: CSPBrowserId=…; path=/; httpOnly; sameSite=strict`. `POST /api/interop-editors/v7/login` → 401 (the endpoint is on the web-app root, not the versioned API). The bundle's `@intersystems/auth` config: `{apiUrl:u,endpoints:{login:"login",logout:"logout",refresh:"refresh",revoke:"revoke"},…}`; tokens are kept in **`sessionStorage`** under keys `${appId}-user`, `${appId}-accessToken`, `${appId}-refreshToken`; every request gets `Authorization: Bearer ${accessToken}` (`addAuthHeader`), a 401 triggers `refreshTokens()` and a retry, and refresh is scheduled at `exp-iat` minus a cushion.
- **Silent login with an existing SMP session works in the browser (live).** With tab 1 logged into `/csp/sys/%25CSP.Portal.Home.zen?$NAMESPACE=HSCUSTOM`, opening `http://localhost:52774/ui/interop/rule-editor/index.html?$NAMESPACE=HSCUSTOM` in tab 2 produced, with no user interaction: `POST /api/interop-editors/login [200]`, `GET /api/interop-editors/info [200]`, `GET …/v7/HSCUSTOM/mgmt-url [200]`, `GET …/v7/%25SYS/system-mode [200]`, `GET …/v7/HSCUSTOM/sourcecontrol/enabled [200]`; the snapshot shows the editor (banner "RULE EDITOR", New/Open/Save/Save As/Compile/Test toolbar), not the login form. The bundle explains the call: `login(e,t){let n=null;e&&t&&(n={user:e,password:t});…this.http.post(this.getLoginEndpoint(),n,a)` — `doLogin()` is invoked with no arguments at init (`!e.isAuthenticated&&!e.vscodeMode&&(…e.doLogin(),e.loginForm=…)`), i.e. a null-body POST that the server accepted because the browser already carried an SMP session. Which cookie carried it was **not isolated**: curl with `Cookie: IRISSessionToken=<value from a form login to /csp/sys>` against `GET …/mgmt-url` → 401, the `/csp/sys/`-scoped `CSPSESSIONID-SP-52774-UP-csp-sys-` is path-restricted and also → 401 when forced, and `?CSPCHD=<sid>` → 401. The null-body `POST /login` + browser cookies combination was only exercised in Chrome. See Leads.
- Web-app grouping: `/csp/sys`, `/csp/hscustom`, `/csp/user`, `/ui/interop`, `/api/interop-editors`, `/api/security-config`, `/api/fhir-explorer`, `/csp/fhir-management(+/api)`, `/csp/fhirsql`, `/csp/oauth2-*/api`, `/csp/healthshare/hssys/app/api` all share `GroupById=%ISCMgtPortal`; `/ui/security-config`, `/ui/fhir-explorer`, `/csp/healthshare/hssys/app`, `/csp/fhirsql/api/*`, `/api/atelier` do not. Observed: the Bearer token minted by `/api/interop-editors/login` was accepted by `/api/security-config/credential/v1/credentials` (200) and rejected by `/api/atelier/` (401, `JWTAuthEnabled=false`).
- Cookies seen live: `/csp/sys` → `CSPSESSIONID-SP-52774-UP-csp-sys-` (`path=/csp/sys/; httpOnly; sameSite=strict`) and `CSPWSERVERID` (`path=/`); `/csp/hscustom` Zen page → `CSPSESSIONID-SP-52774-UP-csp-hscustom-` (`path=/csp/hscustom/`), `IRISSessionToken` (`path=/; httpOnly; sameSite=strict`), `CSPWSERVERID`. All `sameSite=strict`, all first-party for a same-origin iframe.

### 4. Embedded ("VSCODE") mode — the only host↔app message contract found

Present in rule-, DTL- and BPL-editor bundles (and the shared modules inside interop-editor); absent from the six HealthShare bundles (`isc-security/main-*.js`: zero hits for `postMessage`, `window.parent`, `iframe`, `csp/sys`; `hs-app-instance`'s single `postMessage` is an OIDC `checkSession` iframe ping to the issuer). No `BroadcastChannel`, `window.top`, `isEmbedded`, `inIframe` anywhere.

- Activation: query parameter `VSCODE=<any>` at init → `localStorage.setItem("vscodeMode","true")`, then `window.parent.postMessage({direction:"vscode",type:"compatible"},"*")`, then `window.onmessage=u=>{if("auth"==u.data.type){…e.doLogin(u.data.username,u.data.password)}}`. `localStorage.removeItem("vscodeMode")` runs on every load, so the flag does not leak between visits. In this mode the automatic null-body `doLogin()` and the login form are skipped (`!e.isAuthenticated&&!e.vscodeMode&&…`), snackbars on namespace switch are suppressed, and `READONLY=1` is honoured.
- App → parent (`window.parent.postMessage(msg,"*")`, target origin `*`): `{direction:"vscode",type:"compatible"}`, `{type:"saved"}`, `{type:"compiled"}`, `{type:"badrule"|"baddtl"|"badbpl",reason}`, `{type:"userAction",id,label,action}` (source-control user action). No "dirty"/"navigate" event exists — `beforeunload` is handled internally by `showUnsavedChangesAlert`.
- Parent → app (`window.addEventListener("message",this.receiveMessage…)`, no origin check): `{type:"auth",username,password}`, `{type:"compile"}`, `{type:"revert"}`, `{type:"undo"}`, `{type:"redo"}`.

### 5. Chrome the app renders

`fr-topbar` (InterSystems logo `assets/images/isc-logo-cmyk.svg` / `InterSystemsIcon.svg` linking to route `smp`, app name "RULE EDITOR", utility menu About/Logout) is rendered by `*ngIf="!t.sso&&!t.vscodeMode"`; a separate `menusDataSso` variant exists (what sets `sso` was not found). The editor's own toolbar (`app-toolbar`: New/Open/Save/Save As/Compile/Test, filter combobox) and `interop-top-banner` (class-name segment) are always present. Live snapshot confirms the banner + toolbar in normal mode. HealthShare apps ship `fr-topbar`, `fr-left-menu`, `fr-username`, `fr-language`, `app-login` (inventory selectors) — full application frames.

### 6. Headers that affect framing (live)

- `/csp/sys/UtilHome.csp` → `X-FRAME-OPTIONS: SAMEORIGIN`, `CACHE-CONTROL: no-cache,no-store`.
- `/ui/interop/**` static, `/api/interop-editors/**`, `/ui/security-config/`, `/csp/fhir-management/`, `/api/security-config/**`: **no** `X-Frame-Options`, **no** `Content-Security-Policy`, no `Access-Control-*` observed (same-origin requests).
- `/csp/hscustom/EnsPortal.ProductionConfig.zen` (with session) → no framing header in the captured set (only Set-Cookie lines were printed by the filter).

### 7. Theming / branding

`index.html` inlines Tailwind CSS custom properties and Material tokens (`ui/interop/rule-editor/index.html` `<style>*,:before,:after{--tw-…}`); component CSS uses `--fr-styles-color-*` custom properties (`--fr-styles-color-middle-dark-grey`, `--fr-styles-color-very-dark-grey`); font stack "Noto Sans" (README line 188; snapshot shows a "Noto Sans" preload node). No theme switch, dark mode, or `setTheme` API found (only Material backdrop classes and Quill's `theme:"snow"`). Branding = InterSystems logo in the topbar unless the topbar is hidden (VSCODE/sso).

## Leads

1. **Which credential carried the silent `POST /login`?** In Chrome it succeeded with only cookies available (`IRISSessionToken`, `CSPWSERVERID`, possibly `CSPBrowserId`, all `path=/`); in curl, `IRISSessionToken` alone against a GET returned 401 and the POST-with-cookie combination was not tested. Test: form-login to `/csp/sys`, then `curl -b jar -X POST http://localhost:52774/api/interop-editors/login -H 'Content-Type: application/json'` and vary the cookies. If it is `IRISSessionToken`, OcuPilot only needs its own web app in `GroupById=%ISCMgtPortal` and a normal CSP login to get free SSO into every editor.
2. **`sso` flag on the topbar** (`!t.sso&&!t.vscodeMode`): something other than VSCODE mode hides the chrome; `menusDataSso` (About/Logout only) suggests an SSO deployment switch. Locate what sets `sso` (grep `this.sso=` / `sso:` in the bundles).
3. **Seeding tokens instead of posting passwords.** Same-origin iframes share the tab's `sessionStorage`; if OcuPilot minted a JWT through `/api/interop-editors/login` and wrote `${appId}-user/-accessToken/-refreshToken`, the app's `configure()` (`getTokenInfo()?.refreshToken && refreshTokens()`) would resume without the `auth` message. `appId` derivation (`${h}-${f}` with `h = […].join("_")`) must be read from the bundle first.
4. **Schema-viewer parameter contract**: Zen sets the literal key `'&ST'` via `URLSearchParams.set` (becomes `%26ST`), and no `get("ST")` exists in the bundle; check whether the app reads `location.hash` or a different key.
5. **`HOST=` / `NEW=1` / `RULESET` / `action`**: sent by Zen or parsed by the app but not cross-verified end-to-end.
6. **Token scope across web apps**: a `/api/interop-editors` token was honoured by `/api/security-config` (both `%ISCMgtPortal`, JWT on). If JWTs are group-scoped, one login could cover the HealthShare REST backends too — test against `/csp/fhir-management/api` and `/api/fhir-explorer`.
7. **isc-fhir `window.parent` (4 hits in non-main chunks)** and any `iframe` usage in the HealthShare vendor chunks were not examined.
8. Contradiction: README line 133 vs live `UseCookies` values for `/csp/fhir-management` and `/csp/fhirsql` (resolved in favour of live above).
