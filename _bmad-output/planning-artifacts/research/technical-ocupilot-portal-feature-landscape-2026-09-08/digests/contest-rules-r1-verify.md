## Discrepancies

1. **Timezone string.** A and B's rendered UI say `EST` (`23:59 EST`, `12:00:00 AM EST`); B's JSON stores zone-less datetimes (`2026-09-27 23:59:59`); C says `12:00 pm EDT | 6:00 pm CEST` for the 14 Sep webinar. September is EDT in the US, so "EST" on A/B is loose usage. Practical reading: US Eastern wall-clock time.
2. **Originality rule wording.** A: "It should not be an import or a direct interface for an already existing library in another language (except for C++ ...). It should not be a copy-paste of an existing application or library." B: "Must be original – no copy-pasting or simple imports (except for C++ integrations)." Same intent, different text.
3. **README requirement.** B adds "a link to the idea" (`Include an English README with installation steps, a link to the idea, and either a video demo or a detailed app description.`); A has no "link to the idea" clause (`... include the installation steps, and include either a video demo or a description of how the application works.`). Likely a template carry-over on B from idea-driven contests; harmless to satisfy.
4. **Submission cap phrasing.** A: "Only 3 submissions by a single developer/team are allowed." B: "Limit of 3 submissions per developer."
5. **Stale cross-link on B.** B's text "For more details on the rules, nominations, and judging criteria, visit the official contest page" links to `https://community.intersystems.com/post/intersystems-contest-ai-agents-fhir` — the previous contest's announcement, not A. Do not rely on that link for rules.
