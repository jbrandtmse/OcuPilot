## Leads

- **"Health" top-level menu is not built by the exported `Application.cls`** (its `GetSystemConfigArray` has no such entry; the live link goes to `/csp/healthshare/HS.HC.UI.Home.cls`). A HealthShare subclass of the application/home page must inject it — it lives in `HS.*` (irislib), outside this brief's grant. Whether HealthShare also injects extra System Administration leaves is unverified; the third menu level was not confirmed live (uid went stale before the click; budget exhausted).
- **Configure User Events menu text promises "Create, edit, export, import, reset, or delete"**, but `Audit/UserEvents.cls`, `UserEvent.cls` and `EventsTemplate.cls` expose only Create New Event, Change Status, Reset, Delete in the extraction. Export/Import may be missing or implemented via a pattern the regex did not catch — verify live before scoping.
- **`ObjectSettings.cls` (Objects page)**: no `Config.*`/`Security.*` reference matched; the backing class is probably resolved dynamically (as `Config.Advanced` does with `$classmethod("Config."_Subject,…)`). Read the file directly when scoping that page.
- **SQL-privilege dialogs** (`Dialog.SchemaPriv`, `Dialog.ColumnPriv`, `Dialog.MLConfigurationPriv`) are certainly Security-section UI (`/csp/sys/sec`, `%Admin_Secure:USE`) but the extraction did not capture which page launches them; `User.cls`/`Role.cls` SQL tabs are the likely sites (they use `%SQL.Manager.API`/`CatalogPriv`). Unverified.
- **Dead references** (`MoveGlobalsCreate`, `Sharding.Dialog.Activate/Initialize/Verify`, `Dialog.MirrorAuthorizedAsync`, `InstallInfo`, `%CSP.UI.Portal.Home`): either removed features whose JS still mentions them, or features only present in other editions. Do not plan parity for them without a live check.
- **Shadow Server Settings** links to a Hidden class; the "Legacy Settings" grouping and the "deprecated on IRIS" text argue for excluding shadowing from parity scope.
- **Provider pages** (`Kits`, `Installs`, `Instances`, `Machines`, `Manifests`, `Default`) are complete `mgr/` pages absent from the menu; whether any web app or HealthShare menu exposes them is unknown.
- **Enterprise Manager (EMS)** hooks are inert (hard-coded 0) — no need to replicate EMS read-only behaviour.
- **Sharding license = 0** on this Community instance, so Sharding pages cannot be exercised live here.

## Gaps

- The 7 legacy `.csp` pages (SQL Gateway Connections, Database Backup ×5, Web Gateway Management, Task Manager Email, Enable/Disable Auditing, Security Advisor) are not in `irissys/`; only `%CSP.UI.System.SecurityAdvisorPane` was found in a granted folder. Their actions and backing classes (e.g. `Backup.General`, `%Net.Remote.*`, `%SYS.Task.*`) are not inventoried here. A follow-up should pull them from the container's `csp/sys/mgr` and `csp/sys/sec` directories.
- Per-page field lists were sampled (labels captured for MemoryStartup, Journal, SQL, Parameters, Authentication, User, Role, Web, SSL, Audit.View); the other ~100 forms were classified from ribbon/row actions and class references only.
- The third and fourth menu levels were confirmed only from source, not live.
- `%CSP.UI.Portal.Mirror.Monitor` and the read-only `LDAPsRO/LDAPRO` are excluded here as System Operation pages, although `Mirror.Monitor` (1546 lines, `%Admin_Manage`+`%Admin_Operate`) carries several configuration-grade actions (Promote, Demote, Set No Failover) — the System Operation digest should cover it.
- Twelve Hidden classes exist only on the instance; their content was not read.
