## REST layer — architecture, envelope conventions, test harness (with class paths)

### Dispatch shape

- One `%CSP.REST` subclass, `IRISCouch.API.Router` (`src/IRISCouch/API/Router.cls`), with `Parameter UseSession = 0` and `Parameter CONTENTTYPE = "application/json"`. One `XData UrlMap`; **no URL versioning** (no `/v1/`), because the wire contract is CouchDB's.
- Every `<Route>` calls a thin wrapper `ClassMethod` on the Router that (a) delegates to a per-subsystem handler class — `IRISCouch.API.{Server,Database,Document,Bulk,AllDocs,Changes,Attachment,Mango,Replication,Security,Auth,View,AdminUI}Handler`, all plain `%RegisteredObject` — and (b) calls `..RecordRequestMetrics()` before quitting (`Router.cls` lines 117–476). Handlers receive route params as method arguments and read/write the ambient `%request` / `%response`.
- Composite IDs (`_design/<name>`) are reassembled in the wrapper before delegation (`HandleDesignDocPut` etc., `Router.cls` 213–276) because `:param` matches a single segment.
- **Route ordering is load-bearing** and documented inline: explicit 405 method-guard routes and underscore sub-resources are listed before the `/:db` catch-alls; the comment records a real bug where `PUT /_all_dbs` fell through to `PUT /:db` and created a phantom database (`Router.cls` 21–27, 726–736; regression test `Test/MethodNotAllowedTest.cls TestPhantomDatabasePrevention`).

### `OnPreDispatch` as the middleware seam (`Router.cls` 508–668)

In order:
1. Trailing-slash normalization: if URL ends in `/` and is not root, set `pContinue = 0` and re-enter `..DispatchRequest(tStripped, pMethod)` (lines 519–524).
2. Auth context: sets process-private `%IRISCouchUser`, `%IRISCouchRoles` (a `%DynamicArray`), `%IRISCouchAuthMethod`; tries cookie → JWT Bearer → proxy headers → Basic, in that priority; any failure leaves anonymous context and **never blocks** the request at this layer (lines 525–586).
3. `/_utils` intercept: any URL starting `/_utils` bypasses the UrlMap and goes to `IRISCouch.API.AdminUIHandler.HandleRequest(relativePath)` — the comment gives the reason: "the SPA has multi-segment deep-link paths that UrlMap single-segment `:param` cannot match" (lines 587–605).
4. Per-database `_security` enforcement (lines 606–663): anonymous denied → 401, authenticated denied → 403, both rendered through `Util.Error`.
5. Metrics start timestamp `%IRISCouchRequestStart` and endpoint class `%IRISCouchEndpoint`.

### Envelope conventions

- **Error**: `IRISCouch.Util.Error.Render(pStatus, pSlug, pReason)` sets `%response.Status`, content type, and writes `{"error":slug,"reason":reason}` (`Util/Error.cls` 58–65). Thirteen slug constants as class parameters (`NOTFOUND`…`SERVERERROR`, lines 10–50). `RenderInternal(slug, reason, exception)` logs the full exception to the console log and the structured log and sends only a generic reason (lines 74–89, the "NFR-S8" comment). `Render405(allowed)` sets the `Allow` header (196–201). `GetSlugForStatus()` maps status → slug (208–223). Doc comment rule: "Handlers must NEVER construct error JSON inline."
- Router overrides `%CSP.REST`'s `ReportHttpStatusCode` (framework 404/405/other → envelope) and `Http405(pSupportedVerbs)` (`Router.cls` 693–714).
- **Success**: `IRISCouch.Util.Response.JSON(pData)` / `JSONStatus(pStatus, pData)` — writes `%ToJSON()` of a dynamic object or a raw string (`Util/Response.cls`).
- **Request body**: `IRISCouch.Util.Request.ReadBody()` → `%request.Content.Read()` → `%FromJSON`; **returns `{}` on parse failure without signalling** (`Util/Request.cls` 236–254). Handlers that need a 400 on bad JSON parse inline instead (e.g. `API/SecurityHandler.cls HandlePut`).
- **Content negotiation**: none. Response type is fixed JSON except attachments (stored content type, `API/AttachmentHandler.cls` 119) and Prometheus (`text/plain; version=0.0.4; charset=utf-8`, `Metrics/Endpoint.cls` 448). No `Accept` handling found in `API/` or `Util/`.
- **CORS**: no `HandleCorsRequest` parameter, no `OnHandleCorsRequest`, no `Access-Control-*` header anywhere in `API/` or `Util/` (grep, this run). `documentation/getting-started.md` line 468–472 tells operators to "enable CORS on the CSP gateway".

### Large payloads and streaming

- Attachment download: `%Stream` from storage, `tStream.OutputToDevice()` straight to the device ("NFR-P8: no buffering", `API/AttachmentHandler.cls` 113–124).
- Static UI files: `%Stream.FileBinary.LinkToFile` then `Read(32768)` loop with `Write` (`API/AdminUIHandler.cls` 1372–1402 in the bundled read; method `StreamFile`).
- Long-poll: `API/ChangesHandler.cls` 208–257 — `%SYSTEM.Event.Create/WaitMsg` on a per-database event name from `Storage.Changes.EventResourceName`, optional heartbeat that does `%response.Write($Char(10))` + `%response.Flush()` between waits, then re-checks the sequence. `feed=continuous` / `eventsource` return 400 "Feed mode not yet supported" (line 203–207); `documentation/deviations.md` §7 defers them to a standalone TCP listener (Epic 14).

### Test harness

- All backend tests are `%UnitTest.TestCase` (78 classes); the four `%RegisteredObject` files in `Test/` are probe helpers (`Test/ProbeHelpers.cls` is explicitly "ephemeral… may be deleted").
- Naming split: `XTest` = in-process unit test of handlers/engines; `XHttpTest` = live HTTP against the web app.
- **`IRISCouch.Test.HttpIntegrationTest.MakeRequest(pMethod, pPath, .pStatus, .pBody, pRequestBody, pContentType, pBinaryBody)`** (`Test/HttpIntegrationTest.cls` 213–270) is the shared HTTP helper: `%Net.HttpRequest` to `localhost:52773` as `_SYSTEM/SYS`, overridable via `^IRISCouchTest("Server"|"Port"|"Username"|"Password")`; prefixes `/iris-couch`; parses JSON if body starts with `{`/`[` else returns the trimmed string. Other classes call it as a class method (e.g. `Test/AdminUIHandlerTest.cls`, `Test/MethodNotAllowedTest.cls`).
- Variants for headers: `MethodNotAllowedTest.RequestWithAllow` (captures `Allow`), `AdminUIHandlerTest.MakeRawRequest` (raw body + `Content-Type` + `Cache-Control`), `AdminUIRBACTest.GetUtils(pSendAuth, …)` (auth on/off, all headers via `GetNextHeader`), `ErrorEnvelopeTest.RawRequest` + `AssertSingleEnvelope` (asserts no `}{` concatenation, i.e. no double envelope).

- Every test class overrides `%OnNew(initvalue)` and forwards to `##super(initvalue)`.
- Test web-app isolation: `Test/InstallerTest.cls` uses `/iris-couch-test-install/` and uninstalls in `OnAfterOneTest`.

## Auth and RBAC — model and classes

- **User store = IRIS `Security.Users`; no project user table.** Basic auth (`Auth/Basic.cls` 410–454) and `POST /_session` (`API/AuthHandler.cls` 808–819) both do `Set $Namespace="%SYS"`, `Security.Users.Exists(user,.obj)`, `Security.Users.CheckPassword(.obj, pw)`, restore namespace — the comment states this is "instead of `$System.Security.Login` to avoid switching process security context". Roles come from `Security.Users.Get(...)` → `tProps("Roles")` (`Auth/Basic.cls GetUserRoles`).
- **Cookie sessions are stateless HMAC tokens, not CSP sessions** (`UseSession = 0`). `Auth/Session.cls`: cookie value `base64(username:hexTimestamp:hmacSHA256Hex)`; secret from `Config.Get("AUTHSECRET")`, auto-generated with `$System.Encryption.GenCryptRand(32)` and persisted into `^IRISCouch.Config("AUTHSECRET")` on first use (`GetSecret`); expiry `AUTHTIMEOUT` (default 600 s); constant-time comparison (`ConstantTimeEquals`). `AuthHandler.HandleSessionPost` emits `Set-Cookie: AuthSession=<v>; Version=1; Max-Age=<t>; Path=/iris-couch; HttpOnly` — **no `Secure`, no `SameSite`** (`API/AuthHandler.cls` 832). Logout sets `Max-Age=0`.
- **JWT** (`Auth/JWT.cls`): HS256 only; enabled only when `JWTISSUER` and `JWTSECRET` are both set; verifies signature (`$System.Encryption.HMACSHA(256,…)`), required `exp` and optional `nbf` with clock skew from `^IRISCouch.Config("JWTCLOCKSKEWSECS")` (default 60), `iss` match, `sub` = username, roles from claim named by `JWTROLESCLAIM` (array or comma string). JWT identities are **not** looked up in `Security.Users`.
- **Proxy** (`Auth/Proxy.cls`): `X-Auth-CouchDB-UserName/Roles/Token`, token = hex HMAC-SHA1(username, `PROXYAUTHSECRET`); enabled only when the secret is set.
- **RBAC model** (`Auth/Security.cls`): per-database `_security` object `{admins:{names,roles},members:{names,roles}}` stored as JSON in `^IRISCouch.Security(db)`. `CheckAccess(db,user,roles,isAdminOp)`: no security object → open; role `_admin` or `%All` → server admin bypass; admin ops (PUT `_security`, PUT/DELETE `_design/*`) need admins list; member ops need members (or admins); empty members lists → any authenticated user. Deny on internal error. Enforcement lives in `Router.OnPreDispatch`, not in handlers.
- **Admin-party**: `Session.BuildUserCtx()` returns `{"name":null,"roles":["_admin"]}` for an anonymous request — used for JS design-doc callbacks (`Auth/Session.cls` 1191–1211 in the bundled read).
- **Admin UI gate** (`API/AdminUIHandler.cls`): `IsAuthenticated()` requires `%IRISCouchUser` non-empty, else `$Username` not in {`""`, `UnknownUser`, `_PUBLIC`}; the doc comment explains the CSP `DEFAULT_USER` carries `%All`, so a `$Roles`-only check admitted anonymous browsers (fixed in Story 13.4). `HasAdminRole()` checks `%IRISCouchRoles` for `IRISCouch_Admin` or `%All`, and falls back to `$Roles` only when an identity was confirmed. Anonymous → 401 + `WWW-Authenticate: Basic realm="IRISCouch Admin"`; wrong role → 403 (`Test/AdminUIRBACTest.cls`).
- **`_users` database sync** (`Auth/Users.cls`): writes to the CouchDB `_users` DB are intercepted inside the document transaction; password → `Security.Users.Create/Modify` in `%SYS` (IRIS hashes it), PBKDF2-SHA256 metadata (`$System.Encryption.PBKDF2`) is written back into the doc, plaintext stripped; deletes call `Security.Users.Delete`. It **hard-codes** `%DB_IRISCOUCH,%DB_IRISLIB,%DB_IRISTEMP` as roles appended to every synced user (lines 1466, 1509 in bundled read).
- **Angular side**: `ui/src/app/services/auth.service.ts` — `checkSession()` (`GET /_session`) at `APP_INITIALIZER` (`app.config.ts`), `login()` (`POST /_session` JSON `{name,password}` then re-`GET`), `logout()` (`DELETE`); state is a `BehaviorSubject<SessionResponse>`; **nothing is stored client-side** — the browser's HttpOnly cookie is the session. `guards/auth.guard.ts` redirects to `/login?returnUrl=`; `services/auth.interceptor.ts` clears state and redirects on any 401 except `_session`. `services/couch-api.service.ts` hard-codes `API_BASE = '/iris-couch/'` as an absolute path because `<base href="/iris-couch/_utils/">` would otherwise route API calls into the SPA fallback (its own doc comment). `services/error-mapping.ts` preserves the `{error,reason}` envelope verbatim.
- **CSRF**: no token, no `SameSite`, no origin check found in `Router.cls`, `AuthHandler.cls`, `AdminUIHandler.cls`, or the Angular interceptor. State-changing endpoints accept the cookie alone. (Absence claim: grep across `src/` and `ui/src/app/services` for `CSRF|SameSite|Origin`, this run, no hits in code.)
- Web application is created with `AutheEnabled = 64` (password) — `Installer.cls` `DEFAULTAUTHEENABLED`.

## Angular UI hosting — build, deploy into IRIS, serving, SPA fallback (with file paths)

- **Build**: Angular 18.2 standalone app (`ui/package.json`, `ui/src/main.ts bootstrapApplication`), builder `@angular-devkit/build-angular:application`, `"baseHref": "/iris-couch/_utils/"`, `outputPath {base: dist, browser: browser}`, `outputHashing: all` in production, budgets 500 kB/1 MB (`ui/angular.json`). `ui/src/index.html` carries `<base href="/iris-couch/_utils/">`, `<app-root>`, and a `data:` favicon. Fonts are self-hosted under `src/assets/fonts` — README's "zero external dependencies" claim holds for the bundle.
- **Build output is committed**: `git ls-files ui/dist` → 6 files (`3rdpartylicenses.txt`, `browser/index.html`, `browser/main-XXBCC7VQ.js`, `browser/polyfills-FFHMD2TL.js`, `browser/styles-KO5L73LS.css`, `browser/assets/fonts/…woff2`); `ui/.gitignore` comments `# /dist — committed for ZPM distribution (Story 11.5)`.
- **How bundles reach IRIS — answer: a `%CSP.REST` static-file handler class reading the filesystem, not a CSP `ServeFiles` web app and not a `module.xml` `<FileCopy>`.**
  - `Router.OnPreDispatch` intercepts `/_utils*` and calls `AdminUIHandler.HandleRequest(path)` (`Router.cls` 591–605).
  - `AdminUIHandler.GetDistDir()` resolves the directory: (1) `^IRISCouch.Config("UIDISTDIR")` if it is an existing directory, (2) `<IRIS install dir>/dev/iris-couch/ui/dist/browser/`, (3) `<install dir>/dev/iriscouch/ui/dist/browser/`; otherwise `""` → 500 "Admin UI dist directory not configured".
  - `module.xml` (entire file read this run) contains only `<Name>`, `<Version>`, `<Description>`, `<Packaging>module`, `<SourcesRoot>src`, `<Resource Name="IRISCouch.PKG"/>`. **No `<FileCopy>`, no `<CSPApplication>`, no `<Invoke>`.** Last touched in the Story 1.1 scaffold commit (`git log -- module.xml`).
  - Consequently, at HEAD, `zpm "install iris-couch"` compiles the package and does nothing else: it neither creates the web application nor places the UI bundle. `documentation/getting-started.md` 74–79 ("the installer… does four things… Creates the CSP web application…") and `_bmad-output/planning-artifacts/architecture.md` line 360 ("The ZPM `module.xml` references this directory as static web resources mapped to `/_utils/`") describe an intent the manifest does not implement. Resolved code-over-docs: the working install path is the manual one in `README.md` (`$System.OBJ.ImportDir` + `Do ##class(IRISCouch.Installer).Install($Namespace, "/iris-couch/")`), plus placing the built UI where `GetDistDir()` looks or setting `UIDISTDIR`.
- **SPA fallback**: `HandleRequest` URL-decodes, rejects NUL and `..`, normalizes against the dist dir with `%File.NormalizeFilename` and requires the result to be a prefix-child of the dist dir; if the file exists it streams it, otherwise it streams `index.html`; if `index.html` is missing → 404 "Admin UI not found - run ng build first" (`AdminUIHandler.cls HandleRequest`). Angular's own router catches unknown client routes with `{ path: '**', redirectTo: 'databases' }` and uses three custom `UrlMatcher`s to keep `/`-containing IDs in one param (`ui/src/app/app.routes.ts`).
- **Base href**: fixed at build time to `/iris-couch/_utils/`; the web-app path is therefore baked into the bundle, the `AuthHandler` cookie `Path=/iris-couch`, `Config.WEBAPPPATH`, `Metrics.Record.ClassifyEndpoint` prefix stripping, and `CouchApiService.API_BASE`. Changing the mount path requires a rebuild plus edits in at least those four places (inference from the cited lines).
- **Cache headers**: `SetCacheHeaders` → `Cache-Control: public, max-age=31536000, immutable` when `IsHashedAsset` (basename ends in `-<8+ alphanumerics>`), else `no-cache`. MIME map in `GetMimeType` (html/js/mjs/css/json/woff2/woff/ttf/svg/png/jpg/ico/map; default `application/octet-stream`). Verified by `Test/AdminUIHandlerTest.cls` (`TestHashedAssetCacheHeaders`, `TestIndexHtmlNoCacheHeaders`, `TestJsAssetServed`, `TestFontAssetServed`, `TestSpaFallback`).
- **Dev loop**: `ui/proxy.conf.js` proxies everything under `/iris-couch/_utils/` that is not a known SPA route or static extension to `http://localhost:52773` with `pathRewrite ^/iris-couch/_utils → /iris-couch`. `ui/smoke/smoke.mjs` boots `ng serve`, POSTs `/iris-couch/_session` (form-encoded), then `GET /_all_dbs` with the cookie; `.github/workflows/ui-smoke.yml` runs it on PRs touching `ui/**` on a self-hosted runner labelled `iris-smoke` (GitHub-hosted runners have no IRIS).

## Install mechanics

- `IRISCouch.Installer.Install(pNamespace = $Namespace, pWebAppPath = "/iris-couch/")` (`Installer.cls` 826–868 in bundled read): switch to `%SYS`; if `Security.Applications.Exists(path)` → `EnsureAdminRole()` + `Audit.Emit.EnsureEvents()` and return OK **without touching the existing app** (idempotent upgrade path); else `Security.Applications.Create(path, props)` with `NameSpace`, `DispatchClass="IRISCouch.API.Router"`, `AutheEnabled=64`, `Enabled=1`, `IsNameSpaceDefault=0`, `Description`. Namespace is restored in `Catch`.
- `EnsureAdminRole()` (private): `Security.Roles.Create("IRISCouch_Admin", "IRISCouch Admin UI access", "")` if absent; grants it to `$Username` and to `_SYSTEM` by appending to `tProps("Roles")` and `Security.Users.Modify` — **all best-effort, errors swallowed** ("do not fail the install").
- `Audit.Emit.EnsureEvents()`: registers 17 `Security.Events` under source `IRISCouch` (guarded by `Exists`), each `Enabled=1`.
- `Uninstall(path)`: `Security.Applications.Delete` only. Leaves the role, audit events, `^IRISCouch.*` globals and config in place (no code for them).
- `IsInstalled(path)`.
- **Configuration**: `IRISCouch.Config` — class parameters are the defaults; `^IRISCouch.Config(key)` overrides; `Get(key)`, `Set(key,val)`, `GetAll()` (redacts `AUTHSECRET`, `JWTSECRET`, `PROXYAUTHSECRET`). The class doc says it is "the ONLY class allowed to directly read `^IRISCouch.Config`", but `Auth/JWT.cls` line 555 (`JWTCLOCKSKEWSECS`) and `AdminUIHandler.GetDistDir` (`UIDISTDIR`) read the global directly and those two keys have no class-parameter default, so `GetAll()` omits them.
- **Namespace**: docs require a dedicated namespace (`Installer.cls` header "must be installed into a dedicated IRIS namespace (e.g., IRISCOUCH)"); `Auth/Users.cls` hard-codes `%DB_IRISCOUCH`, so the namespace/database name is effectively fixed for the `_users` sync feature.
- **Docker**: none — no Dockerfile/compose in the repo, and no docker mention in `README.md`, `documentation/*.md`, or `.github/` (find + grep, this run).
- **Global inventory** documented in `Config.cls` header (11 globals) is incomplete versus code: grep finds 20+ `^IRISCouch.*` names (listed under Names to avoid).

## Audit and metrics patterns

- **Audit** (`Audit/Emit.cls`): single entry point `Emit(pEventType, pDB, pDocId, pRev, pUser, pExtra)` → `$System.Security.Audit("IRISCouch", pEventType, pEventType, <EventData JSON>, <Description ≤128 chars>)`. EventData is `{db, docId, rev, user, …extra}`; user defaults to `%IRISCouchUser` then `$Username`. Wrapped in Try/Catch — "Audit failure must NEVER propagate". Typed helpers: `DocWrite`, `DocDelete`, `AuthSuccess(user, method)`, `AuthFailure(user, method, reason)`, `SecurityChange`, `UserWrite`, `ReplicationStart/Complete`, `ViewAttempt/Execute/Error`, `ValidateReject/Approve`, `FilterExecute`, `ViewIndexRebuild`, `JsRuntimeTimeout`, `SubprocessRestart`. Event types must be pre-registered (`EnsureEvents`) or IRIS drops them silently (consistent with the OcuPilot rule file). **Reading the audit trail**: there is no project endpoint or class that queries it; `documentation/troubleshooting.md` 170–178 points operators at the Management Portal audit viewer filtered on Event Source = `IRISCouch`.
- **Structured log** (`Util/Log.cls`): `Info/Warn/Error/Debug(subsystem, msg, data)` → `$ZU(9, "", "[IRISCouch] " _ {ts,level,subsystem,msg,data}.%ToJSON(), severity, 1)` into the console log; ISO-8601 UTC timestamps; never throws.
- **Metrics**: `Metrics/Collector.cls` uses `$Increment` on `^IRISCouch.Metrics("req",endpoint,method)`, `("status",code)`, `("lat",endpoint,<bucket>|"+Inf"|"sum"|"count")` with the standard Prometheus bucket set (`BUCKETS` parameter) — lock-free, multi-process safe. `Metrics/Record.cls Record()` is gated by `METRICSENABLED` and skips the `metrics` endpoint; `ClassifyEndpoint(url)` maps URLs to a bounded label set (`server, metrics, auth, mango, changes, document, replication, security, database, attachment, admin_ui, unknown`) and never emits db/doc names ("NFR-O2"). `Metrics/Endpoint.cls HandlePrometheus` renders `iriscouch_http_requests_total`, `iriscouch_http_status_total`, `iriscouch_http_request_duration_seconds` (histogram), `iriscouch_database_count` (gauge) in exposition format 0.0.4, and returns an empty body rather than an error on failure. Router wires `GET /_prometheus` directly to it and does not record metrics for it.
- Doc lag: `troubleshooting.md` 180 greps `/_prometheus` for `iriscouch_audit|iriscouch_replication`; `Metrics/Endpoint.cls` emits neither series.

## Reuse assessment — table: component | reuse as-is / adapt / not applicable | reason | evidence path

## Leads — open questions

1. **Intended IPM packaging for the UI.** `architecture.md` says `module.xml` maps `ui/dist/browser` as static web resources; the manifest does not. Whether the author planned `<FileCopy>` + `<CSPApplication>` or an `<Invoke>` of `Installer.Install` is not evidenced. OcuPilot should decide its own mechanism rather than inherit this gap; the IPM manifest reference on docs.intersystems.com is the place to verify `<CSPApplication ServeFiles>` semantics (not read this run).
2. **Anonymous reach with `AutheEnabled=64`.** `AdminUIRBACTest` says anonymous browsers previously reached the handler; the installer creates the app with password auth only (64). Either the test instance's web app had unauthenticated access enabled or `AutheEnabled` was later changed — not resolvable from code read this run. Relevant to OcuPilot because its portal will face the same `DEFAULT_USER`/`%All` trap if it enables unauthenticated access on its web app.
3. **Performance of streaming assets through `%CSP.REST`** versus a `ServeFiles` CSP application was not measured anywhere in the repo.
4. **JWT role trust**: whether OcuPilot should accept roles from a JWT claim (as here) or always resolve roles from `Security.Users`; this project's choice follows CouchDB, not IRIS security.
5. `compatibility-matrix.md` line 91 mentions an internal `%IRISCouch_Admin` duplicate role; no code creating it was found in the files read. Possibly stale doc.
6. **`_active_tasks` / replicator manager** (`Replication/Manager.cls`, `^IRISCouch.Jobs`) were not read; they may hold a background-job pattern useful for a portal's task views.
