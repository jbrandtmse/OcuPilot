Paged SELECT (confirmed, `QueryExecutor.getTableData`):

```
SELECT TOP {pageSize} {cols} FROM (
  SELECT TOP {offset+pageSize} {cols} FROM "S"."T" {WHERE} {ORDER BY}
) WHERE %VID > {offset}
```
(offset 0 uses a plain `SELECT TOP n`). Page size and offset are validated non-negative integers and interpolated; identifiers are validated against `/^[a-zA-Z_%][a-zA-Z0-9_%$.]*$/` and double-quoted; all values go as `?` parameters. A second query `SELECT COUNT(*) AS total FROM … {WHERE}` supplies `totalRows`.

Writes (confirmed): `UPDATE t SET "c" = ? WHERE "pk" = ?` (one cell per round trip), `INSERT INTO t ("c1",…) VALUES (?,…)`, `DELETE FROM t WHERE "pk" = ?` — all through the same `action/query` endpoint, one statement per request, no transactions.

**Web variant serving and auth (confirmed):** `server.ts` serves `public/` and mounts `@iris-te/webview/src` at `/webview`; `index.html` loads `webThemeBridge.css, theme.js, connection-form.css, /webview/theme.css, /webview/styles.css, /webview/grid-styles.css` and scripts `connection-form.js, ws-reconnect.js, WebMessageBridge.js, spa-router.js, /webview/main.js, /webview/grid.js`. HTTP routes (`apiProxy.ts`): `POST /api/connect` (validates against IRIS, creates session), `POST /api/test-connection` (stateless), `POST /api/disconnect`, `GET /api/session`, `POST /api/iris/query` (forwards `{query, parameters}` to Atelier with the session's Basic header), `GET /health`. Sessions are an in-memory `Map<string, SessionData>` holding host/port/namespace/**username/password** (`sessionManager.ts` l.2–11, l.100, l.216); token in HTTP-only cookie `iris_session`. Security middleware order helmet → cors → csrf → rate-limit (`server.ts`). **The WebSocket carries the `IMessageBridge` protocol**: upgrade authenticated by the session cookie or `?token=` (`wsServer.ts` `extractTokenFromUpgrade`; rejects with 401, close codes 4001/4002); each frame is `{command, payload}` JSON; `commandHandler.handleCommand` maps commands to core services using the session's credentials and a per-connection `ConnectionContext {namespace, tableName, schema}`, replying with one or more `{event, payload}` frames (e.g. `selectTable` → `tableSelected, tableSchema, tableLoading, tableData`). `getServerList`/`selectServer`/`disconnect`/`openServerManager` are stubbed for the web target.

## Limitations and known issues (from code, README, TESTING.md, docs)

- Single-column primary key only; `docs/initial-prompt.md` (l.235) asked for "WHERE clauses with AND conditions for multi-column primary keys" and a `%Dictionary`-based PK lookup — neither is implemented (`SqlBuilder.ts` has no buildUpdate/buildDelete; `QueryExecutor` takes one `primaryKeyColumn`).
- Identity-less tables: PK falls back to a column named `ID`; if absent, `findPrimaryKeyColumn()` returns `null` (grid.js l.1840–1855) — editing such tables cannot key the UPDATE/DELETE.
- Identifier regex forbids spaces, hyphens and non-ASCII, so tables/columns needing delimited identifiers are rejected as "invalid characters" (`SqlBuilder.ts` `VALID_SQL_IDENTIFIER`).
- `updateCell` reports `rowsAffected: 1` unconditionally (no check that the row still existed).
- `_getTableRowCount` swallows errors and returns 0 → pagination shows 0 total on count failure.
- Non-wildcard filters still use `LIKE ?` (case-insensitive equality, not exact match).
- Export all/filtered + import: VS Code only (see Findings). Current-page CSV export is client-side and host-independent.
- Undo: edit-mode-only restore, no history.
- Page-size default differs per host (50 VS Code, 100 web).
- Web server keeps IRIS passwords in process memory for the session lifetime (`sessionManager.ts`).
- macOS keyboard gaps: some handlers check `ctrlKey` only, Home/End (`TESTING.md` l.660, l.794).
- `webview.html` in the shared package is documentation only; real HTML is assembled in `TableEditorProvider._getHtmlForWebview` / `GridPanelManager` (VS Code) and `web/public/index.html`.
- Duplicate parse/format logic (TS core vs JS grid) can drift.
- No virtualisation marker in `grid.js` (rows rendered per page as DOM) — fine at 50–100 rows/page; a large page size is unverified.
