# OcuPilot — C4 model

Four levels. The spine is the contract; this is the shape. Where a diagram and an AD disagree, the AD wins.

## Level 1 — System context

```mermaid
graph TB
  Dev["Developer-administrator<br/>manages their own IRIS instance"]
  Ops["Production administrator<br/>read-only mode, kill switch"]
  OcuPilot["<b>OcuPilot</b><br/>Angular portal + agent co-pilot<br/>served from the instance it manages"]
  IRIS["<b>InterSystems IRIS</b><br/>the one instance OcuPilot manages<br/>security, tasks, processes, databases, logs"]
  LLM["<b>LLM provider</b><br/>Anthropic in the floor;<br/>OpenAI, Gemini, OpenAI-compatible later"]
  Classic["Classic System Management Portal<br/>fallback target for every screen"]

  Dev --> OcuPilot
  Ops --> OcuPilot
  OcuPilot -->|"in process, as the signed-in user"| IRIS
  OcuPilot -->|"HTTPS, the only outbound egress"| LLM
  OcuPilot -.->|"FR-9 fallback links"| Classic
  Classic --> IRIS
```

The only data leaving the instance goes to the configured provider, and only what the screen-context cap allows (AD-24, AD-42).

## Level 4 — The write path, in code terms

```mermaid
sequenceDiagram
  autonumber
  participant Tool as Write tool (in turn job)
  participant Prop as Proposal store
  participant Port as AdminPort
  participant User as User (browser)
  participant Conf as Confirm handler
  participant Aud as Audit

  Tool->>Port: fresh read of the scoped target
  Port-->>Tool: current property set
  Tool->>Prop: mint(tool, args, scoped identity, fingerprint, diff, token)
  Note over Prop: secret-typed fields excluded from stored args
  Prop-->>User: proposal card, 10-minute expiry
  User->>Conf: confirm(token, secret fields only)
  Conf->>Conf: reject any key not declared secret
  Conf->>Conf: re-check privileges, read-only, kill switch
  Conf->>Port: re-read target
  Port-->>Conf: current state
  Conf->>Conf: compare fingerprint - refuse on mismatch
  Note over Conf: atomic: claim token, evaluate prohibited set, write
  Conf->>Port: complete merged body (fresh read + diff)
  Port-->>Conf: result, %response.Status
  Conf->>Aud: agent marker (proposal id, scoped target, user)
  Aud-->>Conf: marked, or "not marked" - never fails the write
  Conf-->>User: confirmed
  User->>User: change event, re-fetch in place, highlight
```

## What each level is good for

| Level | Answers | Audience |
| --- | --- | --- |
| 1 Context | What is OcuPilot, and what does it touch? | Contest judges, Developer Community readers |
| 2 Containers | What is deployed, and what talks to what? | A new contributor's first hour |
| 3 Components | Where does a change go? | Story and epic work |
| 4 Write path | Why is the agent safe? | The claim the whole product rests on |
