## Goal

Bring the classic portal's Interoperability work into OcuPilot for namespaces that support it, with Analytics riding along, so the largest area the classic portal still owns is usable here. Shipped so far: category gating, production control, items and their settings, per-host tabs, the monitor, queue and job reads and actions, lookup tables, read-only business partners, host and transformation tests, the interoperability floor, per-screen permissions, the panel collapse, the agent's source reads, saves and creates, the shared tool-listing cache, the sign-in hand-off, a clean compile and install in a namespace without interoperability, screens that load on demand, the rule, BPL and DTL editors InterSystems built, loaded in place inside the shell (20.7), and the agent's confirmed edits to the content behind those editors (20.16). Three stories are ready for development: 20.8 (the schema viewer and the production configuration diagram), 20.9 (message search and the Header and Contents tabs) and 20.10 (source control). 20.9 was split for size. The session trace moved to 20.30, the next story to plan, and resend and edit-and-resend moved to 20.31. Still to come: item runtime actions, partner writes, the Analytics rider, and guided workflows with Investigate.

## Requirements & Constraints

- **Every write** is a server-minted proposal with a diff the instance computes, an explicit Confirm and an agent marker. A new write key joins the checked-in governance baseline in the same change, and a destructive key ships `false`. Each plan states the action's destructiveness, its key's default and its audit record.
- **The session trace (20.30, next to plan).**
  - **The acceptance.** Given a session, when its trace is opened, it renders as a visual trace, with a generated sequence diagram as the alternative.
  - **The charter** (measured at 20.9's plan):
    - **Screen.** A third tab in 20.9's message tab group, `interoperability/messages/trace` at position 3. It requires `%Ens_MessageHeader:USE` and `%Ens_MessageTrace:USE`, both held by `%EnsRole_Operator`, and its classic page is `EnsPortal.VisualTrace`.
    - **Read.** A port endpoint `MessageTrace`, `LIST`, criterion `message`. It runs two top-level statements: the header's `SessionId`, then the session's headers by `ID`, capped. The vendor resolves any header to its session. The classic trace reads the whole session plus `Ens_Util.Log`, `Ens_Rule.Log` and the IO log, with no cap.
    - **Drawing.** OcuPilot draws the trace itself, as an SVG sequence diagram, through 20.9's `body` input. Participants appear in first-appearance order. There is one arrow per header: a request is solid, a response dashed, and an error is marked. Each arrow links to its message.
    - **The alternative.** Mermaid `sequenceDiagram` text from the same rows. It follows the id and escape rules of the sibling project's `Diagram/Writer.cls` (`iris-execute-mcp-v2`, MIT, the owner's), without its compression and correlation. Rename on harvest.
    - **From the host test.** 20.6's host test answers a session id, so its answer can link to the trace. A session id is its first header's `ID` (inference). Measure it at Task 0.
  - **Why not the vendor's viewer** (measured in its bundle):
    - `/ui/interop/message-viewer` reads only `$NAMESPACE` and `SESSIONID`. `SESSIONID` opens a session's trace full height, and no parameter opens one message.
    - Every load stores an `Ens.Message.Search` row.
    - A namespace change pushes a history entry, and an unknown namespace silently falls back to the first.
- **Message reads (20.9, ready for development).**
  - **Endpoints** (AD-62 item 15):
    - `Messages` (`LIST`) takes the criteria `beginDateTime` (required), `endDateTime`, `status`, `type`, `source`, `target`, `bodyClass`, `session` and `errors`.
    - `MessageHeader` and `MessageContents` (`LIST`) take one criterion, `message`, the header `ID`.
    - Every statement reads `Ens.MessageHeader` with `%ExecDirectNoPriv` after the gate, with every value bound and WHERE fragments chosen by which criteria are present. The time window becomes ID bounds through two top-level statements, as the classic viewer does.
  - **Ids.** A message id is kept exactly and matches `^[1-9][0-9]{0,18}$`. An id no header holds reads as zero rows, and any other text is refused 400 `PORT.VALIDATION`.
  - **Contents** are rendered as text only:
    - EDI shows as the raw view or indented XML, `%XML.Adaptor` goes through `%XML.Writer`, and a character stream shows as read. Any other body is refused `INTEROP.MESSAGE.CONTENTS`.
    - At most 1,000,000 characters are shown, and each line is cut at 4,000.
    - Each read that opens a body first records the vendor's `%Ensemble/%Message/ViewContents` through `Ens.Util.Auditing.AuditViewMessage`, except for alarm messages. A failed audit never fails the read.
  - **Pairs.** All the message reads require `%Ens_MessageHeader:USE`, which `%EnsRole_Operator` holds. Contents also requires `%Ens_MessageContent:USE`, which `%EnsRole_Administrator` and `%EnsRole_WebDeveloper` hold.
  - **Screens.**
    - The list (server criteria) is `interoperability/messages`.
    - Its tab group is `interoperability/messages/document`: Header at position 1, and Contents at `.../contents`, position 2.
    - The classic page is `EnsPortal.MessageViewer`.
    - Queue messages' `rowTarget` opens the Header tab. The item tabs are `detail` screens, and a `detail` screen may not declare a `rowTarget`.
  - **What 20.9 does not use.** No saved searches (a named limit). It never touches `Ens.Message.Search`, `Ens.Message.Utils` or either saved-search store, and it does not embed the vendor's message viewer.
  - **Tests** use synthetic headers saved with `%New`/`%Save`, which needs no production. A fresh throwaway holds no message header, and the save does not set `SessionId`.
- **Resend and edit-and-resend (20.31, after 20.30).**
  - **The vendor call.** `Ens.MessageHeader.ResendDuplicatedMessage(id, .new, target, body, source, headOfQueue)` checks no privilege.
    - It needs a running production and a running target queue, and it refuses retargeting a response.
    - It keeps the session: `Resent` goes up by one and the Description reads "Resent <id>".
    - It audits `%Ensemble/%Message/Resend` on the new header.
  - **OcuPilot's gate.** It requires `%Ens_MessageResend:USE`, and `%Ens_MessageEditResend:USE` for an edit.
  - **The double gate.** The agent's proposal is the dry run: per-message verdicts, nothing sent. A person's action is a dialog showing the same dry run, then Confirm, and Confirm executes.
  - **The cap.** At most 100 messages per action. More than that is refused, never truncated.
  - **Edit-and-resend** works on one message, saving the edited body as a clone as `%ProcessSubmit` does.
  - **Surfaces.** It uses the message list's multi-select and the Header tab.
  - **Settled at its own gate:** the key posture (edit-and-resend at least as guarded as resend) and the armed `ProductionProbe` fixture.
  - **The vendor app's own Resend** sends any number of messages, in requests of 300, with no dry run.
  - **The harvested reference** (sibling project; rename on harvest):
    - A dry run is the default. Executing needs both "not a dry run" and "confirm"; either alone is refused with "No changes were made."
    - A filtered resend defaults to 100 messages. A match count over 500 is refused, and the window is at most 7 days.
- **Embedding a vendor app (20.7 as built; 20.8 follows it).**
  - **In place, never copied.** The app loads from the instance, signed in through 20.13's hand-off. The vendor's bundles are never copied or redistributed.
  - **Results.** In normal mode the app reports a save, a compile or a failed compile in its own notice inside the frame. Nothing reaches OcuPilot's shell, which shows results only through its own reads.
  - **When a frame is drawn.** A screen issues only its declared read, or another built screen's, and draws a frame only for a row that read answers. For a process or transformation, the row must also not be `Coded`. Otherwise the screen shows its "no longer exists" or "written as a class" sentence, and a refusal names the failed pair.
  - **A drawn frame is never navigated.** A new document, a namespace move or Refresh draws a new frame. The screen's note says leaving it, or choosing Refresh, discards unsaved changes (DW-2376, by design). There is no leave guard and no confirm dialog.
  - **The app can move away unseen**, through its own links and the history entries it pushes. The screen keeps naming its own document.
  - **Scope.** An embed brings no write tool, governance key, entity type, read tool or area, and no query parameter beyond `$NAMESPACE` and the app's document parameter.
- **The schema viewer and the diagram (20.8, ready for development).**
  - **Schema viewer.** One listed screen, `interoperability/schema-viewer`, with no read and no document parameter.
    - The app clears its `&ST` before reading it, so every address opens on ASC X12 (measured). The person picks HL7 v2.x or ASTM in the viewer's own list.
    - DW-2396 is a vendor candidate on the owner's hold. 20.8's AC2 is its tripwire.
  - **Diagram.** One unlisted screen, `interoperability/productions/diagram/<production>`, linked from Production items.
    - It draws the configuration app with `$PRODUCTION`, and only for a row whose `Name` exactly matches the route id.
    - Inside it the person may change configuration and start or stop the production as themselves. OcuPilot's write path, governance and agent switches do not reach the frame (inference).
    - Each load stores one `Ens.Message.Search` row for the person (measured).
- **Rule, DTL and BPL edits (20.16, done).**
  - **Tools.** Six tools, `.source` and `.save` on `interop.ruleeditor`, `interop.processeditor` and `interop.transformeditor`. They extend 20.21's class read and save.
  - **Pairs.** Each requires the editor screen's pairs plus `%Development:USE`. Each save also requires `%Ens_Code:WRITE`, because an editor path is never looser than the classic editor's, and routines-database WRITE.
  - **Kind checks.** `IsCodeOfKind` runs at the mint and again at Confirm.
  - **Confirm.** It is refused if the stored content changed after the proposal was minted. Every save compiles on Confirm. A compile also counts as failed when its console reports errors, whatever its status says.
  - **What they build on.** A source read is capped at about 60,000 characters and reports truncation. A save sends exact replacements, each matching exactly once. Only a document in its namespace's own routines database can be saved: never in `%SYS`, never a `%` name, never OcuPilot's own packages.
- **Source control (20.10, ready for development, after 20.31).** Its criterion was restated:
  - The embedded editors exchange hooks, menus, user actions and status with the instance themselves, as the signed-in person, and nothing reaches the shell (AD-63's named consequence).
  - OcuPilot's own saves run the same save and compile hooks through `AtelierPort`, in the caller's process. `GET doc` runs no load hooks.
  - An unreleased document is refused 409 `EXPLORER.DOCUMENT.SOURCECONTROL` (#5845, #5865 or #6151). An error from the hook's own `OnBeforeSave` stays 422 `EXPLORER.SAVE.REFUSED`.
- **Item runtime actions (20.25).**
  - A temporary stop, start or restart of one item is followed by the production update the vendor requires.
  - Each is refused by name where the vendor would answer success while doing nothing (a stopped production, a disabled item).
  - Copy and change of class run as the classic page does.
- **Partner writes (20.26)** on `Ens.Config.BusinessPartner`.
  - Each write is confirmed over a fresh read and records OcuPilot's own audit row.
  - The vendor renames by a delete and a create without a transaction, so a rename is refused or runs in one transaction.
  - Before a removal, it reads the items that name the partner, then refuses or warns.
- **Analytics (20.11).** Cube build, synchronize and repair are the only analytics writes. MDX results render with drill-through and cancel. Architect, Analyzer and the User Portal are linked, not rebuilt. Anything beyond those links needs a DeepSee-enabled namespace.
- **Workflows and Investigate (20.12).**
  - A workflow is a sequence of individually confirmed proposals, never a batch approval.
  - Each write still evaluates the prohibited set, both agent switches and governance.
  - Investigate starts from an alert or a log entry, and returns a recap and ranked hypotheses that cite the rows used.
- **No compile-time dependency on interoperability.**
  - No shipped class includes an interoperability include file. No shipped class names an `Ens.*`, `EnsLib.*` or `EnsPortal.*` class where the compiler resolves it: a superclass, property, argument or return type, `DependsOn`, `CompileAfter` or a class query's SQL. Such a value is typed `%RegisteredObject` or `%String` and reached at run time while switched.
  - `##class(Ens.…)` in a method body, `#dim`, embedded SQL and strings all compile.
  - `OcuPilot.Test.CompileWithoutInterop` and the `package` job enforce this.
- **Secrets and paths.**
  - A secret-named setting answers empty, and setting one is refused before any vendor call.
  - No endpoint accepts a path outside a case AD-21 names.
  - Pasted XML reaches a vendor parser only from its first `<`. HL7 text reaches its parser as a character stream (DW-2378, in the burn-down). A pasted message that declares a document type is refused.
- **Posture questions** go to the orchestrator, with options and a recommendation.

## Technical Decisions

- **Client loading (AD-5, AD-19).**
  - Every screen route has one `''` child, which loads through `rememberedPage(loader)`.
  - A new screen of an existing page needs only a descriptor and its map line in `ScreenOutlet`. A new page needs one loader line, never a static import.
  - Routes are generated from the descriptor mirror. `screens.generated.ts` is never hand-edited.
  - The initial bundle is about 1.92 MB, against a `maximumWarning` of 1992kB, and is re-measured at each forward merge. Each lazy chunk stays under 88 kB.
  - The client is zoneless and `OnPush`, with screen state in framework-free stores.
- **A `detail` tab's body (AD-5).** `DetailPage` takes an optional `body` component that draws the rows in place of the table. Everything else `ListPage` does stays unchanged: binding, refusal, refresh and the re-read when the id changes. 20.9's Contents tab is its first consumer, and 20.30's trace is the next.
- **Embedded apps (AD-63)** are a named exception to AD-28 and AD-47.
  - **Source.** Only `interopEditorSource` (`ui/src/app/core/vendor-frame.ts`) builds `/ui/interop/<app>/index.html`, with `$NAMESPACE`, from a closed vocabulary. A document value that is not a `CLASS_NAME` answers `null`, so no frame is drawn.
  - **Frame.** `app-interop-editor-frame` draws one unsandboxed `<iframe>`. Its `src` is set once, and a new source or `revision` draws a new element.
  - **Nothing crosses.** OcuPilot posts nothing into the frame and reads nothing from it. The CSP, headers, token store and CORS are unchanged.
  - **Redraws.** 20.16's editor page redraws on a `changed` event of type `class` that names its document.
- **Interoperability port (AD-62, `Port/InteropPort`).**
  - **Its role.** It is the only class that starts, stops, restarts, updates or recovers a production, and the only source of interoperability reads. It calls the vendor classes the classic pages call, in process, as the signed-in user.
  - **Extending it.** A new read or write extends the port and names its case in AD-62 at its spec gate. A read also names its case in AD-36. 20.30's trace read and 20.31's resend each add one.
  - **Pairs by endpoint.** A new endpoint takes an explicit `Pairs` branch ahead of the `CODEPAIRS` default, as 20.9's three do.
- **Gate first.** The vendor's production, lookup, partner and test calls check no privilege (measured), so the port's gate is the whole gate.
  - **Order.** The endpoint's pairs come first, then READ on the namespace's globals database, or WRITE for a write. A refusal names the failed pair.
  - **Extra pairs** are declared only where a least-privileged run measured them. Each is refused by name before any port call, and a test that removes it pins it.
  - **The floor** admits `%Ens_Portal:USE`, so every new surface declares its own pair. The `InteropFloor*` rosters pin this.
- **Classic pages and adjustment (AD-44, AD-64).** `Screen.Gate.RequiredPairs` is the one reader of a screen's requirement. It unions the custom resource of each classic page the screen replaces. A port's pairs and the vendor's are never adjustable.
- **SQL reads without grants.**
  - `InteropPort` reads `Ens.MessageHeader` and `Ens_Util.Log` through `SqlRows`, with `%ExecDirectNoPriv` after its own gate.
  - No such statement nests a query that carries `TOP`. On a cold cached query that is refused with SQLCODE -99, and a copy a privileged reader warmed hides the failure. Use separate top-level statements, or a top-level `UNION ALL` of `TOP` branches.
- **Namespace.**
  - `appliesWhen` uses `IsEnsembleNamespace`, plus `%IsDeepSeeEnabled` for Analytics.
  - The port switches by explicit save and restore, and calls no `OcuPilot.*` class while switched. Local-to-UTC conversion therefore runs before the switch.
- **Write shape.**
  - **Action-style.** Each write declares its request type and fingerprints a fresh read the port composes. Anything the vendor would answer as a silent success is refused by name before any vendor call.
  - **Two callers, one operation.** A screen action and the agent's write share the fresh read, the prohibited set inside the per-target lock, the gate, the change event and the read-back.
  - **One request.** Each write finishes in its own request, capped at 15 s, with no spawn site.
  - **Snippets.** Every port that defines `Invoke` also defines a pure `Snippet`, with secrets as placeholders.
- **Audit.** Item and setting changes go through `Ens.Util.Auditing.AuditModifyProductionConfig`. A contents read and a resend record the vendor's own message audit events. Writes the vendor does not audit record OcuPilot's own `ConfigChange`.
- **Reuse rather than copy.** Extend the shared helpers:
  - the server side: `SqlRows`, `LocalStamp`, `RenderTargetHere`, `Ledger.LocalToUtc`, `IsTestWrite` and the `INTEROP.TEST.*` codes;
  - the client: `core/test-answer.ts`, `DataTable`'s getters and the shared skeleton and fault classes;
  - the tests: `runIris`, `list-spec.mjs`, `panel-spec.mjs` and InteropFloor's principals.
- **Reads and ids.**
  - Reads use source kind `interop`. Every read has a row cap and reports truncation.
  - A parent-scoped list takes its parent's route id as its one criterion.
  - An id keeps every part exactly and is percent-encoded in one path segment.
- **Tools.**
  - **Names and declarations.** New interoperability tools extend the `InteropAction` hierarchy, are named `<area>.<screen>.<verb>`, and declare their `CLASSICPAGES`. Each new write type is reviewed against AD-10's prohibited set.
  - **What a turn sees.** A turn starts with the shell area's tools, `shell.tools.find` and the screen context's `tools`.
  - **Gemini.** Keep numeric enums at the top level of the schema.
- **Untrusted content.** Message bodies and headers, session participants, log text, names, settings and rule, DTL or BPL content are untrusted.
  - They reach the screen only as interpolated text.
  - They reach the model only through the one sanitizer. No gate or test relies on the sanitizer as its defense.
- **Measure on the instance**, and amend the spine at the spec gate rather than working around it.

## UX & Interaction Patterns

- **Loading.** A screen's first load shows its skeleton until the first page arrives (two-second target), never on a re-fetch.
- **Rail and tabs.**
  - Interoperability and Analytics follow System Explorer, and appear only where the namespace reports the feature.
  - A screen joins the side bar only once it has shipped.
  - An item's tabs are Status, Settings, Queue, Log, Messages, Jobs and Test. A message's tabs are Header, Contents and, from 20.30, Trace.
- **Embed screens** are `viewer (source)` screens with a bar above the frame holding the note and Refresh.
  - The editors' bar also says the agent reads only what is saved (20.16).
  - The Schema viewer shows no skeleton, empty sentence or refusal of its own.
  - The Configuration diagram behaves as the editors do.
- **Gated controls are never hidden.** They stay focusable and `aria-disabled`, and name the failed pair.
- **Strings.**
  - Each list or tab has a title, an empty state and three suggested prompts. A write-capable list's empty state adds the line inviting the agent.
  - Every new string goes into EXPERIENCE.md's Fixed strings and `strings.ts`, whose values are unique. A refusal sentence lives once, on the server, pinned equal to its fixed string.
  - `strings.test.mjs` now bounds the literal count at 3,800. The next raise comes when the count is within 50 of the bound.
- **Dialogs.** A dialog exists only where EXPERIENCE.md's dialog list names one, so 20.31's dry-run dialog amends that list at its spec gate. Dialogs never stack. A destructive screen action uses the typed-name confirm.
- **Auto-refresh** is opt-in per screen, off by default, and declared in the descriptor and in EXPERIENCE.md's roster.
- **Cards.**
  - Proposal cards follow the standard lifecycle. An agent's destructive proposal carries no typed name.
  - A block over about eight lines starts collapsed with a summary line. Confirm never requires expanding it.
  - A code change behind an editor shows the line diff. Its consequence says the editor opens the document again and drops changes not saved there.
