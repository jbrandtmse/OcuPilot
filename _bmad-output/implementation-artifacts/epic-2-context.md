# Epic 2 Context: Every area shows live instance data

## Goal

Each of the six areas shows real instance data: Web applications, Users, SSL/TLS, Task schedule, Processes, and in Logs the audit viewer, a bounded messages.log endpoint and the application error drill-down. Every screen is backed by one descriptor-declared read that the agent's read tool shares, and every admin-API call goes through one port. The six lists are built; what remains is the Logs area's file and error reads — the first reads in the epic that do not go through `AdminPort`.

## Requirements & Constraints

- **Bounds.** First page within 2 s at 1,000 rows, measured end to end against the instance on the audit viewer (DW-258 closed). Every read is capped (default 1,000, editable, persisted per screen; no ceiling, no page-size control) and reports truncation.
- **One read, two consumers.** The tool's view is the screen's, narrowed by the context cap and stripped of secret fields. Read tools are not dispatchable until Epic 4.
- **Privilege.** A gate is a set of `(resource, permission)` pairs, all required, checked per call, never cached; a denial names the failing pair. A descriptor names the classic page it replaces, so an operator's custom resource on it still applies.
- **Reads only, by construction.** `AdminPort.TYPESUFFIXES = "GET,LIST,INFO"` keeps every vendor write type unreachable. No `rowActions`, no `primaryAction` on any Epic 2 screen; terminate, suspend, resume and broadcast are Stories 5.12, 7.8 and 16.6.
- **Navigation.** No screen links out to the classic portal; an unbuilt screen has no side-bar entry. Ids use the one-segment encoder — a name-keyed entity is a `single` id, a multi-column key a `composite` one.
- **Logs.** No endpoint takes a filesystem path: a fixed source enum, the directory from `$System.Util.ManagerDirectory()` resolved per call and never cached. A held byte offset is validated against the file's current identity so a page restarts cleanly across rotation, and no request can load the whole file. `LogSourcePort` inherits no vendor gate, so it evaluates its declared resource with `$System.Security.Check` before any file access — a line reaches a user only if that user could have read it directly. The error log reads only through `SYS.ApplicationError`'s own queries (never an `^ERRORS` traversal, never `%CSP.ErrorLog`), switches to `%SYS` once by explicit save and restore with the restore first in every `Catch`, carries the target namespace as a parameter, takes that namespace from the drill level alone and never from a route parameter, resolves its permission per namespace, and keeps the captured variable table on screen only — never in context, never to the model.
- **Known gaps — name them, do not re-file, do not work around per screen.** Owed to the burn-down: no manual Refresh action on any screen (DW-260); a stopped Task Manager raises no banner (DW-270); a misspelled *top-level* descriptor key installs silently (DW-271); EXPERIENCE.md citations outside `strings.ts` are ungated, ~60 unresolved (DW-272); a list's table frame collapses to header height, so the viewport reads `clientHeight` 0 and a real click at a row's centre lands on the footer — specs click above the fold and set `scrollTop` directly (DW-273); a query's own privilege refusal arrives as a 500 naming no pair (DW-274); OS management will gate on `%Admin_Manage:USE` once 6.8 and 7.8 land (DW-275); an over-long criterion answers 500, so the criteria grammar needs a `maxLength` (DW-279). Accepted as they stand: DW-276, DW-282 to DW-286.

## Technical Decisions

- **AdminPort.** `OcuPilot.Port.AdminPort.Invoke` is the only caller of admin endpoints and the only file naming `%Api.Admin` (checked). Callers pass a package-relative endpoint, a type (`GET`, `LIST`, `INFO`) and `pQuery`; anything but OK plus 2xx is a `{error, reason, code}` fault. Async calls are self-queued and polled inside the port (`PORT.TIMEOUT`, 30 s) — the audit LIST is that path, and `ShouldRunAsync()` is 0 for it, so never assert otherwise.
- **Read and table grammar.** `read`'s closed key set is six: `source` (`port`, `endpoint`, `type`, optional `rowGet`), `fields`, `filter`, `sort`, `paging: cap`, `table` (`columns` of `{field, labelKey, kind}`, exactly one `name` kind), and `criteria`. No secret field is a column, filter or sort. There is **no cursor paging**, so 2.11 would extend the grammar (inference). Every rule is a refusal sentence held identically by `Registry.*Problem` and its `screen-mirror.mjs` twin; change both, and pin new ones in a shared corpus class as `Test/RowGetCorpus.cls`, `Test/AdminPairCorpus.cls`, `Test/BannerCorpus.cls` and `Test/CriteriaCorpus.cls` do.
- **Declared read surfaces, none of them built per screen.** `criteria` (2.10) carries server search parameters — typed fields (`text`, `datetime`, `choice` with declared `options`) plus a marker override, admin-source only and incompatible with `refreshes`; the declared roster is the allow-list on both callers, and `Read.SeedCriteria` refuses a bad value 400 `READ.CRITERION` **before** the port, which is what keeps the vendor's silent "unknown name → `-1`, matches nearly every row" conversion unreachable. `rowGet` (AD-36) is one detail call per surviving row — a 404 drops the row, any other row fault fails the read. A `banner` is a second read raising a strip above the table, and **any banner fault answers `""`** so the rows still list, the opposite of `rowGet`'s rule. `refreshes` plus `refreshRates` (AD-43) buy the shared timer, persisted rate and silent re-fetch with no client change. Any control a screen renders unavailable uses `aria-disabled` plus `readonly`, never the native `disabled` attribute the Accessibility Floor forbids.
- **A screen is one descriptor class** directly in `Screen/Descriptor/` (the mirror reads it flat), then `node ui/tools/screen-mirror.mjs`; the shared page renders it, with no per-screen route, handler, tool class or store. Six templates to copy from: `WebAppList` and `UserList` (`rowGet`), `SslConfigList` (plain), `TaskScheduleList` (banner), `ProcessList` (`kind: number`) and `AuditList` (the `list (server criteria)` archetype, with a composite id and its own page and store). Each declares its own gate. Never set `navigates` on a list's area.
- **A pair set is established, not read off the endpoint (AD-29).** An endpoint's `ResourcesOR()` is a **lower bound**: the query behind it may check more, and a screen declaring only those resources passes its own gate and then faults inside the port. Establish it two ways together — read the backing query's own privilege check in `irislib/`, **and** run the read as a real least-privileged principal on a throwaway, adding what the instance still refuses. Every admin-port read also declares `%DB_IRISSYS:READ`, because the port switches to `%SYS` for every request type; both engines refuse, as their **last** check, a read that omits it. Never `%DB_IRISSECURITY`: IRIS refuses to grant it to a role (probed).
- **An area covers its screens.** `Registry.AreaCoverageProblem` refuses a screen declaring a pair its area does not. Containment only — a surplus area pair stands, which is the false-denial cost 2.11 must decide: Logs declares `%Admin_Operate:USE`, `%Admin_Secure:USE`, `%DB_IRISSYS:READ` for the audit viewer, while the two remaining Logs screens need only the first (DW-278). Pair **order** matters — the gate names the first unheld pair and `failedPair` fixtures pin it, so append rather than prepend; adding an area pair flips `Test/Wire.cls`'s verdict for a principal holding only the old set.
- **Fields and secrets.** `Read.Project` copies only `read.fields` and writes `null` for a missing key, so the field-presence test is the drift guard. Probe the live source and declare its own spelling (`Nspace`, not `Namespace`, on processes), carrying the readable label in the string key; where the source's value is wrong rather than absent, declare the field nowhere — an absent column beats a false "No" (DW-269, routed to 4.10). `screen-mirror.test.mjs` refuses any declared field name matching `CREDENTIAL_RE` (suffix-anchored, so `PrivateKeyFile`-shaped names are pinned by hand, DW-268); `context.secretFields` is for what a read does carry.
- **Execution and the view rule.** `Screen.Read.Execute` asks for `maxRows` + 1, strips secret fields once, answers `{fields, rows, truncated, banner}` at `GET /api/ocupilot/screens/<toolIdentifier>/read?maxRows=`, declared criteria appended URL-encoded. Emitted timestamps are ISO-8601 UTC and calendar comparisons use `+$Horolog`. Client and server filter and sort identically over `Test/ReadViewCorpus.cls` — case-insensitive ASCII contains, stable one-field sort, numbers numerically, `null` last, an array's members joined by `, ` being what the cell, the filter and the sort all read — and a number arriving as a JSON string compares lexicographically, so a counter's JSON type is itself asserted.
- **Client shell.** Pages read through `RefreshService.readNow()`; the store persists sort, direction, filter and max rows per screen, and `applyTick` writes only rows, truncation, banner and stamp; a refused tick is never retried. The outlet mounts no page until `NavigationService.answered()` (fail-open), so a denied deep link issues no read. A screen declaring `read.sort.fields` gets the command bar's sort menu; sort is never a clickable header, and `aria-sort` is a read-only readout. The client's one `role="dialog"` arrived with 2.10 (440px, Escape closes, focus returns to the opener, no stacking). `Registry.ClassicLinkProblem` and `classic-links.mjs` share one corpus.
- **Tripwires — each new screen edits all of them.** `Test/ReadTool` pins the production tool list by content (six today, `$Order`-alphabetical); `Test/Descriptor.cls` pins every area's pair set, `navigates` and `pinBottom`; `navigation.test.mjs` pins built routes in rail order; `navigation-wire.test.mjs` and `rail-wire.spec.ts` hold two byte-identical `LIVE_PAYLOAD` copies, **neither of which goes red on its own**; `screen-mirror.test.mjs` pins the descriptor and criteria rosters; `Install.Smoke` runs one live read per built list (six today) and `Test/Smoke.cls` re-derives its bounds from `Smoke.cls`'s source.
- **Browser and denial legs.** `ui/browser/list-spec.mjs` exports `viewCount`, `clearFilter` and `filterToSubset`, which asserts `0 < kept < total` off `aria-rowcount` and never DOM rows — the table virtualises — and a leftover filter silently satisfies a cap assertion, so clear before asserting one. Under `%All` every check passes, so a denial needs a real principal: `Test/Wire.cls` and `Test/WireSecurityRead.cls` (a leg per screen), or a browser spec on `scripts/ci-throwaway.sh` (`ocupilot-ci`, `OCUPILOT_DEMO=1`). No security-object mutation on live `ocupilot`; leave zero principals behind.

## UX & Interaction Patterns

- **One data table** on CDK virtual scroll: `name` a `code` link, identifiers in `code`, numbers tabular and right-aligned, `status` a disc plus "Yes"/"No" (a boolean outside a `status` column reads Yes/No with no disc), empty "(none)" in body type, source strings verbatim. Footer "<n> rows", "Max rows" and the cap notice; "Filter rows" drives the filter.
- **Loading and empty.** Skeleton on first load only. The empty state follows only a successful zero-row read, names its scope, and invites the agent only on a write-capable screen; a faulted, denied or filtered-to-zero view is never empty. A screen whose empty state is unreachable still declares the key.
- **Gating.** `aria-disabled` plus "Requires <resource>:<permission>" in rail, side bar and command box; a denied deep link shows the title and "You need <pair> to open <screen>."; a 403 is an inline alert and on-screen data stays.
- **Strings.** Each screen adds its EXPERIENCE.md Fixed strings row (title, headers, empty-state lines) **before** its `strings.ts` keys — `strings.test.mjs` derives a closed-world key equality from that table, so a key with no row fails the build. Its `EXPERIENCE.md:<line>` comments are re-resolved, values must be unique (a label two screens share is one shared key), and non-ASCII is `\uXXXX`. Inserting rows shifts citations elsewhere in `ui/src` (DW-272); repair only the `strings.ts` ones, and never "bump" a citation into a document that did not move.
