# Epic 2 Context: Every area shows live instance data

## Goal

Each of the six areas shows real instance data: Web applications, Users, SSL/TLS, Task schedule, Processes, and in Logs the audit viewer, application error drill-down and a bounded messages.log endpoint. Every list is backed by one descriptor-declared read that the agent's read tool shares, and every admin-API call goes through one port. Build step 1: once the smoke script passes, the listing build can be submitted.

## Requirements & Constraints

- **Bounds.** First page within 2 s at 1,000 rows (table proven in the browser; the end-to-end read is measured in 2.10). Every read is capped (default 1,000, editable, persisted per screen; no ceiling, no page-size control) and reports truncation.
- **One read, two consumers.** The tool's view is the screen's, narrowed by the context cap and stripped of secret fields. Read tools are not dispatchable until Epic 4.
- **Privilege.** A gate is a set of `(resource, permission)` pairs, all required, checked per call, never cached; a denial names the failing pair. A descriptor names the classic page it replaces, so an operator's custom resource on it still applies.
- **Navigation.** No list links out to the classic portal; an unbuilt screen has no side-bar entry. Ids use the one-segment encoder (`/csp/myapp`, `_SYSTEM` round-trip); a name-keyed entity is a `single` id, not composite.
- **Secrets and state.** No private key material in any SSL/TLS read. Disabled or expired (an `ExpirationDate` set and earlier than today on the instance clock) reads as a word, never color alone.
- **Never ship a field the vendor lies about.** The tasks LIST coerces every `Suspended` to `false`, so the task list declares it nowhere — an absent column beats a false "No" on screen, and the demo fixture's suspended task cannot be told apart in a list (DW-269, routed to 4.10, which may use a `rowGet` of type `INFO`).
- **Logs.** No endpoint takes a filesystem path: a fixed source enum, directory from `$System.Util.ManagerDirectory()` per call; pages survive rotation; `LogSourcePort` runs `$System.Security.Check` first. The audit viewer never hides OcuPilot's own events, its marker filter is not a default, and its set needs `%Admin_Secure` and `%Admin_Operate`. The error log reads only through `SYS.ApplicationError`, takes its namespace from the drill level alone, and its variable table never reaches context or the model.
- **Known gaps, already filed — do not re-file, do not work around per screen.** No list has the manual Refresh action (DW-260). Every list's table frame collapses to header height, so the virtual-scroll viewport reads `clientHeight` 0 on all four routes and a real click at a row's centre lands on the footer (DW-273, user-facing, from 2.4's height chain); browser specs click above the fold.

## Technical Decisions

- **AdminPort.** `OcuPilot.Port.AdminPort.Invoke` is the only caller of admin endpoints and the only file naming `%Api.Admin` (checked). Callers pass a package-relative endpoint, a type (`GET`, `LIST`, `INFO`) and `pQuery`; anything but OK plus 2xx is a `{error, reason, code}` fault. Async calls are polled inside the port (`PORT.TIMEOUT`, 30 s). The epics' REST paths name the data, not the call: 2.5's `GET /web-apps` is the `WebApp.App` LIST.
- **Read and table grammar.** `read`: `source` (`port`, `endpoint`, `type`, optional `rowGet`), `fields`, `filter`, `sort`, `paging: cap`, `table` (`columns` of `{field, labelKey, kind}`, exactly one `name` kind; `emptyAgentKey` only when a primary or row action is declared). No secret field is a column, filter or sort. No cursor paging, so 2.11 would extend the grammar (inference). Every rule is a refusal sentence held identically by `Registry.*Problem` and its `screen-mirror.mjs` twin; change both, and pin new ones in a shared corpus class as `Test/RowGetCorpus.cls`, `Test/AdminPairCorpus.cls` and `Test/BannerCorpus.cls` do.
- **A list screen is one descriptor class** directly in `Screen/Descriptor/` (the mirror reads it flat), then `node ui/tools/screen-mirror.mjs`; `ListPage` renders it, with no per-screen route, handler, tool class, page, store or `areas/` file. Four templates now — `WebAppList` and `UserList` (with `rowGet`), `SslConfigList` (without) and `TaskScheduleList` (without, plus auto-refresh and a banner) — all instance scope and `single` id. The gate does not union the area's pairs; each descriptor declares its own. Never set `navigates` on a list's area.
- **The admin-port read pair set is grammar.** An endpoint's own resource plus `%DB_IRISSYS:READ`, each necessary and both sufficient (throwaway, real principal), because `AdminPort.RunSequence` switches to `%SYS` for every request type and `%SYS`'s `%DB_IRISSYS` has no public permission. `ReadProblem` and `readProblem` each refuse, as their **last** check, an admin-port read whose `privileges` omit it — one identical sentence pinned by `Test/AdminPairCorpus.cls` in both engines. Every admin-port descriptor and read fixture declares the pair. Never `%DB_IRISSECURITY`: IRIS refuses to grant it to a role (probed).
- **An area covers its screens.** `Registry.AreaCoverageProblem`, called from `Validate` per descriptor right after `MalformedPair`, refuses a screen declaring a pair its area does not, naming class, area and pair (`Test/AreaPair/Bad.cls` + `AreaPairRegistry` falsify it). Containment only — a surplus area pair stands. `web-applications`, `permissions`, `security` and now `tasks` declare `%DB_IRISSYS:READ` beside their own resource; pair **order** matters, since `Gate.EvaluatePairs` names the first unheld pair and `failedPair` fixtures pin it, so append rather than prepend. Deliberately no mirror twin: `Validate` is the roster check CI runs.
- **Banner grammar (new in 2.8).** A descriptor may declare one `banner`: `{source: {port, endpoint, type: GET}, field, equals, messageKey, severity}` — a second port read on the same descriptor whose match raises a strip above the table. Refused at install by `Registry.BannerProblem` (in `Validate` between `RefreshProblem` and `ClassicLinkProblem`) and its sentence-for-sentence mirror `bannerProblem`, both pinned by `Test/BannerCorpus.cls`; the severity set is closed and lives in the registry. Resolved inside the screen's own read by `Read.BannerKey`, drawn by `ListPage`. **Any fault answers `""`** so the rows still list — deliberately the opposite of `rowGet`'s fault rule. A banner is legal only beside a declared `read`, which is what makes the read's own pair cover its call; `banner.messageKey` is inside the build-time string-key check; it is chrome, not rows, so it never reaches the tool payload, and a refresh tick re-evaluates it. A misspelled *top-level* key still installs silently (DW-271).
- **Key material stays out by shape.** `Read.Project` copies only `read.fields`, and `screen-mirror.test.mjs` refuses any declared field name matching `field-lists.mjs`'s `CREDENTIAL_RE` over every production descriptor — suffix-anchored, so a detail read over `PrivateKeyFile`-shaped names pins them by hand (DW-268, widened in 9.5). `context.secretFields` is for what a read does carry.
- **Fields are the live row's keys.** Probe the vendor LIST; it can differ from the GET/PUT schema (`Namespace`, not `NameSpace`). `Read.Project` writes `null` for a missing key, so `Test/ScreenRead`'s field-presence test over admin-LIST descriptors is the drift guard.
- **Execution.** `Screen.Read.Execute` asks for `maxRows` + 1, strips secret fields once, answers `{fields, rows, truncated}` at `GET /api/ocupilot/screens/<toolIdentifier>/read?maxRows=`.
- **Per-row detail (AD-36).** A read may name one detail call, `read.source.rowGet`, when the LIST omits needed fields, declaring its type `GET` (default) or `INFO`. After the cap, one call of the same endpoint per surviving row merges the declared `fields` with their JSON types; a 404 drops the row, any other row fault fails the whole read, and `truncated` still follows the LIST. `rowGet.derived` computes fields from a closed rule set — the only rule is `beforeToday`, true when a `YYYY-MM-DD` value is earlier than `+$Horolog`, false for `""`/`null`, malformed a 500 `INTERNAL`.
- **Auto-refresh is declared, not built (AD-43).** A screen sets `refreshes` and `refreshRates` (whole seconds, strictly ascending, all > 0, non-empty iff `refreshes` — `RefreshProblem` and its mirror); the shared framework owns the timer, the persisted per-screen rate, the silent re-fetch and the preservation of sort, filter, selection and scroll. `TaskScheduleList` is the first non-empty case and needed no client change beyond the mirror.
- **Dates.** The spine's Conventions Dates row is scoped: emitted timestamps are ISO-8601 UTC; comparisons against the instance's own calendar date use `+$Horolog`.
- **View rule, twice.** Client (screen) and server (tool) filter and sort over `Test/ReadViewCorpus.cls`: case-insensitive ASCII contains; stable one-field sort, numbers numerically, `null` last. An array's text is its members' joined by `, ` in both engines, and that text is what the cell, the filter and the sort read.
- **Classic links, once.** `Registry.ClassicLinkProblem` and `classic-links.mjs` `classicLinkProblem` are pinned against one shared corpus, `OcuPilot.Test.ClassicLinkCorpus`. `classicLinkExemption.exempt` must be a JSON boolean.
- **Client shell.** `ListPage` reads through `RefreshService.readNow()`; the store persists sort, direction, filter and max rows per screen. A refused tick is never retried. The outlet mounts no page until `NavigationService.answered()` (a failed map read counts, fail-open), so a denied deep link issues no read.
- **Tripwires per list — each new list edits all of them.** `Test/ReadTool` pins the production tool list by content (today `permissions.users.read`, `security.ssl.read`, `tasks.schedule.read`, `webapp.list.read`); `Test/Descriptor.cls` pins every area's pair set, `navigates` and `pinBottom`; `navigation.test.mjs`, `navigation-wire.test.mjs` and `rail-wire.spec.ts` pin built routes and `LIVE_PAYLOAD`; `Install.Smoke` runs one live read per built list (four today), each check pinned to the screen it actually read, with an `arealists` pending note now naming only Logs and OS management.
- **Browser specs share one filter helper.** `ui/browser/list-spec.mjs` (no `*.browser-spec.mjs` suffix, so the suite glob skips it) exports `viewCount`, `clearFilter` and `filterToSubset`; `filterToSubset` clears first so every leg runs from the whole list, asserts `0 < kept < total` off `aria-rowcount` (never DOM rows — the table virtualises), and that the named row survives. Every new list spec uses it (DW-267, closed in 2.8).
- **Denial and demo checks run on the throwaway.** Under `%All` every check passes, so a denial needs a real principal: `Test/Wire.cls` and `Test/WireSecurityRead.cls` (a leg per list), or a browser spec on `scripts/ci-throwaway.sh` (`ocupilot-ci`, `OCUPILOT_DEMO=1`). No security-object mutation on live `ocupilot`; leave zero principals behind.

## UX & Interaction Patterns

- **One data table** on CDK virtual scroll: `name` a `code` link, identifiers in `code`, numbers tabular and right-aligned, `status` a disc plus "Yes"/"No" (a boolean outside a `status` column reads Yes/No with no disc), empty "(none)" in body type; vendor strings verbatim (`System,CSP`). Footer "<n> rows", "Max rows" and the cap notice. "Filter rows" drives the filter.
- **Loading and empty.** Skeleton on first load only. The empty state follows only a successful zero-row read, names its scope, and invites the agent only on a write-capable list; a faulted, denied or filtered-to-zero view is never empty.
- **Gating.** `aria-disabled` plus "Requires <resource>:<permission>" in rail, side bar and command box; a denied deep link shows the title and "You need <pair> to open <screen>."; a 403 is an inline alert and on-screen data stays.
- **Strings.** Each list adds one EXPERIENCE.md Fixed strings row (title, headers, empty-state lines) and `strings.ts` keys, whose `EXPERIENCE.md:<line>` comments `strings.test.mjs` checks; it requires unique values, so a label two lists share is one shared key (Name, Type, Enabled, `headerNamespaceLabel`, the empty-state second line). Non-ASCII as `\uXXXX`. Inserting a row shifts the 148 ungated citations elsewhere in `ui/src` (DW-272); repair only the `strings.ts` ones.
