# Epic 2 Context: Every area shows live instance data

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Each of the six areas shows real instance data: Web applications, Users, SSL/TLS, Task schedule, Processes, and in Logs the audit viewer, application error drill-down and a bounded messages.log endpoint. Every list is backed by one descriptor-declared read that the agent's read tool shares, and every admin-API call goes through one port. Build step 1: once the smoke script passes, the listing build can be submitted.

## Requirements & Constraints

- **Bounds.** First page within 2 s at 1,000 rows (the table is proven in the browser; the end-to-end instance read plus first render is first measurable in 2.10, DW-258). Every read is capped (default 1,000, editable, persisted per screen; no ceiling, no page-size control) and reports truncation.
- **One read, two consumers.** The tool's view is the screen's, narrowed by the context cap and stripped of secret fields. Read tools are not dispatchable until Epic 4.
- **Privilege.** A gate is a set of `(resource, permission)` pairs, all required, checked per call, never cached; a denial names the failing pair. A descriptor names the classic page it replaces, so an operator's custom resource on it still applies.
- **Reads only, by construction.** `AdminPort.TYPESUFFIXES = "GET,LIST,INFO"` is what keeps every vendor write type unreachable this epic — terminate, suspend, resume and broadcast are Stories 5.12, 7.8 and 16.6. No `rowActions`, no `primaryAction` on any Epic 2 list.
- **Navigation.** No list links out to the classic portal; an unbuilt screen has no side-bar entry. Ids use the one-segment encoder (`/csp/myapp`, `_SYSTEM` round-trip); a name-keyed entity is a `single` id, not composite.
- **Secrets and state.** No private key material in any SSL/TLS read. Disabled or expired (an `ExpirationDate` set and earlier than today on the instance clock) reads as a word, never color alone.
- **Logs.** No endpoint takes a filesystem path: a fixed source enum, directory from `$System.Util.ManagerDirectory()` per call; pages survive rotation; `LogSourcePort` runs `$System.Security.Check` first. The audit viewer never hides OcuPilot's own events, its marker filter is not a default, and its set needs `%Admin_Secure` and `%Admin_Operate`. The error log reads only through `SYS.ApplicationError`, takes its namespace from the drill level alone, and its variable table never reaches context or the model.
- **Known gaps, already filed — name them, do not re-file, do not work around per screen.** No list has the manual Refresh action (DW-260, five lists now). Every list's table frame collapses to header height, so the viewport reads `clientHeight` 0 and a real click at a row's centre lands on the footer — specs click above the fold and set `scrollTop` directly, and nothing in the shell exercises virtual recycling (DW-273). A misspelled *top-level* descriptor key installs silently (DW-271). EXPERIENCE.md citations outside `strings.ts` are ungated, now measured: 101 above `:318` resolve elsewhere (DW-272). A stopped Task Manager raises no banner (DW-270). The admin port answers 500 where a query's own privilege refusal should be a named 403, and the vendor status never reaches OcuPilot because `ClassQuery` discards what `%Execute()` returned (DW-274). Area coverage will gate all of OS management on `%Admin_Manage:USE` once 6.8 and 7.8 land (DW-275). The sort control is unasserted on the four earlier lists (DW-276, `wontfix-accepted`).

## Technical Decisions

- **AdminPort.** `OcuPilot.Port.AdminPort.Invoke` is the only caller of admin endpoints and the only file naming `%Api.Admin` (checked). Callers pass a package-relative endpoint, a type (`GET`, `LIST`, `INFO`) and `pQuery`; anything but OK plus 2xx is a `{error, reason, code}` fault. Async calls are polled inside the port (`PORT.TIMEOUT`, 30 s). The epics' REST paths name the data, not the call: 2.5's `GET /web-apps` is the `WebApp.App` LIST.
- **Read and table grammar.** `read`: `source` (`port`, `endpoint`, `type`, optional `rowGet`), `fields`, `filter`, `sort`, `paging: cap`, `table` (`columns` of `{field, labelKey, kind}`, exactly one `name` kind; `emptyAgentKey` only when a primary or row action is declared). No secret field is a column, filter or sort. No cursor paging, so 2.11 would extend the grammar (inference). Every rule is a refusal sentence held identically by `Registry.*Problem` and its `screen-mirror.mjs` twin; change both, and pin new ones in a shared corpus class as `Test/RowGetCorpus.cls`, `Test/AdminPairCorpus.cls` and `Test/BannerCorpus.cls` do.
- **A list screen is one descriptor class** directly in `Screen/Descriptor/` (the mirror reads it flat), then `node ui/tools/screen-mirror.mjs`; `ListPage` renders it, with no per-screen route, handler, tool class, page, store or `areas/` file. Five templates now — `WebAppList` and `UserList` (with `rowGet`), `SslConfigList` (plain), `TaskScheduleList` (auto-refresh plus a banner) and `ProcessList` (auto-refresh, no banner, and the first descriptor using `kind: number`) — all instance scope and `single` id. The gate does not union the area's pairs; each descriptor declares its own. Never set `navigates` on a list's area.
- **A pair set is established, not read off the endpoint (AD-29, amended twice on 2026-09-14).** An endpoint's `ResourcesOR()` is a **lower bound**: the query or class behind it may check more, and a screen declaring only `ResourcesOR()`'s resources passes its own gate and then faults inside the port. Establish the set two ways together — read the backing query's own privilege check in `irislib/`, **and** run the read as a real least-privileged principal on a throwaway, adding what the instance still refuses. `%Api.Admin.Endpoints.Process` answers `%Admin_Operate` alone while `%SYS.ProcessQuery` also demands `%Admin_Manage:USE` (or IRISSYS write), so the processes read declares three pairs. Every admin-port read additionally declares `%DB_IRISSYS:READ`, because `AdminPort.RunSequence` switches to `%SYS` for every request type and `%SYS`'s `%DB_IRISSYS` has no public permission; `ReadProblem` and `readProblem` each refuse, as their **last** check, a read that omits it — one sentence pinned by `Test/AdminPairCorpus.cls` in both engines. Never `%DB_IRISSECURITY`: IRIS refuses to grant it to a role (probed).
- **An area covers its screens.** `Registry.AreaCoverageProblem`, called from `Validate` per descriptor right after `MalformedPair`, refuses a screen declaring a pair its area does not, naming class, area and pair (`Test/AreaPair/Bad.cls` + `AreaPairRegistry` falsify it). Containment only — a surplus area pair stands. `web-applications`, `permissions`, `security`, `tasks` and now `os-management` (`%Admin_Operate:USE`, `%Admin_Manage:USE`, `%DB_IRISSYS:READ`) declare `%DB_IRISSYS:READ` beside their own resource; pair **order** matters, since `Gate.EvaluatePairs` names the first unheld pair and `failedPair` fixtures pin it, so append rather than prepend. Adding a pair to an area flips `Test/Wire.cls`'s verdict pin for any principal holding only the old set. No mirror twin: `Validate` is the roster check CI runs.
- **Banner grammar (2.8).** A descriptor may declare one `banner` — `{source: {port, endpoint, type: GET}, field, equals, messageKey, severity}`, a second port read on the same descriptor whose match raises a strip above the table. Refused at install by `Registry.BannerProblem` and its mirror `bannerProblem`, both pinned by `Test/BannerCorpus.cls`; the severity set is closed. Resolved by `Read.BannerKey` inside the screen's own read, drawn by `ListPage`, re-evaluated on a tick, never in the tool payload. **Any fault answers `""`** so the rows still list — deliberately the opposite of `rowGet`'s fault rule. Exactly one shipped descriptor declares one.
- **Key material stays out by shape.** `Read.Project` copies only `read.fields`, and `screen-mirror.test.mjs` refuses any declared field name matching `field-lists.mjs`'s `CREDENTIAL_RE` over every production descriptor — suffix-anchored, so a detail read over `PrivateKeyFile`-shaped names pins them by hand (DW-268, widened in 9.5). `context.secretFields` is for what a read does carry.
- **Fields are the live row's keys, and never a field the vendor lies about.** Probe the vendor LIST; it can differ from the GET/PUT schema and from the obvious spelling (`Namespace`, not `NameSpace`, on web apps; **`Nspace`**, not `Namespace`, on processes). Declare the vendor's spelling and carry the readable label in the string key. `Read.Project` writes `null` for a missing key, so `Test/ScreenRead`'s field-presence test over admin-LIST descriptors is the drift guard. Where the vendor's value is wrong rather than absent — the tasks LIST coerces every `Suspended` to `false` — declare the field nowhere: an absent column beats a false "No" (DW-269, routed to 4.10).
- **Execution.** `Screen.Read.Execute` asks for `maxRows` + 1, strips secret fields once, answers `{fields, rows, truncated, banner}` at `GET /api/ocupilot/screens/<toolIdentifier>/read?maxRows=`.
- **Per-row detail (AD-36).** A read may name one detail call, `read.source.rowGet`, when the LIST omits needed fields, of type `GET` (default) or `INFO`. After the cap, one call of the same endpoint per surviving row merges the declared `fields` with their JSON types; a 404 drops the row, any other row fault fails the whole read, and `truncated` still follows the LIST. `rowGet.derived` computes fields from a closed rule set — the only rule is `beforeToday`, true when a `YYYY-MM-DD` value is earlier than `+$Horolog`, false for `""`/`null`, malformed a 500 `INTERNAL`.
- **Auto-refresh is declared, not built (AD-43).** A screen sets `refreshes` and `refreshRates` (whole seconds, strictly ascending, all > 0, non-empty iff `refreshes` — `RefreshProblem` and its mirror); the shared framework owns the timer, the persisted per-screen rate, the silent re-fetch and the preservation of sort, filter, selection and scroll. Neither auto-refreshing list needed a client change beyond the mirror. A list whose rows change with no write behind them may **not** assert that the row set survives a tick — only that the state slots and the stamp do.
- **Dates.** Emitted timestamps are ISO-8601 UTC; comparisons against the instance's own calendar date use `+$Horolog`.
- **View rule, twice.** Client (screen) and server (tool) filter and sort over `Test/ReadViewCorpus.cls`: case-insensitive ASCII contains; stable one-field sort, numbers numerically, `null` last. An array's text is its members' joined by `, ` in both engines, and that text is what the cell, the filter and the sort read. A number that arrives as a JSON string compares lexicographically, so the counters' JSON type is itself asserted.
- **Classic links, once.** `Registry.ClassicLinkProblem` and `classic-links.mjs` `classicLinkProblem` are pinned against one shared corpus, `OcuPilot.Test.ClassicLinkCorpus`. `classicLinkExemption.exempt` must be a JSON boolean.
- **Client shell.** `ListPage` reads through `RefreshService.readNow()`; the store persists sort, direction, filter and max rows per screen. `applyTick` writes only rows, truncation, banner and the stamp. A refused tick is never retried. The outlet mounts no page until `NavigationService.answered()` (a failed map read counts, fail-open), so a denied deep link issues no read.
- **The command bar's sort control (2.9, shared surface on all five lists).** A menu button in the command bar's "further screen actions" slot, rendered only when the screen declares `read.sort.fields`, offering each field under its column's own `labelKey` plus the two directions, and calling the already-shipped `ScreenStore.setSort`/`setDirection` — no new persistence. Sort is **never** a clickable header: the grid keeps one Tab stop, and the header's `aria-sort` and arrow are a read-only readout. Fields and directions are two `role="group"` radio sets, and dismissal is pinned on all four paths — pointer, focus leaving trigger-and-menu **as one region**, the overlay stack's `closeTop()`, and a route change (the command bar outlives the route, so `DestroyRef` never fires on navigation). It exists because `applyTick` never writes sort, which made "sort survives a tick" structurally unfalsifiable at the browser tier.
- **Tripwires per list — each new list edits all of them.** `Test/ReadTool` pins the production tool list by content (five today, `$Order`-alphabetical); `Test/Descriptor.cls` pins every area's pair set, `navigates` and `pinBottom`; `navigation.test.mjs` pins built routes in rail order; `navigation-wire.test.mjs` and `rail-wire.spec.ts` hold two byte-identical `LIVE_PAYLOAD` copies, **neither of which goes red on its own**; `screen-mirror.test.mjs` pins the descriptor roster; `Install.Smoke` runs one live read per built list (five today), each check pinned to the screen it read, its `arealists` pending note now naming Logs alone, and `Test/Smoke.cls` re-derives its bounds from `Smoke.cls`'s own source.
- **Browser specs share one filter helper.** `ui/browser/list-spec.mjs` (no `*.browser-spec.mjs` suffix, so the suite glob skips it) exports `viewCount`, `clearFilter` and `filterToSubset`; `filterToSubset` clears first, asserts `0 < kept < total` off `aria-rowcount` (never DOM rows — the table virtualises), and that the named row survives. A leftover filter silently satisfies a cap assertion, so clear before asserting a cap.
- **Denial and demo checks run on the throwaway.** Under `%All` every check passes, so a denial needs a real principal: `Test/Wire.cls` and `Test/WireSecurityRead.cls` (a leg per list), or a browser spec on `scripts/ci-throwaway.sh` (`ocupilot-ci`, `OCUPILOT_DEMO=1`). No security-object mutation on live `ocupilot`; leave zero principals behind.

## UX & Interaction Patterns

- **One data table** on CDK virtual scroll: `name` a `code` link, identifiers in `code`, numbers tabular and right-aligned, `status` a disc plus "Yes"/"No" (a boolean outside a `status` column reads Yes/No with no disc), empty "(none)" in body type; vendor strings verbatim (`System,CSP`). Footer "<n> rows", "Max rows" and the cap notice. "Filter rows" drives the filter.
- **Loading and empty.** Skeleton on first load only. The empty state follows only a successful zero-row read, names its scope, and invites the agent only on a write-capable list; a faulted, denied or filtered-to-zero view is never empty. A list whose empty state is unreachable still declares the key — the grammar requires it.
- **Gating.** `aria-disabled` plus "Requires <resource>:<permission>" in rail, side bar and command box; a denied deep link shows the title and "You need <pair> to open <screen>."; a 403 is an inline alert and on-screen data stays.
- **Strings.** Each screen adds its EXPERIENCE.md Fixed strings row (title, headers, empty-state lines) **before** its `strings.ts` keys — `strings.test.mjs` derives a closed-world key equality from that table, so a key with no row fails the build. Its `EXPERIENCE.md:<line>` comments are re-resolved, values must be unique (a label two lists share is one shared key: Name, Type, Enabled, `headerNamespaceLabel`, the empty-state second line), and non-ASCII is `\uXXXX`. Inserting rows shifts citations elsewhere in `ui/src` (DW-272); repair only the `strings.ts` ones, and never "bump" a citation into a document that did not move.
