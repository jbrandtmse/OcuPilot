## Intent

**Problem:** The Logs area has no screen for the errors applications actually threw, and the two things that make this read unlike every other Epic 2 read are the two that a builder will get wrong by default: its privilege is a function of the *selected namespace*, which no static descriptor resource can express, and its captured detail is every local variable at every stack level plus `$ROLES` and `$USERNAME` — on IRIS for Health, potentially patient data — with no schema to classify it against.

**Approach:** Extend `LogSourcePort` with a second source, `applicationerrors`, that reads `SYS.ApplicationError`'s own four queries from `%SYS` and resolves its pair set per namespace before touching anything; serve it through four literal routes; and give the Logs area a `drill-down` screen that owns its page and store (the `AuditList` precedent), walking namespaces to dates to errors to one error's variable table. Secrecy is enforced by **which query is called**, not by a filter: the summary path calls `ErrorList`, which structurally carries no variable table, and `ErrorDetail` is reachable only from the detail route — observed by a fixture counter, not asserted.

## Boundaries & Constraints

**Always:**

- The read goes through `SYS.ApplicationError`'s `NamespaceList`, `DateList`, `ErrorList` and `ErrorDetail` **only**. No `^ERRORS` traversal of OcuPilot's own, and not `%CSP.ErrorLog` (AD-48).
- `%SYS` is entered **once per call**, by explicit save and restore, with the restore the **first** line of every `Catch` (AD-16). The target namespace travels as the query's own parameter; no slice writes `Set $NAMESPACE` to reach it.
- **Nothing inside the `%SYS` window dispatches `##class(OcuPilot.*)`** — that is the `<CLASS DOES NOT EXIST>` trap recorded at `Install/Installer.cls:1376-1392`. Faults are built after the restore.
- The gate runs **before any query executes** and is resolved **per namespace**: `%Admin_Operate:USE` plus `READ` and `WRITE` on the resource guarding that namespace's globals database (AD-48, AD-29). A namespace whose resource cannot be resolved is **refused**, never admitted with an empty pair set.
- The caller names **no namespace and no date of its own invention**: both are validated against the instance's own enumerations (`NamespaceList`, then `DateList` for that namespace) before use, and the date string is the one `DateList` emitted, byte for byte (AD-21).
- The route's `?ns=` parameter (AD-44) **never reaches this port**. The drilled namespace travels under its own parameter name, and the client issues every call on this screen with `ApiRequestInit.scope: null` (`ui/src/app/core/api.ts:69-73`, `:405-416`).
- The detail payload is **secret by default**: it never enters the descriptor's `context` field list, and the read tool carries the five AD-48 summary fields only — `errorNumber`, `time`, `errorText`, `routine`, `line`.
- Every read is bounded by a `maxRows` cap with the delivered contract's exact shape — absent means 1,000, anything else must be a whole number above zero, and there is **no ceiling** (`Screen/Read.cls:65-70`, and the epic's "default 1,000, editable, no ceiling, no page-size control") — refused rather than silently defaulted, and `truncated` reported (AD-36).
- Every failure goes through `Api.Error.Render` with a slug from the twelve-value enum and a `code` declared as a `Parameter` on `Api/Error.cls` (AD-12, AD-39). Nothing here writes to the response device.
- Anything that writes `^ERRORS` or creates a principal runs on the throwaway behind an `OnBeforeAllTests` arming guard, in `Test/LogSourceRotation.cls:41-60`'s exact shape.

**Never:**

- Never delete an application error, never write to `^ERRORS`, and never create a user, role or resource on the live `ocupilot` instance. Never `docker compose up`/`down` against it.
- No delete of any scope. AD-48's three delete scopes are Epic 5's, where a proposal, a confirm and an audit marker first exist; this story declares no `primaryAction` and no `rowActions`.
- No `read`, `table`, `criteria`, `banner` or `rowGet` on the descriptor — the declared-read pipeline is admin-port-only by two independent hard-codings and cannot serve this source (see Design Notes). The screen's tool is a **tool class of its own**, the registry's documented second source.
- No widening of `read.source.port`, no per-descriptor port seam in `Screen/Read.cls`, no change to `AreaCoverageProblem`, and no ninth area.
- No `%DB_*` pair in the descriptor's declared privileges — the per-namespace pairs live at the port, and a `%DB_<ns>` pair the `logs` area does not declare would be refused by `AreaCoverageProblem` (`Screen/Registry.cls:318-338`).
- No sub-route deeper than the one `/:id` segment `buildRoutes` emits (`ui/src/app/app.routes.ts:33-50`); drill level is store state.
- No dialog for the detail: `Dialog` is 440px fixed (`ui/src/styles/_components.scss:2428`), single-action, and one shared overlay id, none of which fits a variable table.

**Acceptance Criteria:**

- **AC1.** **Given** the application error log, **when** any level is read, **then** every value comes from `SYS.ApplicationError`'s own `NamespaceList`, `DateList`, `ErrorList` or `ErrorDetail`, and no code path in this story reads or writes `^ERRORS` or names `%CSP.ErrorLog` — pinned by a fixture whose `QueryClass()` seam counts executions and by a source-level check over the story's files.

- **AC2.** **Given** `SYS.ApplicationError` exists only in `%SYS`, **when** the port calls it, **then** `$NAMESPACE` is saved and restored explicitly, the restore is the first line of every `Catch`, the window is entered once per call and never into the target namespace, the target namespace travels as the query's own first parameter, and a refusal raised inside the window is still rendered as one envelope — because the fault object is built after the restore, not inside the window where `##class(OcuPilot.*)` does not resolve.

- **AC3.** **Given** the drill-down screen, **when** a user opens it and drills, **then** namespaces open to dates and dates to errors, each level is a table, each error shows its error text, its time and — where the instance records them — its routine and its line, and each level's empty state names its own scope (the instance, then the namespace, then the namespace and date). *(Integration AC — a real browser drilling all three levels against the throwaway.)*

- **AC4.** **Given** the namespace an error read acts on, **when** it is resolved, **then** it comes from one source only: the level the user drilled to, carried in the screen's store and sent under this endpoint's own parameter. A route `?ns=` on the same request changes nothing — asserted on an independent witness (the row identities), not on status alone — and the handler reads no `ns`.

- **AC5.** **Given** an error's captured detail, **when** the user opens it, **then** the full variable table renders on screen — every local at every stack level plus `$ROLES` and `$USERNAME` — **and** the same error's read-tool payload carries exactly the five summary fields `errorNumber`, `time`, `errorText`, `routine`, `line` and nothing else, **and** the fixture's `ErrorDetail` counter reads 0 across the namespaces, dates, list and tool paths and non-zero only on the detail path. *(Integration AC, Rule 1 — the consumer is the read tool and the browser, and the counter is the witness.)*

- **AC6.** **Given** `^ERRORS` is unmapped and lives in each namespace's own globals database, **when** the gate is evaluated, **then** the pair set is resolved per namespace at call time — `%Admin_Operate:USE` plus `READ` and `WRITE` on that namespace's globals-database resource — evaluated **before any per-namespace query executes**; a purpose-built principal lacking one of those pairs is refused **over HTTP with 403 and `detail.failedPair` naming it**, while the same principal is served 200 for a namespace whose pairs it does hold in the same session; and a namespace whose resource cannot be resolved is refused rather than admitted on an empty pair set. *(Measured with real principals on the throwaway, at the endpoint rather than at the port's own API; the "no query ran" half is pinned by the fixture's counter, which HTTP cannot observe.)*

- **AC7.** **Given** any caller, **when** a namespace, a date or an error number is supplied, **then** it is used only after being found in the instance's own enumeration for the level above it — `NamespaceList`, then `DateList`, then `ErrorList` — with a named refusal otherwise (`LOG.NAMESPACE`, `LOG.DATE`, `LOG.ENTRY`), and the date string is the one `DateList` emitted, never reformatted and never computed from the browser's clock; and every level is bounded by `maxRows` on the delivered contract — absent means 1,000, a whole number above zero is honoured with no ceiling, anything else is refused 400 `LOG.MAXROWS` rather than silently defaulted — and reports `truncated`.
