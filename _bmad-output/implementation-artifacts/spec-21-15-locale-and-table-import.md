## Intent

**Problem:** The classic Import Locale page (`%CSP.UI.Portal.NLSImport`) loads custom locales, tables and subtables from an export file into the instance, and the classic locale page (`%CSP.UI.Portal.NLS`) exports one locale with its tables to a server file it browses for; OcuPilot has no route, screen action or tool for either, so a person who wants a custom locale from another instance has to use the classic portal.

**Approach:** Two writes on Story 21.14's `LocalePort`, each reached by the Locale definitions screen and by a confirmed agent proposal (AD-53). Import is destructive: the file is a server file named by an allowed root and a relative name (AD-21's sixth case, `source`), or, from the screen only, a file on the person's computer whose text the browser sends; the port reviews the text, writes exactly that text to a temporary file whose name OcuPilot chooses, calls `Config.NLS.Locales.ImportAll` on it, and deletes it. Export reads: the port calls `Config.NLS.Locales.ExportList` for one listed locale into a temporary file OcuPilot names, then copies its text to a server file named by root and relative name (sixth case, overwriting `file`), or, from the screen only, answers it as lines the browser saves, and deletes the temporary file.

## Boundaries & Constraints

**Always:** `LocalePort` is the only product class that calls `ImportAll` or `ExportList` and the only one that writes their temporary files; it gates before any vendor call (AD-29) and switches namespace by save and restore (AD-16). No caller value is a path: the vendor receives only OcuPilot's temporary file name, never the caller's resolved path (AD-21). The import text is reviewed before the confirm (records, digest) and compared again at the write; a difference refuses with nothing imported (AD-6, AD-51). Text holding `<!DOCTYPE` is refused before any parse, OcuPilot's or the vendor's. The import key ships `false` and the import is destructive (typed-name confirm). An import that would replace the current locale or a table it loads is refused from either caller, whatever the key (Design Notes, Self-protection). Export is not destructive, its key ships `true`, and it is gated on the read pairs plus `%Admin_FileSystemAccess:USE`, as the sibling exports are. Every read is bounded (AD-36). Imported locales appear in Story 21.14's locale list after the change event (AD-14).

**Never:** No caller-named path reaches the vendor; no `.goq` legacy import (`ImportLegacy`); no Locales/Tables/Both choice (the whole file is imported, Flags 7); no export of several locales in one file, of a directory (`ExportDir`) or to `^%nls`; no Install, Copy, properties edit or Load table (21.14, 21.16). The local file's name and text, and an export's lines, never enter a tool schema, a proposal's stored arguments beyond the import's fingerprinted payload, a log line or the ledger. No user-facing string beyond those the spec gate rules. OcuPilot's own interface stays English.

## Design Notes

**Governing ADs:** AD-5, AD-6, AD-8, AD-10, AD-11, AD-13, AD-14, AD-15, AD-16, AD-21 (sixth case: import `source`, export overwriting `file`; no caller path reaches the vendor), AD-22 (import `false`, export `true`), AD-29, AD-34, AD-36, AD-39 (an export's lines reach the screen only, its fifth exception as the lookup export's), AD-44, AD-51, AD-52, AD-53, AD-56 (local values are screen values), AD-58, AD-59.

**The file mechanism.** Two sources and two destinations, as Stories 19.13 and 20.5 take them: a server file (`root` + relative `path`, both callers) and the browser (screen only, never in the schema). Both directions hand the vendor only a temporary file OcuPilot names with `%File.TempFilename("xml")` and deletes on every path: the import writes it from the reviewed text, so the vendor imports exactly the bytes the person reviewed; the export copies its text to the resolved file or answers it as lines. So no caller value reaches the vendor as a path, and OcuPilot, not the vendor, decides that an existing export file is replaced. The vendor offers no stream form of `ImportAll` or `ExportList`. A browser export is capped at `MAXIMPORTCHARACTERS` so that what the browser saves the browser can import again; by the Code Map's estimate six shipped locales (`zdsw`, `zduw`, `jpnw`, `jpuw`, `jpww`, `chsw`) pass it and export to a server file only (inference until Task 0 (h)).

**Proposed, for the spec gate (AD amendments; covered by owner answer U-58):**

- **AD-51 named entry (needed; one entry for both):** "Story 21.15's case: `LocalePort`, which hands `Config.NLS.Locales.ImportAll` and `ExportList` only a temporary file OcuPilot names and deletes. The import's file is written from the reviewed text, read from the import tool's declared `root` and `path` resolved through `PathPort` as a `source` or from the screen's local text; its flags are a constant; it answers the fresh read through a port-composed `IMPORTFILE` type and refuses an import whose text no longer yields the reviewed digest. The export's locale is its target alone; the file's text is copied to the export tool's declared `root` and `path`, resolved through `PathPort` as an overwriting `file` whose overwrite is a constant, or answered to the screen as lines; it answers its fresh read through a port-composed `EXPORTLOCALE` type."
- **AD-21 record (needed, by the precedent of every sixth-case consumer):** "Story 21.15's consumers of the sixth case: the locale export is an overwriting `file` consumer whose overwrite is a constant, and it refuses a name whose directory does not exist; the locale import's file is a `source`; local text is a screen value. The vendor receives only a temporary file OcuPilot names."
- **AD-53 named gap (only if Task 0 (e) finds no vendor audit event):** the locale import, as Story 19.13's.

**Self-protection: refused, and destructive with its key off.** An import replaces any custom record of the same name without asking, so it is destructive and ships `false`. A file whose kept custom records would replace the current locale or a table it loads is refused from either caller, key on or off: every process of the instance, OcuPilot's included, takes its tables and formats from the current locale at the next start or reload, and 21.14 already refuses deleting it, which a replacement amounts to. On a stock instance the current locale is a shipped one, so this bites only when a custom locale is current, or if Task 0 (b) shows the vendor writes shipped records; then the port refuses any shipped record `LOCALE.IMPORT.SYSTEM`, consistent with 21.14 changing only custom NLS records (stricter than the classic page). An export changes no NLS record (Task 0 (h)), and PathPort's own refusals keep its file out of the manager and served directories.

**Decided in-stage:** XML only (`.goq` is the pre-IRIS format, refused by extension for a local file and by `SHAPE` otherwise). The `<!DOCTYPE` refusal keeps both parses from resolving an external entity, which would read a server file by content (AD-21's intent). The import preview is OcuPilot's own `%XML.TextReader` read of element names, since `ImportAll` has no count-only flag. Import and Export are actions on 21.14's Locale definitions screen, not a new screen. Export names one locale, as the classic page does; any listed locale, shipped or custom, current or not, may be exported. The classic page's file Browse is OcuPilot's allowed-directory picker in the shared export dialog (DW-2606).
