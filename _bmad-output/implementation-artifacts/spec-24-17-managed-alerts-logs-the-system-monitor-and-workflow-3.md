## Intent

**Problem:** OcuPilot has nothing for the classic Workflow Users page (`EnsPortal.WFUsers`), so a namespace's workflow users cannot be listed, added, edited or removed, and nothing round-trips over `EnsLib.Workflow.UserDefinition`.

**Approach:** Batch 3a of the story (Design Notes, Batch split: Batch 1's item 3 split in two; roles and membership are Batch 3b, `-4.md`). **Workflow users**, a list through `InteropPort` with three writes, **New workflow user**, **Edit** and **Remove**, each one operation reached by the screen and by the agent, built on Story 24.15's schedule family. "Round-trips" means: a user added or edited from either caller reads back from `EnsLib.Workflow.UserDefinition` exactly as sent, and a removed one is gone with its role memberships.

## Boundaries & Constraints

**Always:**

- **One port (AD-62).** `InteropPort` gains `WorkflowUsers`: `LIST`; `WORKFLOWUSER`, the one-user fresh read (with `ACTIONKEY`, refusing what that write would be refused); `WORKFLOWUSERCHOICES`, the names a new workflow user may take; and the writes `ADDWORKFLOWUSER`, `SETWORKFLOWUSER`, `REMOVEWORKFLOWUSER`. Every type name is unique port-wide (`IsAnyWrite` reads a type port-wide). Reads use `%ExecDirectNoPriv` after the gate. Switched by save and restore; no `OcuPilot.*` call while switched, logging included; a fault is logged after the restore.
- **Rows.** List `{Name, FullName, IsActive, Roles, Namespace}`, as the classic `EnsLib.Workflow.Engine:ListUsers` (`Roles` the user's membership count), by name ascending, capped by `WORKFLOWUSERSMAX`, truncation reported (AD-36). `WORKFLOWUSER` the same fields. `WORKFLOWUSERCHOICES` `{Name, Namespace}`: the instance's users as the classic Name selector lists them (`Ens.ContextSearch.ListEnsembleUsers`, which leaves out `_Ensemble`, `_PUBLIC`, `_SYSTEM`, `CSPSystem` and `UnknownUser`), capped by `WORKFLOWUSERCHOICESMAX`, truncation reported.
- **Gate (AD-29, AD-8), before any vendor call or value judged; never cached.** Reads: `%Ens_Portal:USE`, `%Ens_WorkflowConfig:READ` (the classic `RESOURCE`, `WFUsers.cls:10`), then `Admit`. Writes and `WORKFLOWUSERCHOICES`: plus `%Ens_WorkflowConfig:WRITE` (`EDITRESOURCE`, `WFUsers.cls:13`, demanded for `SaveItem` and `DeleteID` by `GetHyperEventResources`) and WRITE on the namespace's globals database. Plus any pair Task 0 (b) or (c) measures.
- **Write refusals by name, after the gate, before any vendor call**, in this order: a namespace under source control, 409 `INTEROP.WORKFLOW.SOURCECONTROL` (every write; `SourceControlled`, as the partner and schedule families); an add whose name is not one `WORKFLOWUSERCHOICES` answers, spelled exactly as it answers it, 422 `INTEROP.WORKFLOW.USERNAME`; an add whose name the namespace holds in any letter case, 409 `INTEROP.WORKFLOW.USERTAKEN`; an edit or remove of a name not held exactly, 404; a `FullName` over 128 characters (the vendor's `MAXLEN`) or holding a control character, 422 `INTEROP.WORKFLOW.FULLNAME`; a field of the wrong type, `PORT.FIELD.SHAPE`.
- **The writes run as the classic `SaveItem` and `DeleteID` (`WFUsers.cls`)**, in the proposal's namespace: an add `%New` and `%Save` (`Name`, `FullName`, `IsActive`, absent `IsActive` the vendor's 1); an edit `%OpenId(name, 4)` and `%Save` of only the fields that differ (none differing calls nothing, as the partner family), the reference dropped in that namespace; a remove `%DeleteId`. A user another process holds locked is 503. No rename: the name is the target (the partner family's rule). A single operation, as the purge: a vendor error status answers 500 `INTERNAL`, never 200, and its audit row reads `completed` false.
- **The tools (AD-3, AD-6, AD-10, AD-14, AD-22, AD-34, AD-51 to AD-55, AD-58, AD-59).** `interop.workflowusers.add` (a create, AD-54; read-back through the update's read), `interop.workflowusers.update` (`SCREENVALUES`/`SCREENOPTIONAL` `edit=FullName:IsActive`, `SCREENEMPTY` `edit=FullName`), `interop.workflowusers.remove` (`DESTRUCTIVE`, typed name, `FINGERPRINTSUBJECT` `Name,FullName,IsActive,Roles,Namespace`, so a membership added after the review closes it as moved). `WRITERESOURCE` `%Ens_WorkflowConfig`, `WRITEPERMISSION` `WRITE`, `CLASSICPAGES` `EnsPortal.WFUsers`. Keys: add and update `true`, remove `false`. The New dialog saves through `POST /interop/workflow-users` (AD-55, sibling `ScheduleSave`). Classified in `ConfirmNamespaceRoster` and `DraftRegistry`. Each script form shape-checks every value, renders no draft for a bad one, and renders the switch, each refusal as a one-line guard and the vendor call, running none. A screen action mints nothing and is not gated by read-only or the kill switch.
- **Namespace at confirm (AD-52).** Every stored proposal carries `Namespace`; every confirm-time judgment (the fresh read, the source-control test, the choices, the taken test, the vendor call) runs there, whichever namespace the confirm is sent from.
- **Audit (AD-15).** The agent's marker on the agent's write; OcuPilot's own `ConfigChange` from either caller through `AuditRuntime`, after the restore, naming the namespace, the user's name, the fields changed and `completed`, never a field's value.
- **Bounds.** `WORKFLOWUSERSMAX` and `WORKFLOWUSERCHOICESMAX` (provisional 2,000; Task 0 (e) sets each), boundary-tested at the cap and one over through a seam.
- **README.** The switched-off count rises by one and the off list gains this batch's clause (veto item 1), in the same commit as the key.
- **Rosters.** `interop-workflow-user` after feature's last entries in `TYPES` and `COVEREDTYPES`; its `Prohibited.cls` terms appended; no earlier type reaches a different arm (a pinning test). Every pinned roster is in the Code Map.

**Never:**

- `EnsLib.Workflow.UserDefinition.OnSubmit` or any SQL `DELETE`/`UPDATE` of OcuPilot's own on the workflow tables; any `EnsPortal.*` call in product code; a rename by delete and create; `$SYSTEM.SQL.Security.UserExists` or `$$ParseUsername^%SYS.SECURITY` as the name rule (the choices read is the one rule).
- A full name in a log line or an audit row; a vendor status text in a log (`LogFault` gets a fixed message and the codes).
- `Set $ROLES`, `AddRoles`, or a `New $ROLES` (a vendor call that changes `$ROLES` is a HALT).
- Workflow roles and membership (Batch 3b), tasks and the worklist (Batch 4); the README's Interoperability paragraph (Batch 5); a spine edit.
- `src/OcuPilot/Api/Error.cls` (frozen; codes go in `InteropError.cls`); `ui/angular.json`; `ui/vitest-base.config.mjs`; `scripts/ci-throwaway.sh` beyond add-only `# classes:` lines, never its bring-up retry block; `Prohibited.cls` beyond appended terms and new arms; `shell/screen-action-handler.ts`, `shell/warning-dialog.ts`, `shell/screen-action-dialogs.ts` beyond add-only map entries.
