## Intent

**Problem:** OcuPilot has no way to read the log the instance actually writes. `messages.log` is 3.2 MB on the development instance and rotates at 5 MB, so any endpoint that serves it whole is a hundred-megabyte response waiting to happen — and a paging viewer that holds a byte offset across a rotation would silently serve from a stale position in a file that no longer exists.

**Approach:** Add `OcuPilot.Port.LogSourcePort` — the project's second port, and the first read outside `AdminPort` — plus one literal REST route that serves `messages.log` in bounded byte pages of whole lines. The port declares its own resource and evaluates it before touching the filesystem, resolves the manager directory on every call, and hands each page an identity token derived from the file's first bytes so the next call can tell "continue here" from "this is a different file now". No screen: Epic 6 builds the viewer, Story 2.12 reads the application error log through this same port.

## Boundaries & Constraints

**Always:**

- The route is **literal** — `GET /api/ocupilot/logs/messages`. The router wrapper binds the source key; no caller supplies a path, a name, or any part of one (AD-21).
- The directory comes from `$System.Util.ManagerDirectory()` **on every call**. Nothing caches it — not a class variable, not a process-private global, not a `%request` attribute.
- The gate runs **before any file access**: the port evaluates its declared `(resource, permission)` pair set and refuses, and only then resolves, opens or reads (AD-29).
- Every response is bounded by a hard server-side byte cap. There is no parameter that raises it and none that disables it.
- Every page is whole lines. A window that starts mid-line discards to the next LF; a window that stops mid-line drops the partial tail unless it reached EOF.
- Every failure goes through `OcuPilot.Api.Error.Render` with a slug from the twelve-value enum and a code declared as a `Parameter` on `Api/Error.cls` (AD-12, AD-39). Nothing in this story writes to the response device.
- Tests that create, append to, rotate or delete a log file use a **test-owned scratch file** under `<ManagerDirectory>ocupilotlogprobe/`, removed in `OnAfterAllTests` — except on the throwaway, where the test owns the whole instance and may rotate its own `messages.log`.
- Tests that create a security principal, or that rotate a real `messages.log`, run on the throwaway (`scripts/ci-throwaway.sh`, `ocupilot-ci`) and clean up after themselves.

**Never:**

- Never write to, rotate, truncate, append to or delete the **live** instance's `messages.log`, and never change its configuration. The live read is read-only, always. The throwaway is the only place a real rotation happens.
- No `%SYS` namespace switch. Nothing this endpoint needs lives there (probed: `ManagerDirectory`, `%File`, `%Stream.FileBinary` and `$System.Security.Check` all answer from `HSCUSTOM` unswitched).
- No screen, descriptor, area edit, `strings.ts` key, EXPERIENCE.md row, or client file. Epic 6's viewer adds those; `strings.test.mjs` is a closed-world equality and a key without a row is red.
- No `%DB_IRISSYS:READ` in this port's pair set — see Design Notes for why the admin-port rule does not carry over.
- No `%Api.Admin.*` reference (containment, `check_admin_api_containment`), no `New $ROLES`, no escalation, no `JOB`.
- Whether anything OcuPilot itself writes to `messages.log` carries credential material is **Story 3.2's** test, where a provider first exists to fail. This story neither asserts it nor relies on it.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| First page | `GET /logs/messages` with no `offset`, holder of `%Admin_Operate:USE` | 200 `{source, lines, offset, identity, size, restarted:false, truncated}` — the **last** `maxBytes` of the file, starting on a whole line | No error expected |
| Continuation | Second call with the first page's `offset` and `identity`, file unchanged | 200, `restarted:false`, the next window; its first line is not the previous page's first line | No error expected |
| Rotation | Held `identity` no longer matches the file's current first bytes — observed over HTTP on the throwaway across a **real** IRIS rotation | 200, `restarted:true`, the page served from byte 1 of the current file | No error expected — a restart is an outcome, never a fault |
| Offset past the end | Held `offset` greater than `size + 1`, identity irrelevant | 200, `restarted:true`, from byte 1 | An independent condition from the identity check; either alone restarts |
| Empty file | `messages.log` exists, 0 bytes | 200, `lines: []`, `offset: 1`, `restarted:false` — an empty page, not a refusal | No error expected |
| Absent source (DW-19) | `%File.Exists` false at the resolved path | 404 `not_found` / `LOG.ABSENT` — a named refusal, **distinct** from the empty-file row above | One envelope; the resolved path is never echoed |
| Unreadable source (DW-19) | The file exists but `LinkToFile` fails | 503 `unavailable` / `LOG.UNREADABLE` | One envelope; raw status to `Fault.LogRaw` only |
| Directory moved (DW-19) | `$System.Util.ManagerDirectory()` answers differently between two calls | The second call reads the new directory; a held offset whose identity no longer matches restarts | Covered by the restart row, not by a fault |
| Over-cap window | `maxBytes` above the cap, zero, negative or non-numeric | 400 `bad_request` / `LOG.MAXBYTES` — refused, never clamped and served | Mirrors `READ.MAXROWS`'s refusal |
| Half a cursor | `offset` without `identity`, or `identity` without `offset` | 400 `bad_request` / `LOG.OFFSET` | Refused before the file is opened |
| Denial (DW-278) | Principal holds `%Admin_Secure:USE` but not `%Admin_Operate:USE` — passes the router's admin gate | 403 `forbidden` / `AUTH.NOPRIVILEGE`, `detail.failedPair` = `%Admin_Operate:USE`; **no file is opened** | The port's own gate, not the router's |
| Sufficient privilege (DW-278) | Principal holds `%Admin_Operate:USE` and **neither** `%Admin_Secure:USE` **nor** `%DB_IRISSYS:READ` | 200 with lines — that pair alone is the whole requirement for this source | This is the measurement DW-278's decision rests on |
| Unknown source | `LogSourcePort.Page("nosuch", …)` at the port's own API | 404 `not_found` / `LOG.SOURCE`, refused before the gate and before any file access | Not reachable over the wire; the route binds the key |

**Acceptance Criteria:**

- **AC1.** **Given** the endpoint and a file larger than the cap, **when** a page is requested with any combination of parameters a caller can send, **then** the bytes served never exceed the cap, a `maxBytes` above it is refused 400 `LOG.MAXBYTES` rather than clamped and served, and no parameter exists that raises or disables the cap. *(Integration AC — measured over the wire against the live 3 MB `messages.log`.)*

- **AC2.** **Given** any request to this endpoint, **when** it is parsed, **then** it accepts no filesystem path, name or fragment of one from the caller — the source is bound by the route, validated against the port's fixed enum — **and** the directory comes from `$System.Util.ManagerDirectory()` resolved on that call, with nothing carried over from a previous one.

- **AC3.** **Given** a viewer holding a byte offset and its identity token across a **real** rotation — the throwaway's own `messages.log` rotated by IRIS, observed over HTTP — **when** it calls again, **then** the endpoint answers `restarted: true` and serves from byte 1 of the current file rather than from the stale position — **and** an offset past the current end restarts on its own, independently of whether the identity matched.

- **AC4.** **Given** `LogSourcePort` serving this source, **when** `Page` runs, **then** it evaluates its declared pair set **before** resolving, opening or reading any file; a principal holding `%Admin_Secure:USE` but not `%Admin_Operate:USE` — which the router's own admin gate admits — is refused 403 with `%Admin_Operate:USE` named as the failing pair and no file opened; a principal holding `%Admin_Operate:USE` and **neither** `%Admin_Secure:USE` **nor** `%DB_IRISSYS:READ` is served; and a source whose declared pair set is empty is refused rather than admitted. *(DW-278: the second leg is the measurement that establishes `%Admin_Secure:USE` is surplus to this source — see Design Notes for the recommendation it supports.)*

- **AC5.** **Given** a consumer reading over HTTP, **when** it takes a bounded first page and then calls again with that page's returned `offset` and `identity`, **then** the second page continues where the first stopped — its first line differs from the first page's first line, and its returned offset equals the first's plus the bytes served — with both pages asserted non-empty before the comparison. *(Integration AC, Rule 1 — a real HTTP request against a real instance, not a fixture.)*

- **AC6.** **Given** the source is absent, unreadable, or the manager directory answered differently between two calls, **when** a page is requested, **then** the endpoint returns a **named** refusal — 404 `LOG.ABSENT`, 503 `LOG.UNREADABLE`, or a clean restart respectively — and an existing but empty file returns 200 with zero lines, so a missing log is never presented as a log with nothing in it. *(DW-19.)*

**Why the route is literal.** `check_handler_wire_tests`' `LITERAL_ROUTE_RE` (`scripts/check-objectscript.py:1044`) excludes `:`, so a `:param` route is keyed by its dispatch class name and is already covered by any test naming `OcuPilot.Api.Router` — `/screens/:screen/read` rides on `Test/Namespaces.cls:180` today. **Why no `%DB_IRISSYS:READ`.** Every admin-port read declares it because `AdminPort` switches to `%SYS` for every request type and both engines refuse, as their last check, a read that omits it. Neither half is true here: reading a file off disk consults no database resource, and nothing on this path enters `%SYS` (probed on `ocupilot-iris` from `HSCUSTOM`, unswitched — `$System.Util.ManagerDirectory()` answers `/durable/iris/mgr/`, `%File.Exists`/`GetFileSize`, `%Stream.FileBinary` `MoveTo`/`Read`/`Size` and `$System.Security.Check` all succeed). The rule for a `LogSourcePort` file read is therefore: **the pair set is exactly what the source itself requires, and for `messages` that is `%Admin_Operate:USE` alone.** AC4's positive leg is what establishes this rather than asserting it — a principal with that pair and neither of the other two is served.

**Which resource, and how the classic portal actually requires it.** The classic messages.log page is `%cspapp.op.utilsysconsolelog`, routed from `/csp/sys/op/UtilSysConsoleLog.csp` (`irislib/%CSP/UI/Portal/Application.cls:466`). It is `[Hidden]`, so it is absent from `irislib/` and was read from the instance; its `SECURITYRESOURCE` parameter is **empty**, and `%CSP.Util.AutoPage` declares no `RESOURCE` at all. The requirement lives on the **web application**: `/csp/sys/op` carries `resource: %Admin_Operate` (`iris_webapp_get` on `ocupilot-iris`). A second, independent witness in the same application declares it explicitly — `irislib/%CSP/UI/Portal/ViewLog.cls:20`, `Parameter RESOURCE = "%Admin_Operate"`. So the AC's answer is right and its mechanism needs stating: there is no page-level parameter to inherit, and OcuPilot must assert `%Admin_Operate` itself. A third layer, `%SYS.Portal.Resources`' per-page custom-resource override, is empty on this instance (`COUNT=0`) and is the screen-descriptor concern AD-44 already covers in Epic 6, not this endpoint's.

**What file identity can actually be observed on this build.** Native ObjectScript exposes **no inode, no `st_dev`, and no true birth time**. `%Library.File.GetFileDateCreated` looks like a rotation detector and is not: on Linux it returns ctime, identical to `GetFileDateModified` and changing on every append (`irislib/%Library/File.cls:726-735` says so; probed, both answered `67828,13406.682018392` while `stat` reported a birth time a day earlier). `$zu(140,*)`'s complete surface (`irislib/%occFile.inc`, subfunctions 1–20) has no file-id entry point. Embedded Python reaches `os.stat().st_ino`, but a `[Language = python]` method in a shipped class is a latent install failure on any instance without embedded Python, so it is unavailable in practice. What **is** observable, from `HSCUSTOM`, cheaply: **size** and **the first N bytes** (a 64 KB tail read measured 1.7 ms; a 512-byte prefix read is cheaper still). Rotation on this build is **rename-and-create, not truncate-in-place** — six generations in the manager directory, distinct inodes, named `messages.old_<YYYYMMDD>` with `_1` for a second rotation the same day, and each file's first line carries the previous file's last-write time to the millisecond (`09/14/26-10:21:18:559`, matching `messages.old_20260914`'s mtime exactly). A first-bytes fingerprint therefore distinguishes generations reliably, and the restart target is byte 1 of the new file — which is exactly where the old one left off, so a forward-paging reader loses nothing. Two independent restart conditions are implemented and pinned separately, because either alone could pass for the other's reason: identity mismatch, and `offset > size + 1`.
