## Intent

**Problem:** OcuPilot has nothing for the classic Workflow Tasks page (`EnsPortal.WFTasklist`), its Assign or Reassign Task dialog (`EnsPortal.Dialog.WorkflowTaskAssign`) or the Workflow Worklist page (`EnsPortal.WFWorklist`), so a namespace's workflow tasks and worklist cannot be listed and a task cannot be assigned, unassigned or canceled, and nothing round-trips over `EnsLib.Workflow.TaskResponse` and `EnsLib.Workflow.Worklist` through `EnsLib.Workflow.Engine`.

**Approach:** Batch 4, after Batches 3a (`-3.md`) and 3b (`-4.md`), whose workflow port family, tool base, case, fixture and seam it extends. **Workflow tasks**, a list with two writes, **Assign** (to a user, or to Unassigned, with an optional priority) and **Cancel task**, each one operation reached by the screen and by the agent, and **Workflow worklist**, a read-only list. "Round-trips" means: an assignment from either caller reads back from `TaskResponse` with the user and priority sent and the worklist the vendor leaves, and a canceled task reads `Cancelled` and complete, gone from every worklist, with its response delivered to the waiting business process.

## Boundaries & Constraints

**Always:**

- **One port (AD-62).** `InteropPort` gains `WorkflowTasks` (`LIST`; `WORKFLOWTASK`, the fresh read by `TaskId` with `ACTIONKEY`, refusing what that write would be refused; writes `ASSIGNWORKFLOWTASK`, `CANCELWORKFLOWTASK`) and `WorkflowWorklist` (`LIST`). Type names are unique port-wide. Reads use `%ExecDirectNoPriv` after the gate. Switched by save and restore; no `OcuPilot.*` call while switched, logging included; a fault is logged after the restore. Batch 3a's rules hold unless named here.
- **Rows.** Tasks `{TaskId, RoleName, IsComplete, Status, Priority, Source, AssignedTo, Subject, TimeCreated, TimeCompleted, Duration, Namespace}` as the classic `Engine:Tasklist`, `TaskId` descending. Worklist `{TaskId, UserName, RoleName, Priority, TimeCreated, Age, AssignedTo, Subject, Namespace}` as `Engine:Worklist`, newest first. Each capped (`WORKFLOWTASKSMAX`, `WORKFLOWWORKLISTMAX`), truncation reported (AD-36). `Status` is the vendor's own word, shown as data.
- **Gate (AD-29, AD-8), before any vendor call or value judged; never cached.** Reads: `%Ens_Portal:USE`, then `Admit` (READ on the namespace's globals database): both classic pages declare no `RESOURCE` and admit exactly that (`EnsPortal.Application.CheckPrivileges`, `Application.cls:232-245`, from `standardPage.cls:440-448`). Writes: plus `%Ens_WorkflowConfig:WRITE` (the Assign dialog's `RESOURCE`, `WorkflowTaskAssign.cls:10`) and WRITE on the namespace's globals database, plus any pair Task 0 (b) measures. If Task 0 (b) finds a classic query refused (`#5580`), the list takes 3a's ruled SQL SELECT check (3a V2), on the list reads only.
- **Write refusals by name, after the gate, before any vendor call**, in this order: a task not held, 404; a task already complete, 409 `INTEROP.WORKFLOW.TASKCOMPLETE`; an assign whose `User` is neither `""` nor an active workflow user of the namespace held exactly, 422 `.TASKUSER`; a `Priority` that is not a whole number from 1 to 5, 422 `.TASKPRIORITY`; an assign whose user and priority equal the task's, 409 `.TASKUNCHANGED`; a cancel while the namespace runs no production, 409 `INTEROP.PRODUCTION.NOTRUNNING` (reused); a cancel whose response cannot be delivered (the task's `ResponseToken` names a production other than the running one, its request header is gone, or that header has no return queue), 409 `.TASKSENDER`. A task another process holds locked is 503.
- **The writes run as the classic `SaveData` (`WorkflowTaskAssign.cls:98-130`)**, in the proposal's namespace, on `TaskResponse.%OpenId(id, 4)`, the reference dropped in that namespace: `Priority` sets `%Priority` when sent and different; `User` `""` calls `Engine.UnassignTask` then `Engine.SendTaskToAll`; a user calls `Engine.AssignTask`; `User` absent keeps the current assignment (assigned: `AssignTask` to the same user; unassigned: the unassign path). A cancel calls `Engine.CompleteTask(task)` with no action. No transaction. A single operation, as the purge: a vendor error status answers 500 `INTERNAL`, never 200, even after part of it was saved (an unassign whose `SendTaskToAll` fails, a cancel whose delivery fails after the vendor deleted the worklist), and its audit row reads `completed` false.
- **The tools (AD-3, AD-6, AD-10, AD-14, AD-22, AD-34, AD-51, AD-53, AD-58, AD-59).** `interop.workflowtasks.assign`: action-style, `DRYRUN`, not destructive, key `true`; screen action `assign`, `SCREENVALUES`/`SCREENOPTIONAL` `assign=User:Priority`, `SCREENEMPTY` `assign=User`; `READBACKFIELDS` `User,Priority`; `Consequence` answers `TASKUNASSIGN` for `User` `""`, `TASKASSIGN` otherwise. `interop.workflowtasks.cancel`: `DESTRUCTIVE`, key `false`, the screen's Cancel task types the task's ID; `PRECONDITIONCODES` naming `NOTRUNNING`, `TASKSENDER`, `TASKCOMPLETE`. Both: `FINGERPRINTSUBJECT` `TaskId,Status,AssignedTo,Priority,IsComplete,Namespace`, so any change after the review closes the proposal as moved; `WRITERESOURCE` `%Ens_WorkflowConfig`, `WRITEPERMISSION` `WRITE`, `CLASSICPAGES` `EnsPortal.Dialog.WorkflowTaskAssign`. Classified in `ConfirmNamespaceRoster` and `DraftRegistry`. Each script form shape-checks every value, renders no draft for a bad one, and renders the switch, each refusal as a one-line guard and the vendor calls, running none. A screen action mints nothing and is not gated by read-only or the kill switch.
- **Namespace at confirm (AD-52).** Every stored proposal carries `Namespace`; every confirm-time judgment (the fresh read, the user test, the production and sender tests, the vendor call) runs there, whichever namespace the confirm is sent from.
- **Audit (AD-15).** The agent's marker on the agent's write; OcuPilot's own `ConfigChange` from either caller through `AuditRuntime`, after the restore, naming the namespace, the task id, for an assign the new `AssignedTo` and `Priority`, and `completed`; never a subject, message or form value.
- **Bounds.** `WORKFLOWTASKSMAX` and `WORKFLOWWORKLISTMAX` (provisional 10,000, the classic tables' `maxRows`, `WFTasklist.cls:32`, `WFWorklist.cls:31`; Task 0 (e) sets each), boundary-tested at the cap and one over through 3a's cap seam.
