# Epic 1 Context: Install once, sign in, and reach the six areas

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

An operator clones the repository, runs one command, and reaches a working OcuPilot: installed into a running IRIS instance, signed in with no form when the browser already holds an instance login, navigable across the six portal areas, showing only the screens their IRIS privileges allow, with any classic portal page OcuPilot has not rebuilt one click away. This is build step 0. The workspace pins, the response envelope, the installer, the screen descriptor mechanism, the shell chrome and the smoke script are built once here; every later epic extends them rather than replacing them.

**Stories 1.1, 1.2 and 1.3 are done — this is neither greenfield, nor unstyled, nor uninstalled.** Under `src/OcuPilot/` there is the one success writer (`Api.Response`), the one error writer (`Api.Error`, carrying a `LogError` seam), the `%CSP.REST` router with its three ordering invariants, its authenticate-and-resolve-once `OnPreDispatch` and its overridden framework 404/405 (`Api.Router`), the harvested request-body/namespace/validation helpers (`Kernel.Utils`), the single entity-id codec (`Kernel.EntityId`), the structured logger (`Kernel.Audit.Log`, with a `WriteConsole` seam), the installer (`Install.Installer`) with OcuPilot's protected-storage base and install-run record (`Kernel.State.Base`, `Kernel.State.Stamp`), and the `Test.*` helpers and suites — plus `scripts/check-objectscript.py`, a commit-blocking mechanical gate over naming, class-name length, package placement, the rename checklist and the write-discipline rule. Under `ui/` there is the color token layer, the Material 3 wiring through `mat.theme()` to the `--mat-sys-*` custom properties, typography and metrics, five vendored font faces, the canonical 104-key string source at `ui/src/app/core/strings.ts`, and two build-failing linters (`ui/tools/client-lint.mjs`, `ui/tools/design-tokens.mjs`) wired into `prebuild`, with `client-lint` also running in `.githooks/pre-commit`. Extend all of these; never write a second one of any of them, and never add a field to the envelope.

## Requirements & Constraints

- **One command, first time.** A clean clone plus one compose command yields a running instance with OcuPilot installed, the default account's password unexpired, auditing enabled with OcuPilot's event types registered, and the app reachable at the published port. The install namespace is chosen in installer code, not in a manifest (`HSCUSTOM` when present, `USER` otherwise — already implemented).
- **Install runs at container start, not image build, and is idempotent.** Upgrade *is* install again, so it must be fast, guard-then-act throughout, and safe against a populated instance: it migrates stored state forward on start, fails loudly rather than serving partial state, and refuses when the stored schema version is newer than the deployed code. No traffic is served until install completes or fails.
- **OcuPilot's own records must be unreachable to a database-rights holder.** The acceptance test is concrete: a user holding `%DB_<install-namespace>:RW` plus `%Admin_Operate`, but not OcuPilot's administrative resource, can read and write neither an OcuPilot table (through SQL) nor an OcuPilot global (directly). Story 1.3 proved this for both.
- **Two web applications, and the split is load-bearing.** An unauthenticated static shell with a non-root base href and a deep-link fallback; and a password-authenticated API with JWT enabled, no server session, joined to the vendor's management-portal group, carrying no application or matching roles. Install-time tests assert those settings rather than leaving them to inspection.
- **Sign-in is silent-first.** A silent probe precedes any form; the form appears only on refusal, with the requested route preserved. Only a Bearer header from per-tab storage authorizes a data call — never a cookie, never persistent storage, never posted into a frame. Refresh carries its token in the body and is a background concern of the API service. Sign-out sends both the Bearer and the cookie, so the browser-level login actually ends.
- **The shell verifies the instance before rendering.** One call confirms the admin API's pinned version and reads the instance identity. A version mismatch and "no administrative privileges" are two distinct blocking notices that must never dress as each other.
- **Nothing a user cannot open is hidden**, and no read returns an unbounded collection — every read is capped and reports whether it truncated.
- Contest floor: an explicitly pinned image tag, no CDN reachable at runtime with every library vendored, and no HealthShare-only dependency.
- **How work here is verified today.** Two test tiers exist and no more. `%UnitTest` classes under `src/OcuPilot/Test/` run on the live IRIS instance (**60/60** green as of this compile); node `--test` files under `ui/tools/` run through `npm test` (**88/88**). **There is no Angular component test runner** — `ng test` has no architect target, deliberately, and standing one up is a later story's work, not a prerequisite you may assume. **There is no CI**: `.github/` does not exist, and Story 1.17 is where it comes from. Until then, "fails the build" means `npm run build` (the `prebuild` linters) for client work, and the check scripts plus the IRIS test run for server work. **The `%UnitTest.Result` global — read through the documented SQL probe — is ground truth; the MCP test-runner envelope truncates and is not.**
- **A test-validity trap that already bit once.** The `%UnitTest` suite authenticates as `_SYSTEM`, which holds `%All`, and `%All` bypasses resource checks outright. A privilege test written the obvious way therefore passes whether or not the privilege logic exists — Story 1.3's review found AD-9's escalation entirely unpinned for exactly this reason, and the fix was a test asserting the *contrast* (a purpose-built denied identity refused directly, reaching the same data through the escalating methods). **Any later story testing a denial must use a purpose-built role and assert the contrast**, never `_SYSTEM` and never `%Operator`.
- **A known operational hazard.** Repeated Install/Uninstall cycling makes `SYS.Database.DeleteDatabase` take 20–40 minutes on this container instead of about a second — observed three times in one session, roughly 2200 s each, cleared by a container restart, never on a freshly restarted container's first few cycles. The tests stayed correct and no `<PROTECT>` was required to explain it. Story 1.17's smoke script and any CI timeouts must assume it; a teardown step that hard-fails on removal latency would be fragile for no gain.
- **Eleven stories carry `- DW-n:` acceptance bullets routed from the deferred-work ledger** (1.3, 1.4, 1.5, 1.6, 1.7, 1.9, 1.10, 1.11, 1.13, 1.16, 1.17). Each is binding: the owning story must either address it or decline it with a written reason. Read the ones on your story from the epics file; they are not restated here.

## Technical Decisions

### What Story 1.3 delivered, and what it deliberately left

- **Protection is on the data, never on the code (AD-9).** OcuPilot's **globals — and only its globals —** live in a dedicated database guarded by a dedicated resource that no ordinary role holds; the **code stays in the install namespace's normal database**, because in IRIS database READ *is* routine-execution permission. Install also creates OcuPilot's administrative resource and a role granting it.
- **The live container now permanently holds** database `OCUPILOT` at `/durable/iris/mgr/ocupilot/`, guarding resource `%DB_OCUPILOT`, administrative resource and role `OcuPilotAdmin`, privileged routine application `OcuPilotState` bound to `Kernel.State.Base` in `HSCUSTOM`, an `OcuPilot*` global mapping, and the registered-and-enabled audit event `OcuPilot/Security/RoleGranted`. So the local instance is **not** a fresh-install rehearsal; it exercises the upgrade-onto-existing-state path.
- **`Kernel.State.Base` is the tree's one escalation point.** It obtains the guarding role through the privileged routine application (`$SYSTEM.Security.AddRoles(<app>)`, application type "Routine"), always inside a `New $ROLES` frame. Two ordering rules make containment real: **nothing is spawned from inside an escalated frame** (a `JOB` inherits `$ROLES` at the spawn and keeps it for the child's whole life), and **nothing re-enters** — a storage method never calls a tool, a port, or code that could. No other class escalates; adding a second escalation point is a spine change, not a slice decision.
- **A namespace-mapped class cannot be dispatched once `$NAMESPACE` has moved away from it.** `##class(X).Method()` re-resolves `X` against whichever namespace's routine database is current at that call. Because OcuPilot's code is mapped only into the install namespace, any `##class(OcuPilot.*)` call made while the installer sits in `%SYS` fails with `<CLASS DOES NOT EXIST>`. The installer therefore defers all reporting into an array and drains it after the namespace restore, and restores with a bare `Set $NAMESPACE = ...` rather than a second call into `Kernel.Utils`. Any later code that switches namespace inherits this constraint.
- **What 1.3 explicitly did not build, and who owns it:** no web application (Story 1.5), and no container start hook, image pin, demo fixture, `_SYSTEM` unexpire or schema-version stamp (Story 1.4). Note that `Kernel.State.Stamp` is a **per-install-run record** (created object names, the administrative grant's outcome and its operator command hint) — it is *not* the schema-version stamp AD-38 has the API check. Story 1.4 introduces that stamp.
- **Stored references are weak (AD-37).** OcuPilot stores references to IRIS objects it does not own — a user, a role, a web application, a task — and IRIS will not tell it when one is deleted. Every stored reference records the scoped identity as **data, never a foreign key**; a reference that no longer resolves renders as "no longer present" rather than failing the screen. `Kernel.State.Stamp` already models the granted user this way.

### IRIS security objects — five behaviors verified on this build

These bind every later story that touches databases, resources or roles (Epic 7, Story 3.8), and are recorded so nobody re-probes them:

- A database's guarding resource **must** be named `%DB_<NAME>`; a custom name errors and `ModifyDatabase` then fails with `<FUNCTION>`.
- `SYS.Database` does not validate that the resource exists, so creating the database before its resource yields a silently `%All`-only database. **Create the resource first, always.**
- Creating a `%DB_*` resource auto-creates its implicit role, granted to nobody.
- `Security.Users.Create` silently accepts a role name that does not exist, so **a grant must be read back to be believed**.
- `%Operator` carries `%DB_IRISSYS:RW` and is therefore a self-escalation primitive — a test proving denial must use a purpose-built role, never `%Operator`.
- `New $ROLES` is **frame-scoped, not block-scoped**, and restores on exception unwind.

### The container start path (Story 1.4's ground)

- **The container and durable-storage model is already in place and is the reference.** `./iris-data` is bind-mounted to `/durable` with `ISC_DATA_DIRECTORY=/durable/iris`, so instance state survives `docker compose down`. Host ports are deliberately offset by one from the IRIS defaults — **52774→52773 (web) and 1973→1972 (SuperServer)** — so this container coexists with a second, unrelated IRIS container on the same machine; container-internal ports stay at the defaults. The compose file today names the floating `latest-cd` tag and there is no Dockerfile and no start hook: pinning an explicit 2026.2 tag and adding the start path is this story's work.
- **Fresh containers open with an expired password.** Community Edition expires `_SYSTEM`'s password on first login, and it surfaces as **HTTP 401 from the Atelier API and the MCP tools rather than as a password prompt** — a failure mode that looks like broken credentials. It is cleared once per new container (which includes any wipe of `iris-data/`) by running `##class(Security.Users).UnExpireUserPasswords("*")` in `%SYS`; an authenticated `HEAD /api/atelier/` returning 200 confirms it. Install must do this itself so a clean clone works the first time without a documented manual step.
- **Install completes before the first request is served (AD-38).** The start path finishes install, or fails loudly, before the web applications accept traffic; the API refuses with a clear "installing" or "upgrade required" response rather than serving partial state. A **version stamp written at the end of install** is what the API checks — a stamp older than the deployed code means upgrade has not finished. Because upgrade re-runs install on every start, this is the daily path, not an edge case.
- **Forward migration is part of install, downgrade is a refusal.** Where the durable volume already carries OcuPilot state at schema version N, install migrates it forward *before* traffic is accepted, with existing rows surviving with their values, and a migration failure failing install loudly. Install **refuses and reports** when the stored schema version is newer than the deployed code rather than running old code against forward-migrated state. This is the half of the story the local container can actually exercise, and it is where DW-13's "operator's instance already has state" lands.
- **The demo fixture is opt-in and never writes on an operator's instance (AD-25).** The fixture set — a disabled `/csp/myapp` carrying no resource, a demo SSL/TLS configuration, a self-signed X.509 credential — is created only under an explicit, clearly named flag, set in this repository's own `docker-compose.yml` so a clean clone reproduces the demo, and absent from every other install path including IPM. Fixtures are namespaced so they cannot collide with a real application, and uninstall removes them. DW-13 (a real `/csp/myapp` already present) and DW-14 (the fixture list omits something later stories need) both sit here. Keep this distinct from AD-32's named **ProviderPort** SSL configuration, which the installer creates when absent with server-identity checking on, unconditionally and not as a fixture.
- **Report the CSP Gateway gap; never silently depend on it.** `Security.Applications.Create()` does not notify the Gateway, so a new application may 404 until an SMP Save or Gateway restart. Report the current Web Gateway response timeout as information only — never as a prerequisite, and never change it. The applications themselves are Story 1.5's, so 1.4 either builds the reporting seam ahead of them or sequences with 1.5 explicitly.
- **Namespace hygiene is explicit save and restore (AD-16), with the restore as the first line of every `Catch`.** `New $NAMESPACE` never appears in a dispatch handler.
- **Privilege is the calling process's, at call time, never cached (AD-8), and anonymous is not unprivileged (AD-21).** There is no service account and no elevation on the request path; AD-9's escalation is the one permitted exception. Every gate resolves the **authenticated** user and rejects the `UnknownUser` and `_PUBLIC` placeholders explicitly — on a Minimal-security instance `%Service_CSP`'s `UnknownUser` holds `%All`. Every SQL statement binds caller values as parameters; no OcuPilot endpoint accepts a filesystem path from a caller.

### Standing invariants for every story in the epic

- **Pins are exact and a wrong version must fail loudly rather than compile:** Angular 22.1.x with Material/CDK 22.x, TypeScript `>=6.0.0 <6.1.0`, Node `^22.22.3 || ^24.15.0 || ^26.0.0`, the `@angular/build` application builder with `outputHashing: all`, no webpack builder. The client is zoneless, standalone and signal-based; screen state is a per-screen store keyed by its descriptor, never a component field.
- **All project ObjectScript lives under `src/OcuPilot/`** in the seven fixed package folders (`Api`, `Kernel`, `Screen`, `Area`, `Port`, `Install`, `Test`), under the project's naming rules. **A class name, package dots included, is 29 characters or fewer** — 29 is the longest name still given the natural `^<Class>D` global on this build, and `OcuPilot.` already spends 9 of them. **Harvested sibling code keeps its call sites but never its names** — packages, web paths, roles, audit sources, globals, credentials, tool prefixes and environment variables all become OcuPilot's own, and `%Atelier` is a forbidden token so a later harvest cannot drag the `{status, console, result}` envelope in. Load and compile through the IRIS MCP tools with `server: "ocupilot-iris"` on every call, never the VS Code extension; `irislib/`, `irissys/`, `irisui/` and `irisdocs/` are read-only reference exports and never project source.
- **Client asset homes are fixed.** Global stylesheets and the token layer live under `ui/src/styles/`; vendored font faces under `ui/src/assets/fonts/` (vendored, never a CDN); the canonical user-facing string source at `ui/src/app/core/strings.ts`. Styles are authored in **SCSS**, with Material 3 configured through `mat.theme($config, $overrides)` — which is what fixes the `--mat-sys-*` custom-property prefix. **Non-ASCII characters in any string source are authored as `\uXXXX` escapes, never literal bytes.**
- **One response writer, one error envelope.** Handlers never write to the response device. Failure renders a flat **`{error, reason, code, detail}`**: `error` is a coarse slug from a closed enum, `reason` is human text a screen renders and may be reworded freely, `code` is a **stable dotted-uppercase machine identifier that is never a number and never reworded** (`ROUTE.NOTFOUND`, `AUTH.ANONYMOUS`), `detail` is an optional structured object present only when supplied. "Flat" forbids per-slice nesting, not the four keys. Inside a nested `Catch` the return is `Return $$$OK` — a bare `Quit` resumes the enclosing `Try` and puts a second envelope on the wire.
- **The router preserves three `%CSP.REST` file-order invariants**, each with its own routing test: method guards before the catch-all, sub-resource routes before single-segment `:param` routes, N-segment before (N−1)-segment. Route targets are thin delegating wrappers with no business logic. `OnPreDispatch` authenticates and resolves the namespace exactly once; on denial it sets `pContinue = 0` and returns through the error writer. Framework 404s and 405s are overridden into the envelope, the 405 carrying an `Allow` header.
- **Entity ids occupy exactly one percent-encoded path segment**, through one shared encode/decode pair, decoded exactly once, round-trip tested over a fixed corpus. An id alone is never an identity: every reference crossing a boundary carries `(entity type, scope, id)`, scope being the namespace or the literal `instance`.
- **The screen descriptor is the single source for a screen** — route, area and side-bar position, archetype, privilege set, entity type and scope, id accessor, context serializer with its secret-typed fields, actions with self-protection rules, empty-state text, command-box aliases, and the classic page it replaces. Routes, navigation and gating all resolve through it, so adding a screen never means editing a router or a nav list. Entity types come from one closed kernel-owned enum and the build fails on a value outside it. Multi-entity screens, sub-resource screens and composite ids must be expressible now, and tool identity must be independent of screen naming.
- **Privilege is a set of `(resource, permission)` pairs, never one resource** — the security APIs need `%DB_IRISSYS:R` *and* `%Admin_Secure:U` together on 2026.2. The set unions the API's requirement with any custom resource assigned to the classic page being replaced, and a denial names the pair that failed.
- **The static origin is hostile ground.** The handler applies both a literal traversal rejection and a post-normalization containment check, accepts no caller path, never reflects input, streams in bounded chunks, and serves the index for anything unresolved; hashed assets get immutable cache headers, the index no-cache, under a policy naming only the instance's own origin. **The SPA never uses a relative API URL** — the deep-link fallback would answer it with the index instead of JSON, silently.
- **Auto-refresh is one shared framework:** one timer, one persisted per-screen setting, one silent re-fetch through the same descriptor-declared read, preserving sort, filter, selection and scroll. It subscribes from the start to the proposal-open/closed channel, so the pause has a channel before there is anything to pause for.
- **Link-out is a list-versus-detail predicate declared in the descriptor.** A list archetype never links out. A detail view may, and only by declaring `classicLinkExemption` with a reason; a list archetype that declares one fails the check. The check **reports every exemption it honors** rather than passing silently, and that count is recorded against SM-C1.
- **Read-only and the kill switch have exactly one enforcement point — Story 3.7's instance-wide switch**, not the per-user toggle that sits over it (Story 10.4). Epic 1 builds nothing that enforces them, but its framework must not preclude the contract: while either is in force, every write tool returns a structured "blocked by read-only mode" result, the agent states what it would have changed and on which screen, and **no proposal card is minted**.
- **Installer, package manifest and CI share one generated roster.** The manifest ships the *built* bundle so install needs no Node toolchain; the Docker path never uses the package manager, which the shipped image does not carry (the official 2026.2 image has zero `%ZPM*` classes).
- **One smoke script is the definition of "installed and working"**, owned by `Install/`, asserting what exists at step 0 and reporting the rest as pending rather than passing vacuously. The unauthenticated readiness endpoint reports only installed/version/installing, nothing aiding reconnaissance. CI, once Story 1.17 creates it, runs against a throwaway container and fails on any CDN reference or embedded Python in a shipped class.

## UX & Interaction Patterns

**The token layer (delivered by Story 1.2 — extend it, never fork it).** The visual system is a brand-layer delta over Angular Material 3 — theme Lantern, direction Bridge — light on first load with the dark set complete and contrast-checked so the polish-week toggle is a flag flip. Every Material 3 role carries its Lantern value; Material's *meaning* of a role is inherited (surface layering, `on-` pairing, container tints) along with state-layer opacities (8% hover, 10% focus, 12% pressed), ripple, scrim, the 38% disabled opacity, and checkbox, radio, switch, form-field and tab anatomy — unchanged. Only values are overridden. **Light values sit on the bare role, dark values under `<role>-dark`, both complete.** Beyond Material's roles, OcuPilot defines the ones Material has no word for: `shell`/`on-shell`/`shell-edge` (the chrome — Material 3 has no app-bar role), the four `agent-*` roles, `change-highlight`, `egress-warning`, `restrained`, `destructive`, `success`, `warning`, `info` with their containers, `code-surface`/`on-code-surface`, `focus-ring`/`focus-ring-inner`, and the four `server-flag-*` pairs. Buttons, links, selection and the running indicator map to `secondary` (teal), not Material's default `primary`. **A hardcoded color value fails the build; only tokens are permitted.**

**Three colors carry three meanings and never trade places:** navy is the instance's chrome (rail, header, status bar, constant across modes), teal is *do something* (the sole action color), yellow is *the agent* (its avatar ground, rationale and expected impact, its proposal card's bar, the row it just changed — **never a control**).

**Type ramp and scale.** Six text roles and no others: `display` 16px/600/1.25 at −0.01em (screen title), `title` 14/600/1.3, `body` 13/400/1.4 (the floor for running text), `caption` 12/400/1.35, `label` 11/600/1.2 at +0.04em (eyebrows and column headers, the only uppercase), `code` 12/400/1.5 monospace for anything the instance would treat as an identifier. Weight 700 appears nowhere, nothing readable renders below 11px, and table numbers are tabular and right-aligned. A 4px scale (4-8-12-16-20-24-32) with 36px rows, 32px controls, 36px inputs, 28px log rows and 4/6/12/9999px radii. Shell metrics: 48px header, 48px rail, 240px fixed side bar with no sash or resize affordance, 24px status bar (an assumption Story 1.10 must confirm), 40px locator, 50px command bar, 640px content minimum, 400/320px panel with the Home width a `min()` formula, 168px tile minimum, 16px gutter.

**Fonts.** Inter for text and JetBrains Mono for code, both OFL, both vendored as `woff2` inside the bundle with `system-ui` and `ui-monospace` fallbacks. No request reaches any CDN or font host. The wordmark is never typeset — it is the artwork asset.

**Contrast.** WCAG 2.1 AA is the floor in both modes: 4.5:1 text, 3:1 non-text and focus indicators, checked automatically over the rendered token pairs. **Three marginal pairs carry explicit guard tests** — the teal name link on a selected row, the toast link on the dark inverse surface, and the `restrained` gated reason on a keyboard-active menu row, which fails in dark at 4.497:1 and therefore renders in `on-secondary-container` instead. **Four measured-and-rejected pairs are recorded so nobody re-derives them, and are never drawn.** Seven color rules govern usage: the chrome does not change with the theme (anything drawn on it takes the dark variants); gradients are the header band and two 2px hairlines only, never under text and never filling an area; teal is text only where it clears 4.5:1; yellow is never a control; privilege-gated controls stay readable in `restrained` rather than dimmed; status colors travel with their own container; and a receded state is dimmed **by role at full opacity, never by opacity**. Depth is tonal first and shadowed second, with hairlines separating; shadows appear only on things that float.

**Reduced motion is honored throughout:** transitions instant, skeletons not pulsing, panel width not animating, the change highlight not settling, spinners replaced by the word "running".

**The copy layer gets the same enforcement as the color layer.** The canonical Fixed strings — 104 named entries as shipped — live in **one** string source, `ui/src/app/core/strings.ts`, which is authoritative over `DESIGN.md` and over every inline quotation anywhere else; where planning documents disagree about a string's spelling, `EXPERIENCE.md` is canonical. The audit-failure string is **"done · audit not marked"** with a **middle dot (U+00B7), never a hyphen** — authored in the TypeScript string source as the escape `\u00b7`, per the non-ASCII rule above. The hyphen forms found elsewhere are a normalization artifact, and `epics.md` has been corrected in six places. A placeholder may be **resolved** by a caller (`<user name>` becoming `_SYSTEM`) but the string may **not be respelled**, and `<user name>` always resolves to the login name *as the audit database records it*, so a string and an audit row cannot disagree about who acted. **A user-facing literal not drawn from the string source fails the build, exactly as a hardcoded color does.** Voice rules: plain, direct, second person, sentences rather than labels; an error says what happened *and* what to do next; a confirmation names its target; a warning carries its consequence; no exclamation mark, no "Oops", no emoji, no "successfully". Agent strings are first person, never claim unverified success, name the screen they mean, and label rationale and expected impact as the agent's own text. Product vocabulary is "agent co-pilot" for the feature, "the agent" for the software, "the panel" for the UI — and **never "co-pilot" alone, anywhere**, enforced by a check across the source tree because it is the one naming mistake that cannot be corrected after release.

**Shell layout is fixed:** a navy header with the lockup at 32px directly on the navy, a centered 360px command box and the namespace switch; a rail of eight items in daily-use order with the agent pinned bottom, one Tab stop, marking the active area with a solid `secondary-dark` indicator; a fixed-width side bar listing only built screens; a thin status bar whose only interactive element is the user segment. No header text is drawn below 100% opacity. The server-flag badge lives in the status bar and on Home's instance line, never the header. Regions yield in a fixed order (side bar collapses, panel shrinks to its minimum, content holds its minimum and scrolls inside itself) — never an overlay, a bottom sheet, or a horizontally scrolling page body.

**Every screen carries a locator bar** (area, screen, selected entity — each navigating; namespace is not a segment) and a command bar with the primary action, filter and its polite match count, view options, sort, the refresh chip and the last-update stamp. Row actions read "select a row first" until a row is selected, every command-bar action is reachable from the command box, and the command box is never a channel to the agent.

**Gated controls stay reachable** — `aria-disabled`, never natively disabled and never hidden — naming the required resource as a tooltip on hover *and* focus, inline in the side bar and command box, and inside the accessible name in menus and result lists, where key managers skip disabled items and no tooltip can show.

**Home is the surface, not a tile:** six area tiles in a wrapping auto-fit grid naming their shipped screens, with the instance line beneath; the agent is reached from the rail.

**Failures are distinguished, not generalized.** A 401 refreshes and retries invisibly; a 403 renders inline naming the missing privilege with on-screen data kept; an unexplained failure runs a connectivity probe separating "instance unreachable" from "request refused"; a 5xx is generic in the browser with full detail logged on the instance, secrets redacted before emission. Vendor status text becomes a slug and a written reason at the port boundary. Desktop Chrome is the supported browser.

## Cross-Story Dependencies

- **1.1 gated everything and is delivered.** Later stories extend the router, the two writers, the entity-id codec, the logger and the test helpers rather than adding parallel ones; `scripts/check-objectscript.py` is the mechanical gate every subsequent commit passes.
