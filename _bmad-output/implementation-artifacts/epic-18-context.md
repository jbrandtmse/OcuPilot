# Epic 18 Context: Stage 2 - the rest of the admin API

## Goal

Take OcuPilot from the contest's Release 1 to System Administration and System Operation parity on the experimental `/api/admin` service: namespaces and their mappings, database configuration with its create, delete, properties and volume editors, the disk operations the contest list deferred, and then journals, licensing, ECP, superservers, authentication options, MFT, encryption, SQL privileges and the web-application extras. Each screen arrives with a read tool and confirmed single-write tools from one descriptor, so the agent grows with the portal. Stage 2 ships as the first versioned IPM release after the contest and deepens the dependency on an experimental API by about twenty screens, which is why containment, the endpoint inventory and self-protection carry most of the weight. 18.1 (the directory allow-list) and 18.2 (namespaces) are done; this run continues with 18.14 (mappings, copy-mappings and enable-interop), then 18.3 (database configuration) and 18.4 (disk operations).

## Requirements & Constraints

- **One contract, no second way to build a screen.** Every screen is one descriptor over one port, derives its read tool and its write tools' field lists from that descriptor with no hand-written tool code, and writes only through a server-minted proposal, an instance-computed diff, an explicit confirmation and an agent marker. No feature-level spec exists: a story's acceptance is this contract plus each catalog row's backing route, and finer criteria are written at the story's plan, never invented in advance.
- **Gates.** Write payloads are observed on the slot's throwaway before any form is built (the probes delete, dismount and truncate). Async operations use the port's async path. Stage 2 builds on the pinned 2026.2 image; the inventory is re-derived against 2027.1 when it ships.
- **Governance keys.**
  - Every new write key gets its `Kernel/Governance/Baseline.cls` line in the same change; `GovernanceBaseline` fails naming a registered key without one. The disabled set is also held by `Governance` and `ToolDispatch`, the violation codes by `AuditingUpdate`, and a tool's pairs by `ToolEmit`: 18.2's full sweep found all four missing from its per-class loop.
  - Enter `false`: namespace delete (shipped), database delete, dismount, truncate, encryption changes, and every 18.4 operation (mount, dismount, truncate, compact, defragment, expand, integrity check).
  - Enter `true` (orchestrator ruling at 18.2's gate): the nine mapping writes, deletes included, and copy-mappings, each keeping the destructive or strongest-confirmation treatment. Through 2026-10-04 any other key enters `true` unless its story's criteria say disabled; after that the owner decides.
- **Reads and gates.** Every read is bounded and reports truncation, every gate uses the caller's own privileges at call time, and no slice writes polling logic.
- **Catalog rows and their backing routes.**
  - 18.14: SA-11 (per kind, `GET /namespace/{global|routine|package}-mappings?namespace=` and `GET|PUT|DELETE /namespace/{kind}-mapping?namespace=&name=`), SA-14 (`POST /namespace/copy-mappings`, async) and SA-13's enable-interop (`POST /namespace/enable-interop`, async; DW-1776).
  - 18.3: SA-16 configuration list (`GET /databases`), SA-17 remote databases (`/database` configuration, `/ecp/data-server/databases`), SA-18 multi-volume properties (`GET /database-dir/volumes`, `POST /database-dir/expand-volume`), SA-19 properties (`GET|PUT /database`, `PUT /database-dir`), SA-20 create and SA-21 delete; also SA-13's inline create-database and SA-15's optional database delete.
  - 18.4: OS-16 to OS-22, `POST /database-dir/{mount,dismount,truncate,compact,defragment,expand-volume,integrity-check}`, plus modify-size for OS-21.
  - Later stories: SA-04, SA-06 to SA-10, SO-01 to SO-08, CP-35/39/41, WA-10 to WA-14, PM-19 to PM-22, SS-28 to SS-35, OS-30, LG-11 and PK-25. No story names SA-05 or SA-22.

DW-1779 (18.3): the database directory must refuse the manager directory itself, or any directory already holding an `IRIS.DAT`. DW-1784 (decision-pending, Epic 18 merge gate): see Identity below. ## Technical Decisions

- **Containment (AD-2, AD-27).** Only `AdminPort`, or a port extending it, names an `%Api.Admin.*` class, reproducing `Main()`'s sequence: stub `%request`, `%response` and `%session` with `IsRunningAsync` 0; `ResourcesOR()` before the query parameters; `ValidateQueryParams()`; captured output; a non-2xx `%response.Status` fails even when `tSC` is OK. No direct `Config.Namespaces`, `Config.Map*` or `SYS.Database` write; a call through the vendor's own class is allowed only as a named AD-27 case written into the spine. Re-run the inventory audit before using an endpoint outside the fixture.
- **Privilege pairs (AD-8, AD-29).**
  - `ResourcesOR()` is a lower bound. Establish each set from the backing class's own check plus a least-privileged principal on the throwaway, never `%Operator`, which carries `%DB_IRISSYS:RW`. Administrative resources are required at `USE`, never `WRITE`.
  - A tool declares extra pairs only in AD-8's two cases (the vendor class writes a database the screen's read does not; an endpoint its call necessarily reaches, such as the async poll or `PathPort`, names the resource) and refuses a caller without them by name before any port call. The spine records 18.2's: every namespace write `%DB_IRISSYS:WRITE`, and the delete also `%Admin_Secure:USE`.
  - An area's pair set must cover its screens' pairs, unless a screen declares the extra pair in `ownPrivileges`.
- **What 18.2's first plan measured for 18.14** (`ocupilot-b-ci`, 2026-09-28):
  - Mapping `PUT` is an upsert: 201 on create, 200 on edit keeping omitted fields. Templates: global `{Database, LockDatabase, Collation}`; routine and package `{Database}`. `DELETE` answers 200, and 404 #421 when absent.
  - A subscript mapping `G("a"):("m")` also creates the base mapping `G` on the namespace's default database, and deleting `G` while a subscript mapping exists answers 500 #451. A routine `X_mac` is created as `X_MAC`, then answers 500. `%`-named globals and packages are accepted: neither the vendor nor the classic page guards them.
  - A mapping list for an absent namespace answers 200 `[]`, and a subscript mapping's list row shows Collation 0 where its `GET` shows 5.
  - Copy-mappings (`{SourceNamespace, DestinationNamespace}`) answers 202 with a location; the poll carries `State`, `TaskName`, `Console`, `FailureReason`, an empty `Result` and three times, and no progress field. The copy merges, the source winning on a name. An absent source still answers 202, then fails #420.
  - Every mapping write also needs `%DB_IRISSYS:WRITE` (`<PROTECT>`, nothing changed). Copy needs `%Admin_Operate:USE` for the poll, which is owner-only. Enable-interop was not observed.
- **18.14's first-plan design** (Part B at `f473ce9b`; re-validate at 18.14's plan):
  - **Identity.** Types `global-mapping`, `routine-mapping` and `package-mapping`, scope `instance`, composite id `[namespace, Name]` joined on `$Char(1)` by `Kernel/EntityId`'s composite pair, because `SPLITQUERIES` splits on `/` and a subscript can hold one. A new rule `foldcase-firstpart` folds the namespace part only; the client mirror implements it or the build fails.
  - **Read (AD-36 extension).** Three parent-scoped lists with one criterion `{param:"namespace"}` (the `WalletSecretList` shape). The vendor rows carry no namespace, so the read seeds the criterion's value onto each row under the id's first part before projection, as the single-object read seeds its route id; registry and mirror refuse that part when `read.fields` lacks it.
  - **Port.** A new `NamespacePort` extends `AdminPort` on the `AuditPort` model. It splits the composite for the three mapping endpoints (anything but two non-empty parts is 404 `PORT.NOTFOUND` with no vendor call), builds `MAPPINGS`' body from the target (the destination) and the tool's `SourceNamespace`, converts `PORT.TIMEOUT` to started (202), and its `Snippet` mirrors every branch. `AdminPort` lists the mapping `PUT`s and `DELETE`s and `Namespace.Namespace/MAPPINGS` as mutating, the deletes as bodyless and verified, and `MAPPINGS` on `QUEUEDWRITES`.
  - **Tools.** `osmgmt.{globalmappings,routinemappings,packagemappings}.{create,update,delete}` declare `NamespacePort`; the agent passes `Namespace`, `Name` and the fields, joined into the id by a mint class on the `ErrorDeleteMint` model. A create fingerprints absence (AD-54), an edit sends the complete set (AD-4), a delete is bodyless and destructive. `osmgmt.namespaces.copymappings` is an AD-51 action (read `GET`, write `MAPPINGS`, no body, subject `Globals,Routines`, screen value `SourceNamespace`) refusing an absent or same source before any task is queued. Every mapping field classifies `ordinary`.
  - **Refused on Name before any port call:** a base-global delete while subscript mappings exist, and a lower-case routine type suffix; the vendor's name refusals (#5854, #448) map to the same shape code.
  - **Enable-interop (DW-1776).** Observe its payload with a probe database first. It writes interoperability code into the namespace's databases and is async, so it needs its own named `QUEUEDWRITES` entry; its pairs are unmeasured.
- **The `%`-global guard (18.14).** Harvest it from the sibling's mapping manager (execute-mcp `Config` MappingManage, which refuses a base `%`-global create unless `force=true`), reading its current body first and renaming it into OcuPilot's names. Orchestrator ruling: permitted at the strongest confirmation (AD-10's privilege-grant idiom), never banned, and no request field bypasses anything. A global-mapping create or edit whose name begins with `%` carries effect `MAPPING.SYSTEMGLOBAL`: the agent's proposal is minted destructive with the consequence, and the form states it under Name. It covers every `%` name, because the vendor creates a subscript's base mapping (measured for a non-`%` global; for `%`, inference), and edits, which the sibling lacks. Deletes and lists are unaffected.
- **Self-protection (AD-10).** Predicates live in the kernel only and are stated over the effect, so a bodyless delete is covered.
  - Shipped: `PROHIBITED.OCUPILOTNAMESPACE` refuses deleting, or changing the `Globals` or `Routines` database of, the install namespace or `%SYS`. The install namespace is the evaluating process's own `$NAMESPACE` (the API process runs in its application's namespace, and a turn job refuses any other), not a `Security.Applications` read, which a namespace-pair caller cannot make without escalation. 18.14's predicate should reuse it (the first plan named the application's `NameSpace`, which 18.2 replaced).
  - 18.14 adds `PROHIBITED.OCUPILOTMAPPING` (first plan): creating, changing or deleting a mapping whose name begins with `OcuPilot`, ignoring case, in the install namespace or `%ALL`, and a copy into either from a source holding one; the source's three lists are read at the write, and a list cut at its cap fails closed.
  - 18.3 and 18.4 candidates (inference): dismounting OcuPilot's state database or the install namespace's code database. Deleting OcuPilot's own database is already refused. Whether the admin API's database delete cascades to namespaces or applications is unmeasured; measure it, and hold every predicate over the whole effect.
- **Spine amendments 18.14 writes at its spec gate (Rule 20).** The spine's AD-8 and AD-10 text names namespace writes only. 18.14 adds: AD-8, the mapping writes' `%DB_IRISSYS:WRITE`, copy's `%Admin_Operate:USE` and whatever enable-interop needs; AD-10, `PROHIBITED.OCUPILOTMAPPING`; AD-26, `Namespace.Namespace` `MAPPINGS` (and enable-interop's type) on `QUEUEDWRITES`; AD-36, seeding a parent's key onto a child list's rows; AD-51, `NamespacePort`'s built copy body. 18.3's delete impact needs its own AD-8 sentence, following the namespace precedent.
- **Server paths (AD-21's sixth case); 18.3 is the first consumer.**
  - The caller names a root and a relative name, never a path. `Port/PathPort` computes the roots on every call: the `%GUIFileSelector` purpose's roots when restricted, otherwise the manager directory. Refusals are `PATH.ROOT`, `PATH.NAME`, `PATH.EXISTS` (unless the tool declares it overwrites) and `PATH.MANAGER` (a file directly in the manager directory), on the named field, before any vendor call, never echoing a path.
  - A consumer declares `root` and `path` arguments and the port's pairs `%Admin_FileSystemAccess:USE` and `%DB_IRISSYS:READ` under AD-8's endpoint clause; resolves at the mint and again at the write; sends the composed path under the vendor's own field, never a settable tool field; and embeds `app-server-path-picker` fed by a page-owned `AllowedDirectoriesStore`. Never add a client copy of the segment rule, a free-text path or subdirectory browsing. Measured: `%Operator` lacks `%Admin_FileSystemAccess:U`.
  - A remote database's directory lives on its data server, so the local allow-list cannot supply it (inference); `/ecp/data-server/databases` is the candidate source.
- **Databases (18.3).**
  - Create is `POST /database-dir` then `PUT /database`, and delete is `DELETE /database` then `DELETE /database-dir`: one tool each, whose declared port (AD-52) sequences the calls, settled at 18.3's plan.
  - The resource must be `%DB_<NAME>` and is created first: a custom name errors, and `SYS.Database` does not check that the resource exists, so a database created first is silently `%All`-only. Its implicit role is granted to nobody, and a grant must be read back to be believed.
  - Unmeasured: whether the database `PUT` upserts or erases omitted fields (AD-4, AD-54), and whether configuration writes need `%DB_IRISSYS:WRITE` as namespace writes do (inference).
  - The delete's impact names the namespaces whose `Globals`, `Routines` or `TempGlobals` is the database (through `NamespaceList`'s read) and the applications depending on it; names only, a part the caller cannot read reported unchecked with its pair.
- **Async and queued writes (AD-26).**
  - Async is per request type. `Database.Actions`: every type except mount and dismount, and compact, defragment and integrity queue themselves, which is wider than 18.4's criteria name, so read the fixture first. `Namespace.Namespace`: interop and mappings.
  - The port refuses a mutating request that would queue unless it is on `QUEUEDWRITES` (today only `Security.Audit.Record` `COPY` and `PURGE`); each Stage 2 queued write gets its own entry, with no secret in its body. Within the bound the confirm answers the outcome; past it the write is recorded applied and marked, and both callers say it is still running. A tool whose screen set lacks `%Admin_Operate:USE` declares it for the poll.
  - "Progress" is a running line, then done or still running (orchestrator ruling). No poll measured so far (`TYPEINFO`, `MAPPINGS`) exposes a progress figure; whether 18.4's operations do is unmeasured, so measure before promising one.
- **Write kinds.** Create (AD-54): fingerprint the name's absence. Merge (AD-4): read fresh, send the complete set. Action (AD-51): a declared request type, no body, and a fingerprint subject naming every field the action's precondition reads; a vendor body carrying a fixed or caller-chosen value (copy's source, a truncate target, an integrity selection) is built by the port under a new named AD-51 entry. Both callers reach one tool (AD-53, AD-55); the screen's caller emits no marker and is not gated by read-only or the kill switch. Every write tool also gets the read-back (AD-58; a list row that disagrees with its `GET`, as a subscript mapping's Collation does, can misread a match (inference)), a `Snippet` mirroring every port branch (AD-59), the change event and marker (AD-14, AD-15), and `%SYS` by explicit save and restore (AD-16).
- **Field lists (AD-3).** A tool's fields come from the endpoint's body-template method; `FieldLists.cls` already holds the four `Namespace.*` templates. The 11 Stage 2 mutating endpoints without a template derive their fields from the underlying class, pinned by a test. Classify every field `ordinary`, `secret` or `opaque` in `Classification.cls` (an unclassified field is emitted secret) and regenerate `ToolFields.cls`.
- **Identity and descriptors (AD-5, AD-13, AD-36, AD-44).**
  - References carry `(type, scope, id)`; each new type joins the kernel's closed enum with its canonical-spelling rule (`namespace`: `foldcase`).
  - New descriptors go into existing slices and each declares the classic page it replaces (the catalog's names; confirm on the instance): 18.14 `%CSP.UI.Portal.Mappings.Global`, `.Routine`, `.Package`; 18.3 `.Databases`, `.Database`, `.DatabaseVolumes`, `.RemoteDatabases`, `Dialog.DatabaseWizard`, `Dialog.DatabaseDelete`; 18.4 `Dialog.DBActions`, the `Background.Dialog.Database*` dialogs, `Dialog.ExpandVolume`, `Dialog.Integ*`.
  - DW-1784: only the declared page's custom resource is unioned, so a page a screen also replaces never gates it; 18.3's database delete dialog meets the same gap. Name it until the merge gate decides.
  - A list never links out, a page may issue another built screen's read, a tabbed editor is one descriptor per tab, and a form or wizard reached from its list takes `sideBarPosition` 0.
- **Testing pattern (from 18.2).** Stateful classes arm under `scripts/ci-throwaway.sh`'s `OCUPILOT_ALLOW_NAMESPACE_CONFIG` (the running throwaway predates it, so 18.2 armed per call with `docker exec -e`). Predicate legs run through the recording `AcceptPort`, so a removed predicate records a call instead of writing. Probe objects carry a story prefix and are removed before, after each and after all tests, and a survivor fails the class.
- **Later stories.** 18.5's journals stay in System Operation, and their directories are path consumers. 18.7 establishes the encryption subset first and settles the file kind. 18.9's criteria predate AD-10's permitted grants; the spine governs. 18.13 keeps one idempotent installer and must keep the install-namespace predicate holding.

## UX & Interaction Patterns

- **The screen contract.** Each screen registers the same 10 things; the side bar lists only built screens; every new string goes into EXPERIENCE.md's Fixed strings, extending the existing rows in place (the side-bar table, the Dialogs line, the OS management literals, delete bodies, kernel refusals, impact phrases). A refusal sentence is published once and pinned to the kernel's copy (AD-53).
- **Placement.** Namespaces is OS management's sixth side-bar entry. The mapping lists are unlisted, reached from the namespace editor's "Mappings" line, and the agent reaches them by route and command box: a list's name cell reaches one editor or one child list, never three. EXPERIENCE.md places no database-configuration screen yet; 18.3 adds its placement.
- **Copy mappings** is a Namespaces row action opening a dialog on the audit copy dialog's model: a select of the other namespaces from the Namespaces read, the consequence line and Copy; while it runs, a running line (first plan: "Copying mappings from <namespace> on the instance since <time>"), then the outcome, or the shipped "Still running on the instance. It finishes in the background."
- **Destructive actions on a screen** use a one-level `confirm-dialog`: the title names the action and target, the body states the consequence and ends "This cannot be undone.", and a typed-name field requires an exact, case-sensitive match. An agent proposal carries no typed-name field. A delete with an impact shows it as the dialog's advisory, not a stepper, when the vendor offers no choice.
- **A strongest-confirmation effect** (a `%`-global mapping) shows its consequence line at the field on the form and makes the agent's card destructive.
- **Wizards** follow the New Task precedent: a vertical, linear stepper; Next validates the step, Back keeps values, and a step with an error says "This step needs attention: <reason>". The integrity-check wizard and its log viewer form one flow replacing four classic dialogs.
- **Editors** are form pages whose tabs mirror the classic editor, with one form across all tabs and a sticky Save.
- **The path picker** offers only the read's roots; its one text entry is the relative name, the composed path is display only, and a `PATH.*` reason renders on the field it names.
- **Gated controls** stay focusable with `aria-disabled` and name their reason; a self-protection refusal is drawn the same way.
- **Live data.** Databases and Database details auto-refresh, pausing while a proposal on the same entity type is live (AD-43). Async values render as skeleton cells until they resolve, and an async write shows a running line, then done or still running.
