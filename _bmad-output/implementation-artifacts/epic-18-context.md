## Goal

Take OcuPilot from the contest's Release 1 to System Administration and System Operation parity on the experimental `/api/admin` service: namespaces and their mappings, database configuration with its create, delete, properties and volume editors, the disk operations the contest list deferred, and then journals, licensing, ECP, superservers, authentication options, MFT, encryption, SQL privileges and the web-application extras. Each screen arrives with a read tool and confirmed single-write tools from one descriptor, so the agent grows with the portal. Stage 2 ships as the first versioned IPM release after the contest and deepens the dependency on an experimental API by about twenty screens, which is why containment, the endpoint inventory and self-protection carry most of the weight. 18.1 (the directory allow-list) and 18.2 (namespaces) are done. The run order is now 18.14 (mappings and copy-mappings), 18.3 (database configuration), 18.4 (disk operations), then 18.15 (enable interoperability), which was split from 18.14 for risk.

## Requirements & Constraints

- **One contract, no second way to build a screen.** Every screen is one descriptor over one port, derives its read tool and its write tools' field lists from that descriptor with no hand-written tool code, and writes only through a server-minted proposal, an instance-computed diff, an explicit confirmation and an agent marker. No feature-level spec exists: a story's acceptance is this contract plus each catalog row's backing route, and finer criteria are written at the story's plan, never invented in advance.
- **Gates.** Write payloads are observed on the slot's throwaway before any form is built (the probes delete, dismount and truncate). Async operations use the port's async path. Stage 2 builds on the pinned 2026.2 image; the inventory is re-derived against 2027.1 when it ships.
- **The instance, not the specification, is the contract.** The owner's "Admin API behavior to design for" notes (after the criteria of 18.3, 18.4, 18.5, 18.9 and 18.11) come from a DC article on where the SysAdmin API specification and IRIS disagree. "Checked" means confirmed on slot A on 2026-09-28; "reported" is the article's claim only and is verified on the throwaway before anything relies on it.
- **Async results are read once (orchestrator rule for every async write this epic builds, 18.14's copy included).** Read a finished task's result exactly once: a second `async-result` read logs a severity-2 alert (ERROR #7846 from `TryToKillQueue^%Api.Admin.Util.AsyncTask`) and turns the instance's state to Warning (reported). `AdminPort`'s single read-then-delete adds no alert (checked). Run one poller per task, share it between two views of one task, and stop polling at the end.
- **Governance keys.**
  - Every new write key gets its `Kernel/Governance/Baseline.cls` line in the same change; `GovernanceBaseline` fails naming a registered key without one. The disabled set is also held by `Governance` and `ToolDispatch`, the violation codes by `AuditingUpdate`, and a tool's pairs by `ToolEmit`.
  - Enter `false`: namespace delete (shipped), database delete, dismount, truncate, encryption changes, and every 18.4 operation (mount, dismount, truncate, compact, defragment, expand, integrity check).
  - Enter `true` (orchestrator ruling): the nine mapping writes, deletes included, and copy-mappings, each keeping its destructive treatment. Through 2026-10-04 any other key enters `true` unless its story's criteria say disabled; after that the owner decides. Enable-interop's key is 18.15's to settle.
- **Reads and gates.** Every read is bounded and reports truncation, every gate uses the caller's own privileges at call time, and no slice writes polling logic.
- **Catalog rows and their backing routes.**
  - 18.14: SA-11 (per kind, `GET /namespace/{global|routine|package}-mappings?namespace=` and `GET|PUT|DELETE /namespace/{kind}-mapping?namespace=&name=`) and SA-14 (`POST /namespace/copy-mappings`, async).
  - 18.3: SA-16 configuration list (`GET /databases`), SA-17 remote databases (`/database` configuration, `/ecp/data-server/databases`), SA-18 multi-volume properties (`GET /database-dir/volumes`, `POST /database-dir/expand-volume`), SA-19 properties (`GET|PUT /database`, `PUT /database-dir`), SA-20 create (`POST /database-dir` + `PUT /database`) and SA-21 delete (`DELETE /database`, `DELETE /database-dir`); also SA-13's inline create-database and SA-15's optional database delete.
  - 18.4: OS-16 to OS-22, `POST /database-dir/{mount,dismount,truncate,compact,defragment,expand-volume,integrity-check}`, plus `/modify-size` for OS-21.
  - 18.15: SA-13's enable-interop (`POST /namespace/enable-interop`, async).
- **Routed ledger items.** DW-1784 (18.14, decided; see Privilege pairs). DW-1776 (18.15): observe enable-interop's payload, effects and pairs on the throwaway first. DW-1777, DW-1778 and DW-1779 (18.1 rework iteration 3, before 18.14's implement): refusing the CPF and the data directory's `IRIS.DAT` files to an overwriting file consumer, a read-existing file mode, and refusing a directory-kind location that names the manager directory itself. DW-1774 (every screen-adding story): extend every pinned side-bar list of your area (`grep -l ocu-side-bar-label ui/browser`, plus `ui/tools/navigation.test.mjs`). ## Technical Decisions

- **Containment (AD-2, AD-27).** Only `AdminPort`, or a port extending it, names an `%Api.Admin.*` class, reproducing `Main()`'s sequence: stub `%request`, `%response` and `%session` with `IsRunningAsync` 0; `ResourcesOR()` before the query parameters; `ValidateQueryParams()`; captured output; a non-2xx `%response.Status` fails even when `tSC` is OK. No direct `Config.Namespaces`, `Config.Map*` or `SYS.Database` write in product code (test-only `%SYS` seeding is allowed); a call through the vendor's own class is allowed only as a named AD-27 case written into the spine. Re-run the inventory audit before using an endpoint outside the fixture.
- **Privilege pairs (AD-8, AD-29, AD-44).**
  - `ResourcesOR()` is a lower bound. Establish each set from the backing class's own check plus a least-privileged principal on the throwaway, never `%Operator`, which carries `%DB_IRISSYS:RW`. Administrative resources are required at `USE`, never `WRITE`.
  - A tool declares extra pairs only in AD-8's two cases (the vendor class writes a database the screen's read does not; an endpoint its call necessarily reaches, such as the async poll or `PathPort`, names the resource) and refuses a caller without them by name before any port call. Shipped for 18.2: every namespace write `%DB_IRISSYS:WRITE`, the delete also `%Admin_Secure:USE`.
  - **DW-1784, decided (AD-44 amended):** a screen that replaces several classic pages declares each, and each write tool's pairs union the custom resource assigned to every page whose operation it performs, read at call time, never cached. 18.14 applies it to the namespace tools 18.2 shipped (create: `%CSP.UI.Portal.Namespace`; delete: `%CSP.UI.Portal.Dialog.NamespaceDelete`) and to the mapping tools; 18.3's wizards and 18.4's dialogs follow the same rule.
  - An area's pair set must cover its screens' pairs, unless a screen declares the extra pair in `ownPrivileges`.
- **Measured for 18.14** (`ocupilot-b-ci`, 2026-09-28):
  - Mapping `PUT` is an upsert: 201 on create, 200 on edit keeping omitted fields. Templates: global `{Database, LockDatabase, Collation}`; routine and package `{Database}`. `DELETE` answers 200, and 404 #421 when absent.
  - A subscript mapping `G("a"):("m")` also creates `G` on the namespace's default database; deleting `G` while a subscript mapping exists answers 500 #451 and changes nothing. A routine `X_mac` is created as `X_MAC`, then answers 500. `%`-named globals and packages are accepted.
  - A mapping list for an absent namespace answers 200 `[]`, and a subscript mapping's list row shows Collation 0 where its `GET` shows 5, so the read-back uses the `GET`.
  - Copy-mappings (`{SourceNamespace, DestinationNamespace}`) answers 202; the poll carries `State`, `TaskName`, `Console`, `FailureReason`, an empty `Result` and three times, and no progress field. The copy merges, the source winning on a name. An absent source still answers 202, then fails #420.
  - Every mapping write needs `%DB_IRISSYS:WRITE` (`<PROTECT>`, nothing changed). The poll needs `%Admin_Operate:USE`. Unmeasured: the copy's `%DB_IRISSYS:WRITE` (measure before the dialog is built) and the list's case handling.
- **18.14's design (the spec is `draft` for a re-plan of Parts A and B; enable-interop is out).**
  - **Screens and classic pages.** Three unlisted `os-management` lists and their forms, pairs `%Admin_Manage:USE` and `%DB_IRISSYS:READ`, reached from the namespace editor's Mappings line. The lists replace `%CSP.UI.Portal.Mappings` (one classic list for all three kinds); each form replaces its kind's dialog `%CSP.UI.Portal.Mappings.{Global,Routine,Package}`.
  - **Identity.** Types `global-mapping`, `routine-mapping` and `package-mapping`, scope `instance`, composite id `[namespace, Name]` joined on `$Char(1)` by `Kernel/EntityId`, because `SPLITQUERIES` splits on `/` and a subscript can hold one. A new id rule `foldcase-firstpart` folds the namespace part only; the client mirror implements it or the build fails.
  - **Read (AD-36 extension).** Parent-scoped lists with one criterion `{param:"namespace"}`; the vendor rows carry no namespace, so the read seeds the criterion's value onto each row under the id's first part before projection.
  - **Port.** `NamespacePort` extends `AdminPort` on the `AuditPort` model: it splits the composite (anything but two non-empty parts is 404 with no vendor call), builds `MAPPINGS`' body from the destination and the tool's `SourceNamespace`, converts `PORT.TIMEOUT` to started, and its `Snippet` mirrors every branch. `MAPPINGS` joins `QUEUEDWRITES`.
  - **Tools.** `osmgmt.{globalmappings,routinemappings,packagemappings}.{create,update,delete}`: a create fingerprints absence (AD-54), an edit sends the complete set (AD-4), a delete is bodyless and destructive. `osmgmt.namespaces.copymappings` is an AD-51 action, destructive on the agent's card, refusing an absent or same source (ignoring case) before any task is queued. A lower-case routine suffix is refused before any port call; the #451 base-with-subscripts delete is mapped from the vendor's refusal, not pre-read.
  - **The `%`-global guard.** Harvested from the sibling's mapping manager (which refuses a base `%`-global create without `force`), renamed into OcuPilot's names. Orchestrator ruling: permitted at the strongest confirmation, never banned, and no request field bypasses it. A global-mapping create or edit whose name begins with `%` carries effect `MAPPING.SYSTEMGLOBAL`: the agent's proposal is minted destructive with the consequence, and the form states it under Name.
- **Self-protection (AD-10).** Predicates live in the kernel only and are stated over the effect, so a bodyless delete is covered.
  - Shipped: `PROHIBITED.OCUPILOTNAMESPACE` refuses deleting, or changing the `Globals` or `Routines` database of, the install namespace (the evaluating process's own `$NAMESPACE`) or `%SYS`.
  - 18.14 adds `PROHIBITED.OCUPILOTMAPPING`: creating, changing or deleting a mapping whose name begins with `OcuPilot`, ignoring case, in the install namespace or `%ALL`, and a copy into either from a source holding one; the source's three lists are read at the write, and a list cut at its cap fails closed. OcuPilot's own mapping today is one global mapping, `OcuPilot*` to `OCUPILOT`, in the install namespace.
  - 18.3 and 18.4 candidates (inference): dismounting OcuPilot's state database or the install namespace's code database. Deleting OcuPilot's own database is already refused. Whether the database delete cascades to namespaces or applications is unmeasured; measure it, and hold every predicate over the whole effect.
- **Spine amendments 18.14 writes at its spec gate (Rule 20).** AD-8: the mapping writes' `%DB_IRISSYS:WRITE` and the copy's `%Admin_Operate:USE`; AD-10: `PROHIBITED.OCUPILOTMAPPING` and the `%` effect; AD-26: `Namespace.Namespace` `MAPPINGS` on `QUEUEDWRITES`; AD-36: seeding a parent's key onto a child list's rows; AD-51: `NamespacePort`'s built copy body. 18.3's delete impact and extra pairs need their own AD-8 sentences, following the namespace precedent.
- **Server paths (AD-21's sixth case); 18.3 is the first consumer.**
  - The caller names a root and a relative name, never a path. `Port/PathPort` computes the roots on every call (the `%GUIFileSelector` purpose's roots when restricted, otherwise the manager directory). Refusals are `PATH.ROOT`, `PATH.NAME`, `PATH.EXISTS` (unless the tool declares it overwrites) and `PATH.MANAGER`, on the named field, before any vendor call, never echoing a path.
  - A consumer declares `root` and `path` arguments and the port's pairs `%Admin_FileSystemAccess:USE` and `%DB_IRISSYS:READ`; resolves at the mint and again at the write; sends the composed path under the vendor's own field, never a settable tool field; and embeds `app-server-path-picker` fed by a page-owned `AllowedDirectoriesStore`. Never add a client copy of the segment rule, a free-text path or subdirectory browsing.
  - 18.3's database directory must refuse the manager directory itself and any directory already holding an `IRIS.DAT` (DW-1779, fixed under 18.1); probe on the throwaway that it holds before relying on it. A remote database's directory lives on its data server, so the local allow-list cannot supply it (inference).
- **Databases (18.3).**
  - Create is `POST /database-dir` then `PUT /database`, and delete is `DELETE /database` then `DELETE /database-dir`. A candidate is one tool each whose declared port (AD-52) sequences the calls; 18.3's plan settles it.
  - The resource must be `%DB_<NAME>` and is created first: a custom name errors, and `SYS.Database` does not check that the resource exists, so a database created first is silently `%All`-only. Its implicit role is granted to nobody, and a grant must be read back to be believed.
  - `GET /v2/database-dirs` answers a plain list of directory objects, not the `LocalDatabaseList` object the schema declares (checked: 14 entries).
  - `%Operator` holds `%Admin_Operate:USE`, which the specification accepts for `GET /v2/databases` and `GET /v2/database-dirs`, yet both answer it 403 with an empty error list (reported). Take the pairs from the instance.
  - Unmeasured: whether the database `PUT` upserts or erases omitted fields (AD-4, AD-54), and whether configuration writes need `%DB_IRISSYS:WRITE` as namespace writes do (inference).
  - The delete's impact names the namespaces whose `Globals`, `Routines` or `TempGlobals` is the database (through `NamespaceList`'s read) and the applications depending on it; names only, and a part the caller cannot read is reported unchecked with its pair.
- **Disk operations (18.4).**
  - `Database.Actions` answers async for every type except mount and dismount, and compact, defragment and integrity queue themselves (AD-26), which is wider than the criteria name, so read the fixture first. Each queued operation needs its own `QUEUEDWRITES` entry with no secret in its body, and declares `%Admin_Operate:USE` for the poll where its screen's set lacks it.
  - The integrity check takes its databases in the body (`Databases[]`, each with `Directory`), while compact, defragment and the others take the `dir` query parameter. A body carrying the caller's selection is built by the port under a new named AD-51 entry.
  - "Progress" is a running line, then done or still running (orchestrator ruling). No poll measured so far exposes a progress figure; whether 18.4's do is unmeasured, so measure before promising one.
  - The integrity check's output file would be a file-kind `PathPort` consumer, and its log viewer a reader of an existing file under DW-1778's read-existing mode (inference).
- **Write kinds.** Create (AD-54): fingerprint the name's absence. Merge (AD-4): read fresh, send the complete set. Action (AD-51): a declared request type, no body, and a fingerprint subject naming every field the action's precondition reads; a vendor body carrying a fixed or caller-chosen value is built by the port under a named AD-51 entry. Both callers reach one tool (AD-53, AD-55); the screen's caller emits no marker and is not gated by read-only or the kill switch. Every write tool also gets the read-back (AD-58; a 202 continuation is `unchecked`), a `Snippet` mirroring every port branch (AD-59), the change event and marker (AD-14, AD-15), and `%SYS` by explicit save and restore (AD-16).
- **Field lists (AD-3).** A tool's fields come from the endpoint's body-template method; `FieldLists.cls` already holds the `Namespace.*` templates. Stage 2 mutating endpoints without a template derive their fields from the underlying class, pinned by a test. Classify every field `ordinary`, `secret` or `opaque` in `Classification.cls` (an unclassified field is emitted secret; a bodyless tool needs no entry) and regenerate `ToolFields.cls`.
- **Identity and descriptors (AD-5, AD-13, AD-36, AD-44).** References carry `(type, scope, id)`; each new type joins the kernel's closed enum with its canonical-spelling rule (`namespace`: `foldcase`). Each descriptor declares the classic page it replaces (the catalog's names; confirm on the instance): 18.3 `%CSP.UI.Portal.Databases`, `.Database`, `.DatabaseVolumes`, `.RemoteDatabases`, `Dialog.DatabaseWizard`, `Dialog.DatabaseDelete`; 18.4 `Dialog.DBActions`, the `Background.Dialog.Database*` dialogs, `Dialog.ExpandVolume`, `Dialog.Integ*`. A list never links out, a tabbed editor is one descriptor per tab, and a form or wizard reached from its list takes `sideBarPosition` 0.
- **Testing pattern (from 18.2).** Stateful classes arm under `scripts/ci-throwaway.sh`'s `OCUPILOT_ALLOW_NAMESPACE_CONFIG` (a throwaway predating the block is armed per call with `docker exec -e`). Predicate legs run through the recording `AcceptPort`, so a removed predicate records a call instead of writing. Probe objects carry a story prefix, never touch `USER` or `HSCUSTOM`, and are removed before, after each and after all tests; a survivor fails the class.
- **Later stories.** 18.5's journals stay in System Operation, and their directories are path consumers. 18.7 establishes the encryption subset first and settles the file kind. 18.9's criteria predate AD-10's permitted grants; the spine governs. 18.13 keeps one idempotent installer and must keep the install-namespace and own-mapping predicates holding.

## UX & Interaction Patterns

- **The screen contract.** Each screen registers the same 10 things; the side bar lists only built screens; every new string goes into EXPERIENCE.md's Fixed strings, extending the existing rows in place (the side-bar table, the Dialogs line, the OS management literals, delete bodies, kernel refusals, impact phrases). A refusal sentence is published once and pinned to the kernel's copy (AD-53).
- **Placement.** Namespaces is OS management's sixth side-bar entry. The mapping lists are unlisted, reached from the namespace editor's Mappings line: a list's name cell reaches one editor or one child list, never three. EXPERIENCE.md places no database-configuration screen yet; 18.3 adds its placement beside Epic 6's read-only Databases and Database details.
- **Copy mappings** is a page-owned Namespaces row action opening a dialog on the audit copy dialog's model: a select of the other namespaces from the Namespaces read, the consequence line and Copy; while it runs, a running line, then the outcome, or the shipped "Still running on the instance. It finishes in the background." The dialog is the screen's confirmation; it is not a typed-name delete.
- **Destructive actions on a screen** use a one-level `confirm-dialog`: the title names the action and target, the body states the consequence and ends "This cannot be undone.", and a typed-name field requires an exact, case-sensitive match. An agent proposal carries no typed-name field. A delete with an impact shows it as the dialog's advisory, not a stepper, when the vendor offers no choice.
- **A strongest-confirmation effect** (a `%`-global mapping) shows its consequence line at the field on the form and makes the agent's card destructive.
- **Wizards** follow the New Task precedent: a vertical, linear stepper; Next validates the step, Back keeps values, and a step with an error says "This step needs attention: <reason>". The integrity-check wizard and its log viewer form one flow replacing four classic dialogs.
- **Editors** are form pages whose tabs mirror the classic editor, with one form across all tabs and a sticky Save.
- **The path picker** offers only the read's roots; its one text entry is the relative name, the composed path is display only, and a `PATH.*` reason renders on the field it names.
- **Gated controls** stay focusable with `aria-disabled` and name their reason; a self-protection refusal is drawn the same way.
- **Live data.** Databases and Database details auto-refresh, pausing while a proposal on the same entity type is live (AD-43). Async values render as skeleton cells until they resolve, and an async write shows a running line, then done or still running.
