- (decision) OQ15 RESOLVED by config probe, with one correction to FR-2. Security.Applications on ocupilot-iris: /csp/sys and /api/admin share GroupById='%ISCMgtPortal', and so does /ui/interop - the vendor editors the auth spike ALREADY observed sharing the browser login. Same group plus UseCookies=2 means the classic portal shares the login by the same mechanism the spike proved, so a form login through OcuPilot is expected to sign the browser into /csp/sys. TWO caveats that change requirement text: (1) /csp/sys has JWTAuthEnabled=FALSE - it rides the CSP session cookie and the browser id, NOT the token pair, so FR-1's claim is about the browser-level login only; (2) /csp/sys has AutheEnabled=96 = password(32) + UNAUTHENTICATED(64), so after OcuPilot's sign-out the classic portal may keep rendering as an unauthenticated session rather than showing a login form. FR-2's consequence should read 'ends the authenticated session', never 'the classic portal shows its form'.

- (question) GAP FOUND IN THE ADOPTED SPINE: FR-63's application error log has no port. The spine scopes LogFilePort to 'the manager directory' (files) and AD-21 frames the log rule entirely around file paths resolved from a fixed enum under $System.Util.ManagerDirectory(); AD-36's read contract names no global source. But the 2026-09-08 probe established that the application error log is the ^ERRORS GLOBAL, held per namespace, needing AD-16's namespace save/restore - not a file. Needs an architecture decision: broaden LogFilePort to cover log SOURCES rather than files, or add a port. Owner: bmad-architecture.
